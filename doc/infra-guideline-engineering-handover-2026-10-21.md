## Implementation mechanisms with tested evidence

**Durable user authority:** The canonical human chat path is the persistent orchestrator, reached by `orchestrator.message` for voice/connected clients or SWAAG's foreground CLI. Finalized exact user messages, edits, supersession/cancellation, durable control IDs, model requests and selected exact source evidence are stored in history. The last fast reply can be replayed without inventing new work; duplicate-effect prevention and exact old receipt lookup were regression tested. Tests establish those mechanical invariants for tested cases, not perfect interpretation of arbitrary changes of mind.

**Quick answer and real worker state:** Precomputed snapshots now describe all active workers' real objectives, status, creation/start times, report age, last reported task activity, model route and finite/continuous nature. An explicit validated worker step assessment may supply a percent or dated remaining-time estimate; if absent the figure is **unknown**. Completed plan-node percentages are not worker percentages. Current mechanical state has greater evidentiary weight than older assistant dialogue or model-authored status claims. Snapshots are timestamped and fail closed when stale or their task revision changes. An arbitrary LLM output is not automatically truthful simply because its JSON is valid.

**Governing policy and remembered notes:** Exact applicable durable user rules and lower-trust notes can be included on the quick path under named token/character bounds. Their authority, store, revision and source are carried explicitly. Overflow or policy-database failure returns control to the full orchestrator rather than silently deleting a rule. Changes occurring during inference invalidate a stale answer. This is stronger than the old behavior that delegated every question whenever any note existed, but **not** a guarantee of long-history semantic relevance.

**History and source compaction:** The complete conversation remains in durable source-linked history. Large tool returns, exact worker records and selected project content can be retrieved without pasting everything into the first context. Indexed history and lifecycle/receipt reverse traversals replaced all-event history materialization in certain replay paths. The quick path has bounded recent whole messages and bounded old-message candidate lookup; the deep orchestrator can retrieve selected exact source ranges when necessary. Lexical overlap or a fixed recency window is **not** a complete semantic history selector. Source provenance must remain recoverable when summaries are created.

**Task supervision and worker question handling:** Plan/worker supervision, background progress events, state/task controls, question inventories and the separate communication loop exist. Liveness/heartbeats show activity rather than semantic completion. One LLM can draft a status but cannot prove its side effects. Intentionally indefinite work has no fabricated overall completion fraction. Stale or incomplete reports must be qualified and possible new questions returned to the actual question inventory, not generated from guesses.

**Tool/workspace ownership and security:** Tool schemas and local validation are deterministic. The agent-owned workspace lives outside user project repos; reusable tool code is versioned in the tool forge and retained experience is revisable data, not upgraded to a policy by its mere existence. The new text-write admission verifies UTF-8 bytes and kernel-reported user-available storage while holding the write lock, before creating parent directories or replacing a file. New sandboxed shell, Python and package-install operations are refused when free-space observation is missing or below the reserved floor. It still lacks **aggregate quota enforcement** once a process is running; no arbitrary tool is certified safe for hostile packages.

**Structured model requests and inference bounds:** Generated actions and structured replies use provider-specific constrained grammar/JSON and local validation. The separate OpenRouter-like strict JSON-schema guideline is applicable only where the provider supports it; it was checked with an isolated request-builder test, not claimed as a guarantee for every llama.cpp or hosted endpoint. Context-token admission, reserved outputs, bounded retries and complete source references have regression coverage; schema validity alone does not prove task quality.
