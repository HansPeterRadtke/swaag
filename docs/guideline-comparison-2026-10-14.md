# Complete Infra guideline comparison with SWAAG — 2026-10-14

## Scope and evidence boundary

The complete `/data/infra/docs/guidlines` tree was reread, including the original recordings, then compared with current source, installed packages, operating state, retained live experiments, and focused reproductions. The directory is spelled `guidlines` in Infra. This is a requirement comparison, not certification that every requirement has passed and not a redesign proposal.

Baseline: Infra `ab5d265f47c156d2043b67298dfdd51d7daeadae`; Jetson SWAAG `c2cbcb065b4c8b42c3289b10705cf7c1b2cebf9f`; Thor SWAAG `7f18c63116186724f73c5611ca3a729f88399e48`. Jetson SWAAG was clean before this documentation change. Infra's pre-existing modification to `hosts/jetson/config.json` was preserved. No production model, service, configuration, package, or workload was changed by this audit.

Evidence root: `/data/var/swaag-benchmarks/guideline-audit-20261014` on Jetson.

- `guideline-inventory.json`: all 242 files, 4,987,516 bytes, exact hashes and initial timestamp.
- `canonical-reading-index.json`, `canonical-00.txt` through `canonical-15.txt`: 76 normalized guideline, research, index and template files.
- `original-reading-index.json`, `originals-00.txt` through `originals-40.txt`: all 165 originals. Only exact consecutive sentence repetitions were consolidated in reading copies, with explicit repetition counts; authoritative files were unchanged. Truncated reading outputs were reread in smaller ranges.
- `appendix/source-preservation.md` is the remaining file: its duplicated source corpus was checked against all originals by Infra's `recording_coverage_check.py`: `originals=165 coverage=165 preserved=165 errors=0`. This integrity check supports preservation; semantic interpretation came from reading the originals, not counting bytes.
- `requirement-file-ledger.json`: every file mapped to comparison sections below, with the source hash, reading provenance and original-to-normalized references. The complete file index is also retained in [the repository ledger](guideline-comparison-2026-10-14-files.json).
- `reproduce_gaps.py`, `reproduced-gaps.json`: isolated probes importing the installed Jetson package. They use deterministic model doubles where indicated and a real sandboxed shell for scratch-output behavior; they do not measure real-model accuracy.
- `focused-tests.txt`: **220 passed in 91.83 seconds** on the current source. This was a focused suite, not a new full-suite certification.
- `jetson-installation.json`, `endpoint-health.json`, `runtime-verification.json`: timestamped package, service, address and memory observations.

Status terms below are deliberately narrow: **implemented/evidence** identifies an existing mechanism and its evidence; **partial** identifies a concrete missing part; **failure** means an observed counterexample; **conditional** applies when SWAAG performs that domain or a frontend supplies that interface; **experiment** is an unresolved design choice rather than a mandatory architecture. A file can contain several such kinds of statement.

## Result

SWAAG has working durable orchestration, actual command execution, command-result reporting, instruction ordering, cancellation fences, model admission, status snapshots, structured questions, context accounting, history recovery and background-work controls. These are substantial implementations, not placeholders. Current evidence nevertheless contradicts blanket claims of complete guideline compliance.

The highest-impact gaps are ordinary early-response delivery, semantic routing/claim accuracy, automatic global-state context on the full orchestration path, exact scratch-command output retention, reusable-tool catalogue and coordination, configuration metadata/policy completeness, the named Diane experience interface, and deployment consistency. The existing session lock must not simply be removed: it protects ordered mutation, while the missing feature is safe responsive conversation and early delivery around that ordering.

## Detailed counterexamples and acceptance boundaries

### F1. The first message exists internally but ordinary delivery waits

`CommunicationService._orchestrator_message_locked` runs the semantic gate and then the full turn. The JSONL dispatcher awaits that processing and `handle_client` writes its response afterward. The runtime writes `assistant_progress` before executing tools, so the internal event order is correct but ordinary clients cannot speak that message at its creation time.

The [real ordinary-action study](orchestrator-action-delivery-2026-10-14.md) used the installed runtime and isolated explicitly authorized shell configurations. Success produced the requested file once; an expected exit-seven command ran once and was accurately reported; cancellation during inference caused zero shell effects. Success took 59.735 seconds to the combined first action, 59.848 to the effect, and 116.981 to the final reply. The error case reached the tool at 49.107 seconds and the final reply at 126.436. Cancellation acknowledgement was about 104 seconds after cancellation. These are functioning action/control paths with poor delivery/acknowledgement latency, not evidence that tools never run.

Acceptance for a correction must separately time durable receipt, semantic first reply, dispatch, effect, final response and TTS/playback; prove replay/reconnect and stale-action fences; and allow authorized work to overlap speaking without treating incomplete speech as authorization.

### F2. A lexical safety helper changes a semantic routing decision

Installed `_fast_reply_claims_unperformed_work` results in the isolated fixture (no tool has executed):

| Reply text | Actual rejection | Semantic issue |
| --- | --- | --- |
| `I can explain how to start a worker.` | true | Explanation capability is not a claim that work was started. |
| `If you approve later, I will deploy it.` | true | Conditional future intent is not a claim of present dispatch. |
| `I restarted the service.` | false | Unsupported completed action slips through. |
| `I have cancelled the deployment.` | false | Unsupported completed cancellation slips through. |
| `Ich werde den Dienst neu starten.` | false | Equivalent future commitment is missed in German. |

The source comment calls this a rejection gate, but it still interprets semantic action claims with keywords and changes routing. This is a deterministic-helper counterexample, not a real-model failure-rate estimate. Adding more English patterns would not resolve the architectural semantic-ownership issue. Acceptance should use execution receipts/authority plus model-owned semantic interpretation, with held-out paraphrases, languages, conditions and negations.

### F3. Snapshot coverage is not the same on every model path

The gate snapshot includes collection timestamps, explicit per-source consistency, active turn details, exact pending messages, workers/plans including terminal results, complete question inventory and supervision. Before returning a direct answer, the fingerprint is checked; pending controls are included. Two deliberately injected concurrent corrections caused two generations and a stale-state error, with all messages retained and no stale reply committed. That mechanism works as intended.

The full orchestration call does not receive that gate snapshot through `run_turn_in_session`. Its action loop refreshes worker questions; its runtime context adds local processes, wakeups, tool handles, workspace, notes and other local sources. It does not automatically rebuild the global workers/plans/results/supervision view for each action request. Historical tool results or fresh lookup tools are not equivalent to automatic current context. The isolated idle-context probe identifies local component names; the missing global source conclusion additionally follows from the call path and context-source inspection, not from that empty fixture alone.

Acceptance needs markers representing concurrent worker/plan transitions in actual serialized gate and full-action requests, correction ordering, state-generation timestamps, truthful phase names and measured context cost. A compact snapshot is an experiment; deleting meaningful state solely to meet an arbitrary text cap is not acceptable.

### F4. Scratch output is actually discarded before history can preserve it

`AgentWorkspaceTool._run_sandboxed` captures all stdout/stderr into memory with `subprocess.run`, then slices both strings to `max_capture_chars`. It returns flags, but no exact output artifact or recovery reference. In the installed probe, a real sandboxed command exited successfully, emitted 200 zeroes plus a tail marker, and returned only the configured 100-character preview. The tail was absent from the tool output, generated events and files. Durable history could only retain that already-truncated result.

`read_text` similarly materializes a whole file and returns a prefix without an offset. Its tail remains in the original file and can be recovered through another operation; it is not permanently deleted. `list_files` materializes/sorts the tree, returns at most 1,000 paths and exposes no continuation cursor; a shell workaround exists but the listing API cannot page. These distinctions matter: only command-output loss is irreversible in this probe.

Acceptance: stream exact output into the existing integrity-checked artifact machinery while bounding memory; expose preview/recovery metadata and pagination; handle timeout, nonzero exit, large stderr, concurrent writers and storage admission failure without claiming complete retention when it failed.

### F5. The shared directory is a foundation, not the complete tool forge

The scratch root and virtual environment are shared, so reuse is already possible. Missing pieces are automatic compact catalogue discovery and provenance, general/project helper classification, validated version publication, leases or equivalent coordination for mutation, atomic promotion/rollback, stable references for in-use versions, trust boundaries and quotas/ownership for disk, memory, processes, network and services. `write_text` directly overwrites a path; virtual-environment initialization uses an existence check without a shared mutation lock. No destructive race or OOM stress was run; these are source-inspected limitations.

Acceptance should include two workers discovering/reusing one helper, conflicting updates, retained working versions after failure, a large catalogue without full injection, untrusted helper/instruction content, and cleanup/admission under realistic resource pressure. None of this requires a particular database, separate process or model count.

### F6. Metadata presence is not metadata completeness

`AgentConfig.parameter_metadata` describes every leaf but often uses generic consequences. `agent_data.max_capture_chars` has no advertised positive range even though validation requires one; `communication.max_concurrent_requests` has no count unit/range; `tools.allow_side_effect_tools` describes consequential effects but is classified as normal criticality. Null ranges for unrestricted text are not defects by themselves. Orchestrator priority/preemption policy and scratch listing limits also need explicit treatment as configurable behavior versus justified invariants.

Acceptance should check actionable metadata against actual validation and permission consequences, then test selected policies under contention. A high metadata-entry count is not sufficient.

### F7. Current installed state differs by host and configured address

At 14:28–14:39 UTC on October 14:

- Jetson's 190 tracked package files exactly match its current source. Its canonical executable exists under `/data/var/swaag/venv/bin/swaag`; `/data/bin/swaag` is absent. It is not a dangling leaf symlink: the parent `/data/bin` resolves into Infra, which explains the misleading resolved target recorded by the first check.
- Jetson `llama-cpp-jetson.service` is failed with exit status 75, zero restarts and no main PID; localhost port 14829 refuses connections. This audit did not obtain the historical journal cause and does not infer one solely from current free memory. Earlier successful production observations are historical.
- Thor's 189 installed package files match its older checkout, not Jetson's current source. This is actual installed-version drift.
- Thor BF16 and Q3 services remain active with the same PIDs and zero restarts. Their units bind to `10.8.0.7`, not loopback. Health at that address on ports 14833/14834 returns 200 from Jetson; localhost probes refuse. A localhost refusal is therefore not evidence that those model services are down.
- The installed `/etc/swaag/voice-agent.toml` points its worker to `127.0.0.1:14833` and communication to `127.0.0.1:14832`; neither address accepts the configured connection. The installed config includes explicit communication model identity and context fallback that its repository copy lacks, so an earlier suspicion of implicit wrong identity does not describe the installed file. The actual defects are unavailable/wrong-bound endpoints and drift. The voice communication service is inactive.
- Available host memory was approximately 18.9 GiB on Jetson and 18.7 GiB on Thor. These are observations, not safe-admission estimates. Thor's installed nine-billion service is inactive; this audit made no startup attempt.

An inactive communication daemon is not by itself a SWAAG failure: foreground interaction is supported. It does mean this particular voice deployment is not a working acceptance path. Repairing or deploying it requires selecting the intended current configuration and established guarded operations, not restarting existing models for this audit.
