# Foreground identity and configured model routing — October 19, 2026

## Reproduced failures

The user-facing SWAAG/Coder model is expected to answer factual conversational questions without losing the application name or inventing an unspecified model identity. In an isolated real-model holdout, the ordinary question "Who are you?" previously produced a good initial SWAAG answer, but the independent `direct_conversational_reply_check` returned false because it had neither the installed application-role source nor its model-route metadata. The full completion verifier unnecessarily reexpanded historical runtime/audit material and sometimes rewrote an accurate answer into a generic response that omitted SWAAG. A separate combined question, "Who are you, and which model is answering my message?", could not converge because the snapshot exposed backend URLs without the actual configured model ID. The independent reviewer repeatedly rejected unsupported claims of absent model information, and the run exhausted its 130-second bound.

**Important benchmark correction:** Earlier isolated scripts set `tools.staged_discovery=False`, unlike installed `/etc/swaag/voice-agent.toml` where it is `true`. That caused a much larger initial 36,915-character action message and 20,285-character response-format schema in a simple identity benchmark. A correct, staged-discovery baseline reduced the first action's actual `prompt_tokens` to approximately 4,407, so the earlier 74-second identity timing must not be passed off as representative production latency. Always record staged-discovery, context settings, exact model route and raw model events when comparing latency.

## Source-grounded correction

The installed `system_foreground.txt` policy explicitly identifies the software as SWAAG's user-facing assistant and orchestrator and instructs the agent not to invent other titles or an underlying model identity. The lightweight independent `foreground_reply_check` now reads **only the first two sentences of that trusted local policy**, not action-model-selected instructions, tool schema content, prior agent claims, or model-authored metadata. It includes those as an explicitly bounded application-identity evidence component alongside the preserved authoritative user request, applicable earlier context and current model-independent system snapshot. It still cannot authorize tools, change user intent, invent effects or bypass task-state freshness checks.

`CommunicationService._orchestrator_runtime_snapshot()` now includes `model_routing.foreground` and `model_routing.default_worker` drawn directly from the configured live `AgentRuntime` instances, with separate `requested_model_id`, `configured_profile` and `base_url` for each. This distinction matters on Thor: the foreground model is the configured Qwen3-Coder, while default workers use Qwen3.8 Q8. The snapshot explicitly labels these as **configured routes, not attestation of the remote model binaries**. The direct checker receives explanatory model-route context only when an actual nonempty configured foreground ID exists. It does not turn a missing model field into a purported fact. Task-state fingerprints continue to cover mutable worker/plan/authority state; immutable model config for an instantiated service does not create false task-state changes.

The independent checker treats installed role metadata and the qualified configured model route as sufficient *source evidence for those facts only*. It must still refuse unsupported claims of Android playback, worker effects, permissions or completed external work and send unresolved substantive work to the full independent verifier. No code pattern-matches the user's question to synthesize an answer or skips model-selected tool use.

## Real model evidence

All cases below used the actual resident Coder endpoint, with private isolated SWAAG sessions and no production user conversation. The first baseline and identity correction were checked with the same ordinary question and live model; single-trial timing is indicative rather than a controlled statistical distribution.

- With proper production-style staged discovery, the uncorrected fused foreground role took **18.770 s** on the identity question and required **one action plus three independent completion-evaluation calls**, including historical source expansion. Source: `/data/var/swaag-benchmarks/fused-baseline-staged-20261019/`.
- With independently grounded role evidence and otherwise equivalent staged discovery, the candidate took **8.911 s**, using **one action plus one successful direct independent verification**. It answered that it was SWAAG's assistant and orchestrator. Source: `/data/var/swaag-benchmarks/grounded-staged-20261019/`.
- The candidate's separate "Can you hear me? Please say hello" case passed after **8.663 s**, with one action plus one independent direct verification. Its answer did **not** claim that the Android phone had played audio. Source: `grounded-identity-live-20261019/greeting/`.
- A question asking whether Android audio playback had actually been fixed returned an honest, limited unknown status after **45.418 s**, without claiming any successful repair or playback; the conservative full evidence evaluator made multiple semantic calls. This slower case remains an optimization and evidence-access gap, not a pass of the response-latency requirement.
- A five-word identity question was answered using exactly five whitespace-delimited words after **7.66 s**. The numeric output constraint was preserved. This is one sample, not general numeric instruction compliance.
- The combined software/model-identity question **timed out beyond 130 s** before model-routing disclosure was added. The candidate repeatedly asserted the model name was absent despite the source route being configured. This failed run remains recorded as genuine negative evidence at `grounded-identity-live-20261019/model/`.
- After adding live configured-model routing disclosure, the same combined question completed in **10.588 s** with **one action and one independent direct verification**. It correctly identified SWAAG and the configured foreground route `qwen3-coder-30b-a3b-instruct-q4-k-m` rather than guessing the Qwen3.8 worker model. Source: `/data/var/swaag-benchmarks/grounded-routing-holdouts-20261019/model/`.

These live cases establish meaningful semantic and speed improvements for selected factual voice queries, while remaining much too slow for ideal full-duplex conversation. Earlier quoted user requirements, ambiguous intentions, very large histories, phone/editor state, simultaneous Q8 load, physical microphone and speaker playback, and unobserved external changes remain separate release gates.

## Tests and release boundary

Dedicated tests verify the exact installed application-identity source appears in the independent checker (and unrelated action instructions do not), configured foreground versus default worker aliases are distinguished in the actual provider snapshot and preserved in its prompt view, missing routing metadata does not become invented knowledge, tool-effects still require full verification, changed authority cannot be delivered stale, and unsupported phone-playback claims fail. An original snapshot-field regression test was first observed failing with `KeyError: model_routing`, then passed with the source addition. The original application-ID candidate before model-route disclosure passed 1,514 offline tests, with three optional skips; that run is not the final amended source acceptance. Live holdouts and complete offline regression must be treated separately. The production SWAAG service is not switched to this candidate until full post-change acceptance and a non-destructive deployment boundary have been verified.

## Complete current-source regression and converged model-name test

After dynamic model-route disclosure, the optional route-guidance guard and added evidence tests, the complete offline SWAAG suite finished with **1,517 passed, three skipped and zero failures** in **311.37 seconds**, retaining the independent completion and safety tests. The source log is `/data/tmp/swaag-grounded-identity-final-full19.log`. A redundant overlapping pytest invocation belonging to this investigation was terminated without touching production tests or services; the surviving complete run reached its own full test summary.

A fresh isolated *real model* regression for the previously non-convergent combined application-and-model question completed in **10.588 seconds** rather than exhausting a 130-second cap. The assistant correctly named SWAAG and its configured foreground model `qwen3-coder-30b-a3b-instruct-q4-k-m`, not the Qwen3.8 Q8 worker route; independent direct completion validation passed in a single call. The wording still included a colloquial team-leader metaphor, which is not a verified organizational title and should not be promoted into an actual role claim. The verified configured model route is dynamically obtained from the running `AgentRuntime`, not from training data or an embedded Thor-specific constant.

The source was built and tested in an isolated worktree; the live audio service remained on its previous fused-verifier revision during these tests. This regression proves better factual software identification and safe semantic evidence access for the tested questions, not global phone/audio reliability, external effect verification or real-time conversation.
