## Correct test surface versus misleading developer-path results

The generic benchmark runner's `AgentRuntime.run_turn_in_session` directly exercises an agent developer session, not the canonical human interface. In earlier isolated real-Coder checks it failed both simple identity cases, answered without SWAAG identity, and made two model calls per question. For the six new conversational developer-path cases, two passed (history pronoun and corrected folder); two identity cases were unsupported and two tool-attempts violated the explicitly zero-tool benchmark contract. These are valid development-path failures, but they do not demonstrate that the deployed voice conversation route has the same defect. Preserve the negative evidence in `/data/var/swaag-benchmarks/conversation-20261103/live/`.

The NEW `swaag.benchmark conversation-acceptance` subcommand invokes the REAL `CommunicationService.orchestrator_message` as used by finalized voice and chat input, with real Coder inference. Each independent case owns a separate private session root and workspace, seeded with actual durable user/assistant messages. There are no shared production sessions, configured tools, worker rights or permitted writes. The CLI preserves durable operation IDs, captures the exact observed final message and independent answer/regex oracle, asserts zero tools/workers, and writes per-case receipts under `/data/var`. The result file and session history are **not** inside the benchmark workspace; an early test discovered the resulting false-positive workspace-mutation verdict and was fixed without weakening the unchanged-workspace assertion.

On Thor, the actual deployed configuration with only development-case session and tool boundaries overridden passed **six of six canonical conversational cases** in the preserved `canonical-benchmark-v2` run. The cases cover identity including rude speech wording, explanatory follow-up from prior actual conversation, pronoun resolution selecting the correct host, latest user correction overriding prior assistant advice, and truthful denial of a previously unexecuted backup. Five fast cases took about 0.7 to 1.3 seconds with one foreground model call. The longer voice-interface explanation took approximately 17 seconds and escalated to a deep action plus completion evaluation. That fallback is slow for a short history-grounded question and warrants a targeted latency/context audit, not an unverified success claim. These six original development cases are not a representative semantic reliability rate, multi-turn scalability study, or untouched final holdout. The October 25 real multi-source false completion remains unresolved.

Focused new benchmark tests passed **33 tests**. Existing broader deterministic regression with the compatible Thor runtime passed **1,731 with three skips**, before the final standalone conversation acceptance module was added; rerun the entire suite after integration when planning deployment. Maintain actual PYTHONPATH `/data/src/github/swaag/src` in testing: the installed site-package is older and can produce an unrelated false failure.

## Real speech ground truth and current limitations

A pinned exact original public LibriSpeech dev-clean dummy parquet was independently SHA256-verified on Nitro and Thor and contains 73 real FLAC waveforms paired with official transcript labels, one speaker, three distinct chapters. The original is retained outside Git under `/data/var/swaag-benchmarks/voice-corpus/librispeech-asr-dummy`, with speaker/chapter provenance, original audio checksums and a documented split: development chapter 128104 (15), validation chapter 135031 (25), sealed holdout chapter 141231 (33). No trained/TTS-generated fake voice was used as the only speech test oracle; the source is actual speech. Corpus license is LibriSpeech CC BY 4.0; provide proper credit and do not embed audio in Git.

Thor's already-running warmed Whisper large-v3 resident service was exercised directly with four development plus four validation original FLAC-derived PCM WAVs. All eight API calls succeeded. The development aggregate nominal WER was approximately 4.82 percent and validation approximately 1 percent. These are tiny, hand-selected portions of one easy read-aloud speaker and not real-phone, multilingual, spontaneous conversation or tail latency estimates. One development completion appended a spurious 'Thank you', which must remain negative evidence for transcript hallucination. The initial elapsed call was roughly ten seconds, later calls generally under 1.5 seconds. The remaining 65 originals, especially 33 untouched holdout clips, have not been used for model/prompt selection. The test is STT only: no irreversible actions and no live SWAAG submissions.

## Independent research checked against actual original literature

Used the native KnowMoreDiRT FileDB semantic search on Raspi, verified current source-hash-backed excerpts, then read actual first pages of the original PDFs for the July 2026 'Speculative End-Turn Detector for Efficient Speech Chatbot Assistant' and 2026 'AgentSuite: Toward More Reliable Agent Evaluation with a Component-Based Benchmark Auditing Pipeline'. The former distinguishes silent hesitation versus completed turns and motivates explicit semantic endpointing and mixed quick/deep classifier tests. The latter isolates user objective, environment, authoritative ground truth and evaluator quality to avoid invalid benchmark conclusions. These support, but do not replace, the actual Infra-guideline contract: preserve exact human final speech, corrections and pause/interrupt semantics; no provisional audio-derived consequential action; end-to-end reliability, manual fallback and verifiable tool effects. Semantic KMD snippets alone were not treated as the full papers. All research originals and semantic index stay outside Git.

## Reproduction

From canonical Thor `/data/src/github/swaag`, use its installed compatible Python 3.13 with `PYTHONPATH=/data/src/github/swaag/src`. First run focused pytest on `tests/test_conversation_acceptance_benchmark.py`, `test_benchmark_catalog.py` and `test_benchmark_runner.py`. Then execute `python -m swaag.benchmark conversation-acceptance --config /etc/swaag/voice-agent.toml --output /data/var/swaag-benchmarks/conversation-20261103/canonical-benchmark-v2`, or select cases with repeated `--case`. The documented output path already contains completed durable receipts; rerunning does not resubmit them. For a new independent experiment choose a fresh output root and do not reset a possibly uncertain previous run. For the STT-only sample use `/data/var/swaag-benchmarks/voice-corpus/librispeech-asr-dummy/evaluate_asr.py`; original source, exact checksums, labels, split policy and outputs reside adjacent to it. No raw audio or prompts belong in public Git.
