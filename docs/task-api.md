# Transport-neutral task API

`TaskApi` is the internal command/query boundary used by the communication service and protocol adapters. Worker state and events remain authoritative; transports do not own task lifecycle semantics.

## Caller-defined structured output

The `create` operation may include `output_schema` and `mechanical_fields`:

```json
{
  "objective": "Audit the release and report the finding.",
  "output_schema": {
    "type": "object",
    "properties": {
      "finding": {"type": "string"},
      "confidence": {"type": "string", "enum": ["low", "high"]},
      "worker": {"type": "string"},
      "state": {"type": "string", "enum": ["completed"]}
    },
    "required": ["finding", "confidence", "worker", "state"],
    "additionalProperties": false
  },
  "mechanical_fields": {
    "worker": "worker_id",
    "state": "status"
  },
  "start": true
}
```

Schemas must satisfy Swaag's portable closed-schema subset. Mechanical bindings address top-level output fields and may use `worker_id`, `session_id`, `objective`, `status`, `created_at`, `started_at`, or `run_count`. Those fields never enter the semantic generation schema. Remaining fields are generated by an LLM call that uses the central context compiler, actual schema-constrained decoding, full-fidelity evidence when it fits, and measured semantic tool-result reduction only on overflow.

The final merged object is mechanically validated against the caller's complete schema and stored in the terminal worker event. `get` returns it as `structured_output`. The ordinary textual worker `result` is always retained as the transport-independent common-denominator response.

## Durable event cursors

`events` returns worker events after `after_sequence` with a bounded `limit`. `events.wait` uses the same cursor and waits up to 60 seconds for a new event or an input-required/terminal state; its `timed_out` and `terminal` fields distinguish those outcomes. Reissuing the request with `next_sequence` is resumable and does not depend on a live connection.

Worker lifecycle rows stay small. Stream-worthy canonical session events are linked by session ID, sequence, event ID, type, and integrity hash. A read hydrates the exact append-only source event on demand and rejects a mismatched reference; raw tool results and semantic status are therefore not copied into a second authority. The AG-UI view maps linked tool calls/results, semantic status, questions, and assistant progress into protocol events. `ag_ui.subscribe` exposes the bounded cursor wait over the current TCP transport without claiming that the transport itself is an AG-UI SSE/WebSocket server.

The A2A projection accepts `send`, `get`, cursor-paginated `list`, `cancel`, and resumable `subscribe` operations. New sends create server-owned worker/context IDs; follow-up messages must cite a matching pair. Inline raw file parts enter the ordinary attachment store before execution, while URL parts remain disabled until an authenticated fetch capability exists. A send follows A2A's blocking default or returns the submitted task immediately when requested.

The communication listener also serves the A2A 1.0 JSON-RPC HTTP binding on `/a2a/v1` and the required public Agent Card on `/.well-known/agent-card.json`, without adding another port or state authority. `SendMessage`, `GetTask`, `ListTasks`, and `CancelTask` return normal JSON-RPC responses. Get/list history limits project exact append-only user/assistant message events with source sequence/hash provenance; list filtering, pagination, and optional artifact inclusion follow the current protocol bounds. `SendStreamingMessage` and `SubscribeToTask` use SSE, atomically capture the initial durable task plus event cursor, then emit only later status/artifact updates until terminal state. HTTP requests require `A2A-Version: 1.0`, bounded headers/bodies, and exact content types. The deployed listener remains localhost-only; authenticated non-local exposure, HTTP+JSON/gRPC bindings, signed Agent Cards, and upstream SDK conformance are separate work.

## Open WebUI Pipe

`integrations/open_webui_pipe.py` is a standalone Open WebUI Pipe for the localhost communication listener. It maps Open WebUI `chat_id` and `message_id` metadata through `open_webui.send` to durable conversation/worker and request/message rows, so retries and service restarts do not duplicate a known request. The Pipe follows progress through resumable `task.events.wait` cursors and obtains the current normal response through `open_webui.get`. It returns final, failure, and blocking-question text directly instead of depending on a transient browser event connection; short `status` events are supplementary.

Open WebUI local file paths and image data URLs enter Swaag as raw content-addressed attachments with exact bytes and source lineage. The adapter does not extract them automatically. Non-local file/image references are described to the worker but are not fetched implicitly. Outbound file/source event projection and live Open WebUI acceptance remain separate from this tested transport mapping.

Task creation also accepts `completion_mode`: `natural` is the default terminal lifecycle, while `continuous` explicitly keeps semantically complete cycle results provisional and starts another context-compiled improvement cycle. Continuous workers stay in `working`, expose the latest provisional result and durable iteration events, and stop only through cancellation or a blocking LLM-authored question. Because they intentionally have no terminal completion point, they cannot declare a terminal caller output schema.
