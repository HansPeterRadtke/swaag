# SWAAG source-to-installed-package preflight — 2026-10-22

## Reason and limits

The October twenty-second read-only inspection on Thor showed a clean source checkout and active Thor SWAAG communication and voice-gateway services. The source checkout was not the same as the Python package installed in the runtime virtual environment. Earlier source tests cannot establish that those running daemons use the newly tested code. The main service restart and voice-agent work remain owned by separate concurrent tasks; this work did not restart or install anything.

The older 'scripts/verify-live-deployment.py' already compares installed package assets but assumes particular legacy systemd unit names and health endpoints. Its full check is not portable to the Thor-specific service layout. For the shared source/package requirement, 'scripts/verify-installed-package.py' now provides a non-disruptive, individually runnable release preflight.

## Command and expected result

Run: python3 scripts/verify-installed-package.py --repo /data/src/github/swaag --venv /data/var/swaag/venv

It interrogates the selected runtime interpreter in isolated mode, checks SQLite meets the required version 3.51.3 floor and supports FTS5, and compares exact on-disk hashes of source and installed Python package files/assets, excluding generated bytecode. Missing, extra, modified or symlinked paths produce exit status one and structured JSON evidence. It neither imports SWAAG's runtime application nor writes the runtime database. Optional '--output' writes a chosen local JSON report; '--installed' permits offline/isolated comparisons without loading a virtual environment.

For the inspected Thor state, the read-only tool returned **not passed**, with **seventeen source-only files**, **twenty-nine differing installed/source files**, **zero installed-only files**, and SQLite **3.53.1**. The JSON evidence was saved under the SWAAG runtime data directory. This is an observed deployment discrepancy, not a diagnosis that a specific live process has malfunctioned. The gateway's process was still active from October eighteenth; installed files alone do not prove which code an already-running process has loaded.

## Verification and acceptance boundary

The standalone preflight and existing deployment-asset regressions passed eleven source tests. Existing source tests on Thor passed sixty-eight focused status, orchestration, context and presentation cases earlier in this run. The initial Nitro checkout's twenty-five status tests also passed against an isolated official SQLite 3.51.3 library.

This new preflight must be rerun and return zero after an explicitly authorized, idle-safe release. Even a zero result proves package byte equality *only*, not active-process freshness, safe backend cancellation, correct model routing, voice-device behavior or end-to-end user action acceptance. Independent process, endpoint and behavioral checks remain mandatory. Do not hot-restart, overwrite active voice-agent changes, or claim live deployment convergence based solely on this report.
