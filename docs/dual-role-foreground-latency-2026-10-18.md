# SWAAG Coder/Q8 foreground delegation repair — October 18, 2026

## Scope

After the user's model-role reassignment, the production voice orchestrator uses Qwen3-Coder Q4 at `14833/v1`, and default background workers use Qwen3.8 27B Q8 at `14835/v1`. The first isolated live cross-role trial established genuine delegation and Q8 worker completion but took 249.482 seconds and included two invalid `orchestration_control` arguments. Its final user-facing reply described the worker as queued even though its durable result was already completed. The goal is to reduce mechanically avoidable failure without disabling independent completion checking or inferring user intent from keywords.

## Changes

The orchestration-control tool explicitly instructs the model to use `plan.apply` for an already constructed graph and to set the unrelated top-level `completion_mode` field to null. Its validator accepts a redundant top-level `completion_mode` on `plan.apply` **only when every nested node explicitly has exactly the same valid mode**; that redundant value is removed from the validated invocation while the raw original tool call remains in audit history. An inconsistent mode, an unrelated operation using that field, or an invalid graph is still rejected. This addresses the exact initial failure in the real retained trace and prevents the interface from failing because a model repeated an identical declaration at two levels.

The existing independent foreground completion checker also receives a concise reminder: for an already verified asynchronous handoff, prefer the current task receipt over older administrative audit records. It remains free to request evidence when material facts, constraints, effects, or authority genuinely require it. No deterministic completion bypass, forced “short answer,” hidden tool permission, worker preemption or GPU scheduler change was added.

## Results

The source change was tested using the same isolated real-model cross-role harness from the retained experiment, with a new private session store. Coder generated one accepted `orchestration_control` plan application with no invalid tool retries. The durable plan created exactly one default Q8 worker. The worker returned the expected `CROSS_ROLE_COMPLETE_42` and the plan completed. The measured elapsed foreground time was **154.685 seconds**, versus **249.482 seconds** in the earlier trial, reducing wall time by **94.797 seconds (38.0 percent)** for these **two different runs**, not a repeated-seed statistical latency claim. Latency still fails interactive requirements, and model generation still dominates.

The isolated test recorded that the orchestrator produced multiple model calls after plan creation, in part due to task-state updates during model generation and evidence-checking. It is not evidence that the full conversation is now fast or that its final current worker status is always accurate. A separate status-freshness implementation is still required. No production model service, worktree or durable user-worker record was modified by this trial. The source trial is kept under `/data/var/swaag-benchmarks/dual-role-fix-20261018/` and the baseline under `/data/var/swaag-benchmarks/q8-role-acceptance-20261018/`.

Six focused deterministic tests in `tests/test_dual_role_plan_input.py` verify redundant mode tolerance, conflicts, unrelated operation rejection, node mode preservation and invalid graph rejection. The 63 orchestration-focused regressions passed. The complete offline suite on this branch recorded **1,489 passed, three skipped, one failed**. The one failing test, `test_orchestrator_snapshot.py::test_full_action_gets_global_state_without_lookup_tools`, was separately reproduced unchanged on the original production worktree, with the identical `No fake model responses left` failure. It is an **existing test-fixture/verification integration failure**, not a new passing claim and not evidence that this patch caused that defect. Do not describe the full suite as green. Its exact output is `/data/tmp/swaag-dual-role-full-20261018.log`, and the unchanged baseline reproduction is `/data/tmp/swaag-baseline-snapshot-20261018.log`.

## Remaining work

The recorded final answer can become outdated while the worker finishes; it must be reconciled with verified current state and delivered without altering the user’s authorized task. That requires full replay, stream and Android audio assertions. The foreground controller can still run excessive completion-evidence expansion and action retries; these must be optimized without mistaking queued actions for completed real-world effects. Realistic large programming/UI tasks, interruptions, voice audio and simultaneous GPU contention remain open acceptance. This change has not been deployed to production; do not claim that phone latency improved merely because the isolated test did.

## Current worker state at final reply — implemented and live tested

A separate regression reproduced the observed truthful historical queue receipt becoming misleading by the time the reply finally reached the user. A verified `orchestration_control` `tool_result` includes `started_worker_ids`; these are concrete durable worker identities, not an action draft or an inference result. The new `swaag.orchestrator_delivery` helper reads **only** real successful start receipts from the exact current orchestrator turn (bounded by `turn_started`), looks up current statuses in SWAAG's canonical worker store, and builds a brief factual follow-up when a started worker is already completed, failed, canceled, or awaiting user input. It never promotes a merely queued or working worker into a terminal status and never claims external side effects that the worker record cannot verify. It is not a keyword router for user intent.

After normal independent foreground completion evaluation and `turn_finished`, the communication service appends any qualifying status update to the delivered reply, and commits an `orchestrator_worker_status_delivery` event containing the exact original turn-finished sequence, suffix and source worker status identities. The stored suffix is reused on receipt recovery/reconnect so replay does not repeat a tool action or produce an unexplained different historical answer. User-specified `exact_word_count` response constraints and deliberately silent completions are respected. No tool or model execution is introduced by the status append.

An actual fresh isolated **Coder foreground → orchestration_control → default Qwen3.8 Q8 worker** trial exercised this deployed-model behavior on this source branch using `/data/var/swaag-benchmarks/dual-role-fresh-status-20261018`. The worker durably completed with the requested exact `CROSS_ROLE_COMPLETE_42` and the model's original reply still described it as queued. The final answer now also contained an explicit verified update stating that SWAAG's worker records show the delegated worker completed. The cross-role harness passed. Measured total foreground time was **153.451 seconds**; this remains severely too slow for normal speech and is not statistically better than the earlier 154.685-second run. The separate raw model/action journal confirms retries from a first invalid planner operation, later rejections when genuine worker state changed during generation, and completion-evidence expansion. **Status accuracy is addressed at final delivery for workers started in the same turn; excessive model-generation latency is not fixed.**

Deterministic regressions under `tests/test_orchestrator_delivery_status.py` cover successful current-turn receipts, absent/malformed/failed/unrelated tool receipts, exclusion of prior turns, worker lifecycle changes, preserved strict word counts and exact durable replay. They also verify that the original committed assistant text remains unchanged. The generated follow-up reports SWAAG's durable worker status, not an independently proven effect outside SWAAG. Repeating a completed historical answer after a new unrelated user turn does not re-query the worker and alter the old recorded answer.

The previously failing global-snapshot unit test was investigated. Its fake model response callback asserted a *specific old prompt display label*, even though the required completed/blocked worker facts and exact durable snapshot were already supplied. That obsolete assertion threw an exception inside the fake model callback and caused a retry, eventually reported as `No fake model responses left`. The corrected test asserts the actual worker contents and durable snapshot without depending on a rendering label, and scopes its sole fake model reply to action-context coverage; independent completion review remains covered separately. This is a fixture correction, not a production change that skips completion evaluation.

## Complete candidate offline regression, source and production boundary

After the replay-safe delivery update and obsolete snapshot-label test correction, the **entire** offline SWAAG test suite completed with **1,501 passed, 3 skipped, 0 failed** in 257.02 seconds. Exact output: `/data/tmp/swaag-dual-role-fresh-status-full-20261018.log`. No model inference was enabled for that suite. This supersedes the earlier non-green regression count in the first trial of this branch; the earlier failure log and baseline reproduction are retained as debugging evidence, not erased.

An independently recorded live dual-role trial using this candidate source completed in **153.451 seconds**. The fresh final response includes the verified terminal worker status; its canonical session journal contains `turn_finished` followed by the immutable `orchestrator_worker_status_delivery` event with the exact worker ID, `completed` status, and suffix. The model still sometimes submits an initial invalid operation and repeats foreground actions after background state transitions. Hence this change corrects truthful final status and eliminates some redundant validation retries but **does not** establish acceptable voice responsiveness. The full live test used disposable session storage and real resident Coder/Q8 servers, not the production user conversation. The new implementation must be merged with any newer production voice-priority patches and qualified there before restarting services.
