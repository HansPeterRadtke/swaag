## Correction to SWAAG's installed-context behavior

The complete, tool-using SWAAG orchestrator previously had no general task-specific Infra guideline navigation reference. It was prompted to check applicable guidelines before asking the owner, yet the implementation did not advertise where the owner's guideline families were. In the isolated SWAAG worktree `audit/cross-domain-guide-routing-20261021`, `src/swaag/system_context.py` now exposes a small mandatory, non-projectable `infra_guideline_navigation` source when the configured filesystem read tool can actually access the resolved Infra root. The entry supplies the trusted index, agent rules, named project families and the separate Google operations runbook when permitted. The model must still select, read and apply the correct guide for the **actual task**; it does not receive all guidelines for every call and has no new filesystem permissions or ability to execute instructions from gathered documents. This is a source-discovery fix, **not proof that the semantic model always reads every relevant rule**. The fast one-call conversational layer is deliberately unchanged. A tested production-configuration instantiation produces an approximately eight-hundred-character guideline locator with the configured Qwen Coder model unchanged. Three focused source tests passed, including unreadable-root and symlink-escape cases. The integrated SWAAG source suite in that isolated worktree passed **1,672 tests, three skipped, no failures** before the source trace scripts were added; the trace scripts have their own three deterministic unit tests and six focused tests together.

## Real cross-repository evidence on actual hosts

**KnowMoreDiRT / KMD** — The Nitro checkout was old, clean, and pinned to a May revision. Basic Nitro unit and smoke tests passed forty-one checks but the evaluation suite failed four tests: **71/134** difficult raw reasoning questions, **29/60** messy document questions, plus broad/noise fixture failures. That is an actual model/semantic-quality failure, not a harmless documentation omission. The Raspi source was a distinct July revision, passed eight evaluation tests, and its hard test expected **131/134** (not perfect). Independent Nitro `git ls-remote` confirmed the actual origin master had advanced to a third, August revision; it was fetched into a **separate clean worktree**, not overwritten onto the older checkout. The upstream August evaluation-only suite passed eight tests, with its own hard benchmark threshold of **129/134**. A larger upstream suite remained incomplete after a three-minute timeout after more than half of the test collection had executed, so **the upstream source is NOT certified for promotion** and the Nitro default checkout is unchanged. These three revisions and their differing hard fixtures must be reconciled with an independent identical heldout corpus before concluding which is better. The foundational KMD goals of semantic, provenance-grounded, correct contextual scope across quotes, dreams, negations, file boundaries and time remain open as a product-level acceptance task.

**Nitro Games** — The real Games working tree had more than eighty preexisting changes, so no source mutation or merge was attempted. Eighteen targeted systemic simulation, adapter and RPG contract tests passed. This tests some game-core mechanics but **does not certify** actual headless 3D physics authority, equivalent text/2D/3D results, no-loss save-anywhere across active physics/quest state, player-trained habit rollout, occult hidden-rule experimentation or actual human enjoyment. The Games recordings govern those distinct behaviors, not SWAAG's agent test suite.

**Nitro Trading** — The working tree had hundreds of concurrent modifications, so no destructive reset, checkout or blind change was attempted. Four targeted real SQLite tests passed for schema/foreign keys, time-aware security identity, observed `available_at` versus event date, and canonical source evidence. A combined trading GUI plus database acceptance run unexpectedly continued for several minutes without useful completion; the audit-owned process was intentionally terminated to avoid wasting host resources. This is a **runtime/verification gap**, not a passing GUI test. Correct historical quote depth, actual put-assignment and liquidation mechanics, realistic fill fees/collateral and independent trading alpha remain **unproven** by those four tests. Prior Trading research documents physically impossible older simulation assumptions; profitability claims must not be promoted from those old results.

**Infra Google/mail/Calendar** — Twelve real offline runbook ownership, model/service separation, OAuth boundary, security and operational documentation tests passed on Thor. The actual provider/Android notification lifecycle and external irreversible operations were **not** executed as part of this audit. The dedicated Multiverse account must never be confused with the owner's personal account. These are Infra-owned integrations, not a side effect of SWAAG core code.

**Nitro Infra Gallery / HMI** — The original browser acceptance run reported seven passing non-browser checks and nine failures during browser setup, because tests assumed `/usr/bin/chromium` and `/usr/bin/chromedriver`. Nitro actually has Chromium and the matching ChromeDriver in different locations. A real Chromium WebDriver session was proven against an offline page. A portable, no-download path discovery helper and corresponding test-script edits are in isolated Infra worktree `fix/offline-browser-test-discovery-20261021`. Running those tests exposed another genuine defect: the production Gallery page did **not include its dedicated viewport stylesheet**, despite shipping it. The outdated gallery test also relied on removed `GalleryViewport` APIs and a renamed label element. The test was adapted to the current `GalleryZoom` API and a realistic explicit `Fit all` interaction. A separate live Chromium test then caught the sticky Save footer physically intercepting the `Bring to front` click on the image editor. The candidate CSS moves Save into visible, in-flow position rather than covering editable controls; it is loaded through the corrected page stylesheet link. The affected upload/layer test passed in Chromium after those fixes. Full Gallery suite and mobile behavior must pass before merging this change or calling the UI repaired.

**Networking, robotics and other domains** — The source documents were individually inventoried and classified, but no arbitrary UDP/QUIC migration, physical robotics safety run, new broker trade, user media publication or production device change was executed merely because a guideline discussed it. Actual cross-host transport tests, physical robot controllers, KMD discourse, UI design/feedback with exact interaction geometry and model-quality holdouts remain unverified. The full guideline families and each file are explicitly indexed in `infra-guideline-full-topic-coverage-2026-10-21.md`.

## Blocking failures versus unresolved design choices

The audit uncovered real defects: (1) missing project guidance navigation in SWAAG's full model context, (2) severe failed KMD semantic acceptance on a stale Nitro revision, (3) test/browser configuration absent on Nitro, (4) Gallery stylesheet omission plus real overlapping Save controls, and (5) long-running Trading GUI acceptance that cannot be interpreted as success. These are materially different from hypothetical technology options and are not solved by a merely comprehensive requirement document. Source-level fixes need a clean commit, passing targeted and broad regression, installed-source verification, and actual client interactions where required.

The larger open program is not a single coding switch: actual long-range semantic relevance with discourse scope, goal relevance/supersession, uninterrupted physical Android speech with configurable manual fallback and playback controls, per-host OS/security/resource quotas, true concurrent GPU model scheduling and honest task progress, point-in-time economic testing, and actual game/robot project acceptance. A small passing example is only a partial proof of its defined scope. No unverified effect should be reported as achieved.

All cited runtime logs are under their originating host's `/data/var/` or `/data/var/swaag-audit/` directories. Source files were left intact; KMD/Games/Trading/Android active project trees were not overwritten. The Infra and SWAAG worktree changes are isolated until tested and integrated. The source/corpus inventory is auditable, but **complete proposition-level compliance is not yet established**.
