## Immediately usable tiered default, from real positives and negatives

**Instrumented web/desktop GUI:** run real browser widget bounds, child `scrollWidth/clientWidth` plus computed overflow and actual clipping ancestors, visible text expectations, font scaling and layout conditions first; use [axe-core](https://github.com/dequelabs/axe-core) for the supported computed-style WCAG accessibility rules. A previous independent Firefox original-site study detected all **nine** known target-container text clipping positives and had **zero of nine** paired control false alarms, **when the correct target element/criterion was supplied**. This is a *narrow contract*, not broad GUI validation. Its root-page viewport-overflow shortcut missed **five of seven** protruding targets; CSS clip ancestors and element-local bounds must be inspected. In a separate independent W3C ACT contrast test, axe-core 4.14.0 executed thirty-two safe original test cases, including seven correct failures, seven passes, nine not-applicable, eight inconclusive and one applicability error; two scripted cases were intentionally excluded. Do not count eight unknowns as passes. CSS/background-image and gradient cases require explicit inconclusive handling or verified visual review.

**Rendered screenshots when HTML/widget source is unavailable:** apply OCR with an independent expected-text list and a specialized screen element parser only to gather proposed regions. On eighty-two truly rendered, strongly human-annotated SlideAudit overflow positives and eighty-two category-specific controls, a fixed pixel OCR border signal found **fifty-eight** defects and falsely accused **twenty-six** controls; source text box off-slide geometry found **nine** defects and falsely accused **seven** controls. Conversely, on one hundred and five rendered positive *occlusion* examples and one hundred and five controls, original layout-object geometry found **ninety-three** but falsely accused **thirty-three**, while overlapping OCR word boxes found only **twenty-four** and falsely accused **twelve**. Source overlap regions were significantly localized against independent human regions beyond a matched uniform spatial null (85 of 104 with human boxes versus roughly 44 expected random, 10,000 trials). These are presentation slides, including intentional source augmentations, **not mobile/desktop GUI app deployment accuracy**. Generic CLIP ViT-B/32 actual local inference on the same real images had ROC AUC below 0.5 for all three visual flaw prompts. ScreenParser YOLO11-L on thirty-two real full-page Firefox screenshots located only eleven selected target DOM rectangles at IoU at least 0.5, averaging roughly one minute per image on busy Nitro CPU; it generates boxes/classes, not a defect verdict. Real visual occlusion requires checking intention, opacity, overlap ordering and actual final pixels, not simply stacking bounding rectangles.

**Source-backed charts and diagrams:** verify required graph nodes, edges, directions and labels from the source schema and the intended chart data before rendering. Compare actual rasterized labels/connection regions with OCR and targeted visual proposals; abstain when an expected label is unreadable or an arrow's direction is ambiguous. In [SADU](https://zenodo.org/records/19339991), 154 original real software architecture diagrams with 2,431 human-source QA questions, our independent re-scoring of eleven archived VLM model outputs found the best around **72% strict source-answer accuracy**. Tesseract extracted 820 of 1,733 distinct source-annotated entity labels, **47% overall**, though simple entity–relationship diagrams were substantially easier. The same source graph had 924 internally consistent numeric QA checks; that does **not** establish that its final PNG contains every node/arrow correctly. Do not confuse valid reference numbers and confident caption text with actual visual semantic correctness.

**Three-dimensional and physically plausible industrial objects:** inspect actual saved component instances, source-version identity, engineering units, world-space mesh triangles, intended collision/contact areas, object orientation and full support/kinematic chains. This can prove *a specified local geometrical fact* but not all machinery's material, stress, motor, weld, friction or global stability properties, nor whether the final render *looks* photorealistic. On 119 externally human-labeled generated GLBs, a generic mesh AABB overlap flag found only **nine of thirty-three** missing semantic parts and falsely flagged **twenty of eighty-six** negatives; all 119 had an open mesh and zero degenerate triangles under the fixed tolerance. Human semantic completeness cannot be derived from generic mesh validity. The five-model expert-adjudicated VLM majority voting scored **eight of thirty-one** missing parts, with **eight false alarms among sixty-eight** negatives. Specialist trained industrial-image methods such as [PatchCore](https://openaccess.thecvf.com/content/CVPR2022/html/Roth_Towards_Total_Recall_in_Industrial_Anomaly_Detection_CVPR_2022_paper.html) or [EfficientAD](https://openaccess.thecvf.com/content/WACV2024/html/Batzner_EfficientAD_Accurate_Visual_Anomaly_Detection_at_Millisecond-Level_Latencies_WACV_2024_paper.html) may help when calibrated on *actual clean and defective images of the same product family*, not as a substitute for engineering correctness or real-world photorealism. Their source author headline scores were never independently established for our forklift/warehouse.

**Moving video and audio:** verify timestamps, source-to-final frame references, explicit source edit/cut/allowed-hold contract, visible continuity candidates, and audio event alignment as distinct requirements. Use [FFmpeg freezedetect](https://www.ffmpeg.org/ffmpeg-filters.html) only to report low frame-change intervals; it cannot tell that a deliberately static editorial hold is an unwanted video freeze. Two original warehouse/dock native 30-FPS outputs had 420 frames each and uniform presentation timestamps, but that did not establish visual smoothness; the warehouse intentionally includes a final three-second camera hold. In externally human-annotated Spotlight videos, flow-warp residual flagged only five of nine original motion-error-positive clips, and nine of eleven annotated temporal peaks were not convincingly above a random-time control (around ten percent of random runs matched or exceeded the count). In a separate human preference physics comparison, original native FPS alone predicted all eighteen pairwise preferences, so the optical-flow apparent win could not be credited to physics reasoning. [LIVE Mobile Video Quality](https://live.ece.utexas.edu/research/Quality/live_mobile_video.html) includes original frame-freeze distortions, while the [LIVE Mobile Stall Video Database-II](https://www.colorado.edu/lab/live/live-public-domain-subjective-mobile-stall-video-database-ii) provides 174 streams with 26 stalling-event patterns from 24 references and 54 human raters; these are more relevant independent datasets but download requires an access request. **Neither was downloaded or locally scored here.** A complete production temporal/video model remains unqualified.

## New decisive source evidence: vertical contact can pass while a complete real support chain fails

This continuation investigated the **actual saved production warehouse scene** rather than an easier synthetic cube mockup. The owner had previously reported a visually floating-pallet problem. Existing immutable source scenes preserve successive repair stages: original pre-bearing geometry, a stage with all 72 added steel bearing bars but uncorrected rack axes, and a final stage with horizontally reoriented racks. Existing production source code at `/data/var/warehouse-film-v45/fix_actual_rack_orientation_and_contacts_v45.py` explicitly rotates the twelve double-rack world matrices **ninety degrees** to align their long axis with the pallet load positions; this is separate from adding the steel bars. We independently verified original world-space 3D mesh geometry and actual triangle ray intersections, not code comments, previous checks or JSON flags alone.

All source checks were run with **Blender 4.0.2, `--disable-autoexec`, one low-priority CPU thread, no Cycles render and no GPU**. Exact scene and result SHA-256 provenance resides in `perceptual-owner-warehouse-physical-contact-chain-2026-10-25.json`. For each actual pallet, the wood underside was derived from real transformed mesh vertices. For each of 72 steel bearing bars, several upward rays from its declared support footprint were cast against its specifically referenced actual pallet wood mesh, requiring an intersection within **two millimetres** of the steel top. Separately, six predefined downward rays near each bar's two intended rack-flange end regions tested for actual triangle intersections with the **correct original rack mesh** inside the steel bar's vertical slab. These are distinct physical properties and were measured without reading the prior QA labels.

| Physical source stage | Real pallet wood–bearing contacts within 2 mm | Steel bearings contacting original rack at both ends | Full source chain passes |
|---|---:|---:|---|
| Intermediate **bearing-bars-present** stage, racks still misoriented | **72/72** | **0/72** | **No** |
| Corrected rack-orientation stage | **72/72** | **72/72** | **Yes, under the defined contact geometry gate** |

The corrected wood-to-bearing measured gap at sample points is **minus 0.3 millimetres** (a slight spatial overlap), not an unsupported air gap. The intermediate stage's **wood-to-steel gap check alone would falsely pass all 72** while none of the bearing bars intersects the intended rack support at both tested ends. This is exactly the type of real mechanical source error that a careful deterministic analyzer can find and a simplistic geometry proximity check can miss. Our independent intermediate and corrected checks each used the same six rack-end probe offsets and preserve the original negative results. **A missed ray can also result from sparse sampling**, so the gate checks specific required contact locations; it is not an unlimited search for other supports.

**Controlled source lineage is critical.** The 24 complete pallet world-space mesh fingerprints match exactly at a ten-micrometre coordinate resolution across the pre-repair, intermediate and corrected stages. All **72** steel bearing-bar world-space AABBs likewise match exactly (within ten micrometres) between intermediate and corrected stages. The original twelve rack world-space mesh fingerprints match pre-repair to intermediate, but **all twelve change** between intermediate and corrected, consistent with the separately inspected ninety-degree world-matrix rack repair. This makes the intermediate-to-corrected comparison a particularly informative *local repair contrast*: it changes rack orientation while holding the pallet and bearing geometries fixed. It does **not** make 72 bar contacts statistically independent cases; they are components of one correlated manufactured scene. It also shows why a previous vertical-contact result could sound stronger than the evidence supported. The earlier source scene with no added bars produced zero rack-face hits at the 144 predefined prospective bearing endpoints, but that sparse negative is *not* proof there were no possible original contact points elsewhere.

**Temporal stability for this local geometry result:** in the corrected saved movie source, all **108** directly relevant mesh instances (24 wood pallets, 72 steel bearing bars, twelve racks) had identical world-space vertex fingerprints at original frame indices one, ninety-one, two hundred and ten, three hundred and thirty, and four hundred and twenty, and none of those instances had object/mesh animation data. This supports applying the same static contact result to those sampled points in the 420-frame film. It does **not** certify appearance, all unobserved effects in every rendered frame, beams' load strength, welds, maximum allowable load, the final buyer archive or the photorealistic lighting.

**Evaluation integrity:** this is an actual company-owned asset with one correlated source scene and a single documented multi-stage repair. The binary positive/negative stage comparison demonstrates a meaningful *failure mechanism* and a successful *specified geometric gate*, but no independent-human-dataset true/false rate or scientific reliability interval for unrelated mechanical products can be inferred. Human-labeled industrial assembly images with known CAD and engineered supports are still needed before claiming generality. The measured example directly supports the tiered default: source integrity and **full component relationship** first, then engineering checks, then real rendered visual assessment, with an explicit unknown state when source intent or contact topology is ambiguous.

## What remains decisive rather than generic additional work

The original requested scientific objective remains **PARTIAL**. For GUIs, a genuinely untouched human-rated corpus of real dynamic application text clipping, overlap and contrast is needed, separately from slide design datasets and author DOM labels, before setting reliable global acceptance thresholds. For diagrams, source graph consistency and printed legibility alone cannot establish every arrow/relationship or visual readability. For physical/mechanical renders, engineering-certified source CAD and independent real positive/negative render samples are needed for false positives/negatives and visual realism, beyond this one source-scene contact chain. For video, the next meaningful external experiment needs actual trusted clean-versus-time-coded natural freezes/judder with controlled frame rate/codec and expert labels, followed by testing specific model versions, resources and latency. The previously denied external result retrievals were not repeated. No calendar events were created.

Only existing SWAAG research paths and a source-linked analyzer registry should be updated. The Blender scenes, mesh data, raw rays, source videos, thumbnails, model weights and other workers' code/checkouts remain untouched; no production GPUs or rendering were interrupted. A clean source-backed contact check is stronger than visual guessing, but it is not a universal photorealism or engineering proof.


## Original-source temporal gameplay VLM benchmark update (25 October 2026)

A new source-linked video-specific continuation at [`perceptual-tempglitch-primary-video-evidence-2026-10-25.md`](perceptual-tempglitch-primary-video-evidence-2026-10-25.md) examined original [TempGlitch arXiv:2605.21443v1](https://arxiv.org/html/2605.21443) and **all 1,500 original source file metadata entries**, independently recalculating every published confusion matrix for **twelve VLMs (twenty-two input variants)**. The author-created Godot benchmark has 750 deliberately injected glitches and 750 normal clips across five temporal categories, not independently blind human-ranked production videos. Its best original model reached only **54.1% overall accuracy**: GPT-5.4 Mini at 5 FPS had **173 detected, 577 missed, 112 false alerts on 750 normal, 638 correctly accepted clean**. Qwen3-VL 8B at 5 FPS detected **2/750** glitches with no false alerts, while Gemini 3 Flash given raw video detected **654/750** but falsely accused **650/750** normal videos. These are exact original author-run model results, not Nitro/Thor inference. A trivial *always-glitchy* classifier scores **66.7% F1** on the balanced corpus while flagging every normal video. Thus F1, precision, model confidence and denser video frame sampling are not sufficient release-quality evidence.

In a separate independent source-metadata audit, a fixed size-only/category logistic baseline trained on 1,180 source listings and evaluated on **320** heldout original clip listings gave **87 true positive, 73 missed, 66 false positive, 94 true negative; ROC AUC 0.599** (paired-source bootstrap 95% descriptive interval **0.547–0.653**). No actual video pixels were used for this baseline, and it must **not** be compared statistically head-to-head with published VLM predictions on all 1,500 clips. Source release integrity also required distinguishing **75 Platformer and 75 TPS** videos whose Stuck-in-Place numbers overlap. The only verified conclusion is that source files contain a nonvisual category-correlated size signal; this does not show the tested VLMs exploited it. Source data are two Godot demo environments and original author labels, so the decisive production fault benchmark and independent subjective labels remain open. No huge 60GB release download or production GPU call occurred.
