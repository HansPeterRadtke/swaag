# Real Android GUI heldout source-reference perceptual check — 26 October 2026

**Status PARTIAL.** This is a new source-external actual Android screenshot test, separate from earlier SlideAudit/Firefox source and synthetic manual tests. Public source: [RotBench Android screenshot bug benchmark](https://huggingface.co/datasets/ImDim/RotBench), pinned revision `25b6e8214c5be600f54dc0834eaf4597fa9192e6`, test JSON SHA-256 `0586b29f82590636806e7dd05a45e6933d46286318a52e444cee4241fb785ca7`. The source has original captured Android states and independently author-injected mutation labels. The positive mutations are synthetic and were **not independently human-reviewed for perceptual severity**. Only research artifacts and code were saved in SWAAG; original screenshot media stays in isolated `/data/var`, license unconfirmed, not distributed.

## Independent external labels and fixed matched negative control

The pre-gold frozen manifest SHA `2dee311bfaa8a4161178f37eb93ad5af8bcd55695ec9ab0fab5401caf7f93a86` selected 25 clip and 25 overlap mutants and 50 source normal cases by hash rank among test records, from **39 apps and 81 activities**. The source JSON includes label-leaking filenames; paths were used for stratification, NOT for prediction. All 100 case predictions were computed using actual native-resolution decoded screenshots and the author-captured matching correct orientation image, then frozen under SHA `8bc7860b4e5861d1d00330ac87ebacfabbd44ad886ec9aa52a9b179f8b27ebeb` **before** the original author bug labels were joined. The predeclared negative control used the same threshold, native image dimensions and operations but a clean reference screenshot from an *unrelated* activity, frozen separately with SHA `4a9c264b65e2f84d12051b28013c54fa0fcc0b88fafb4b5765cefb6572afff9c`. This directly tests a source identity shortcut; it does not test benign real UI state changes. Raw metadata and exact source files are private isolated research storage, not Git.

| Detector on same 100 screenshots | True defects found / 50 | False alerts / 50 controls | Defects missed / 50 |
|---|---:|---:|---:|
| Correct reference + localized pixel difference (changed area >0.05%, RGB channel difference >=24) | **39** | **0** | **11** |
| Same aligned actual source images, **global** mean RGB difference >1.5 | **3** | **0** | **47** |
| Same localized difference but **wrong app reference** | 50 | **50** | 0 |
| Null always predicts normal | 0 | 0 | 50 |

The localized method found **25/25 overlap** and **14/25 clip** author mutations. All eleven misses were clipping mutations that demonstrably changed native screenshot pixels by only **0.0054% to 0.0464%** screen area; no missed mutation was a byte-identical no-op. Sensitivity 39/50 has descriptive exact-binomial 95% interval **[0.6404, 0.8847]**; this is optimistic as independent inference because samples share 39 apps. A 0/50 false alert rate has an independent-binomial upper 95% bound of about **7.11%** even under these easy conditions; real benign state changes were not sampled at all.

The localized versus global method compared exactly the same decoded pixels, original correct references and low-priority CPU processing; 36 positive mutants were detected only by localized pixels, 3 by both, 11 by neither. This directly demonstrates that global visual averages conceal small clipped content even when correct reference frames are available. The source-aligned feature extraction took **66.126 s**, the matched wrong-reference negative control **81.279 s** on busy Nitro CPU, no GPU. The wrong-reference negative produces 50/50 clean false alarms: successful detection utterly depends on **correct reference identity**. These timings include both shared localized/global measures in each pass, so are not separate model latencies. Frozen input features, SHA receipts and every per-case prediction and author label are in the companion JSON.

## Owner production decision

**Auto-fail only** the property *“the actual final screenshot deviates from an approved immutable original by more than the defined tolerance”* when both reference identity/version and final rendered screenshot are independently verified and the workflow really forbids changes. On a live changing Android/web UI, this test must **abstain or propose REVIEW**, not label a developer's legitimate changes as faults. OCR, UI VLM, region overlap, contrast proxies and a general high-confidence caption remain evidence proposals unless separately verified against appropriate actual final pixels and semantic requirements. The new external Android sample does not certify native GUI release, independent human-accepted low-contrast, natural valid screen changes, diagram arrows, industrial CAD photorealism, final owner warehouse rendering or temporal/audio sync. Existing actual owner source mesh contact data prove the narrow 72/72 corrected support-chain contract; existing TempGlitch benchmark had at most 1/12 localized character freezes. **Single decisive gap still unresolved: independent human/authoritative gold for actual final owner outputs with truly legitimate dynamic negative variations and time-coded physical/video defects.** No production service, GPU model, previous uncertain Enter, denied source-result retrieval or live asset was touched.

## Reproducibility

`nice -n 15 python3 tests/research/rotbench_frozen_actual_android_pixels_20261026.py freeze` then `extract`; `nice -n 15 python3 tests/research/rotbench_mismatched_reference_control_20261026.py`; then original script `score` and `python3 tests/research/publish_rotbench_android_20261026.py`. Each stage refuses to overwrite a frozen artifact; remove/repoint the isolated data directory only for a genuinely separately declared replication, not this recorded run. No external media is committed. In a new environment this requires permission to download the externally hosted public screenshots; the original author's test labels are only read at `score` time. The committed JSON supports offline integrity and confusion-count tests without the source media.
