# Real source gameplay animation freeze: is whole-frame or region-aware video analysis enough?

**25 October 2026. Research verdict PARTIAL.** The owner asked for actual judgement of dynamic visuals and video motion, not a fake frame-difference pass. The preceding original VideoSham benchmark evaluated deliberate video-editor frame changes, whereas the published TempGlitch VLM source tables measured in-game engine animation anomalies but no local image pixel algorithm was actually run. This independent new video-source test uses **24 original videos (twelve creator-injected frozen CHARACTER ANIMATION, twelve scene-ID/family-matched normal gameplay clips)** in the original [TempGlitch dataset](https://huggingface.co/datasets/asgaardlab/TempGlitch) (2026, Godot Platformer game, source author engine-injected labels, MIT dataset release). All original source MP4s were fetched from the pinned public release and verified by exact official original content SHA256 and bytes. **No source output or defect footage was synthetically generated by our scripts.** Original 716.73MB videos and per-scene output remain outside project Git. This study is one image-pixel focused continuation that does not repeat original previous VideoSham/MVTec/SADU experiments.

Selection, source provenance and controls: from the complete independently inventoried TempGlitch release, we selected **all potential original source pairs with both Platformer Buggy and Normal files sharing full scene family/index identity and combined file size <=70MB**, then used a fixed SHA256 ordering to select twelve of twenty-seven eligible source-scene pairs. This was frozen before downloading or decoding any video content. The size cap introduces a strong potential bias toward shorter/lower bitrate/compressible clips. Other author glitch filenames in the first twenty-one cases did not establish unambiguous same-environment pairing and were deliberately excluded rather than cross-matched by numeric suffix. These are genuine source author labels, **not new independent human adjudication** or natural playback stalls.

All five methods were fixed before examining video pixels: native-frame official FFmpeg `freezedetect=n=-50dB:d=0.6`, full-frame 5FPS grayscale low-change runs, center ROI low-change while outside moves, translationally registered center ROI low-change while outside moves, and local-versus-outer Farneback optical-flow mismatch. The center ROI was a generic central-person assumption, not an object detector; no annotated person location or engine pose target was given. Decoded each actual source video at native FPS for official FFmpeg; sampled five frames per second at 192 by 108 pixel grayscale for all other methods, CPU only, one thread, no Nitro RTX or Thor resources. The image-only outputs were frozen before the original author bug/normal labels were joined for scoring. Five binary detectors share the same twelve author-glitch/normal source pairs; missing decoding counts as **abstain**, not success.

The compact report [`perceptual-tempglitch-real-character-pose-video-control-2026-10-25.json`](perceptual-tempglitch-real-character-pose-video-control-2026-10-25.json) retains exact source-positive/negative counts, source-authored classification recall, false alarms, original-scene paired uncertainty, model-free thresholds, source SHA receipts, decoded sample counts, frame-rate/duration metadata and CPU runtime. The source scene is **a character's animation pose becoming frozen**, while camera, objects and background may continue moving and video frames are valid. Therefore detecting frozen **whole** image frames is the wrong observable: a no-freeze result from FFmpeg does not establish absence of original frozen-body animation. Center-crop image differencing and optical flow may also fail because pose can be stationary while the character translates and the camera moves; without actual person/rig tracking, a moving torso region does not prove animation quality. Similarly a true source normal video can intentionally display little motion. The source externally annotated which game code was intentionally changed, but no exact frame intervals or independent audience ratings are available. Consequently ROC AUC and author-label classification are distinct from human-objectionable temporal video quality, timing F1 and production render acceptance.

The appropriate immediately usable tier remains *authoritative source animation state and physical kinematic constraints where available*, plus original expected event timing, valid captured frame/audio stream alignment, object/pose tracking and independently rated playback inspection. FFmpeg only checks full-frame freezing; optical flow estimates changes in pixel movement, not action correctness or aesthetic continuity. A specialized video transformer/pose model could be researched next, but must be independently validated on original source-labelled physically consistent vs inconsistent movement and truly human-reviewed clean/defective production streams before automatic approval. Neither this limited source test nor prior VLM author tables qualifies a universal perceptual motion judge. Existing owner warehouse render/GPU remains unaffected.
