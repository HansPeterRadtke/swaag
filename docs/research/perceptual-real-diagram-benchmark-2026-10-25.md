# Real software architecture diagrams: independent visual-language judge evidence

**Research date:** 2026-10-25. **Project:** SWAAG visual perceptual research. **Question:** Can a GUI/diagram analyzer reliably decide whether actually rendered architectural/technical diagrams convey the correct entities, directions and connections? **Answer so far:** source-structured graph properties can be deterministically checked; general-purpose vision-language models are not reliable enough to be autonomous rendered-diagram acceptance judges. The accompanying pixel-only OCR experiment is reported separately below once completed. This does not change the previously verified Thor Qwen3-VL 8B 3/4 clipped-text failure, nor the negative industrial 3D and temporal-video results. This is independent source evidence, **not** newly issued calls to any frontier model.

## Independent public original material, not toy fixtures

Source: Shuyin Ouyang et al., [*Benchmarking and Evaluating VLMs for Software Architecture Diagram Understanding*](https://arxiv.org/abs/2604.04009), 2026, plus the paper's primary [SADU benchmark archive, Zenodo DOI 10.5281/zenodo.19339991](https://zenodo.org/records/19339991). Directly retrieved the **60,967,413-byte CC BY 4.0 source archive**, MD5 `e1d920fd43b36442427c8c36a2e7582e`, SHA256 `73b8c04cffc0411fbaeca8ed6f67f005df5a9568d46017fe2244ae5c85c3a717`; the unmodified ZIP remains under `/data/var/perceptual-independent-20261024/sadu-diagrams/` and is **not committed to Git**. No bundled Python or original-model code was executed; the archive's unrelated `personal_token` directory was **not accessed**. The verifier only read explicitly whitelisted `dataset/SAD` original images/JSON and `experiment_result/response_result/default` plus model-evaluation logs.

**154 real-world diagrams** were collected from original software/system architecture artifacts: **51 behavioral, 53 structural and 50 entity–relationship** diagrams, with one original real PNG, one manually annotated structured entity/relation/cluster graph and one author-generated QA reference per diagram. The source contains **1,842 annotated entity instances and 1,887 structured relations**, and **2,431 diagram questions** across 24 entity/count/relation/attribute tasks. All 154 archived reference QA files were checked against the responses' exact diagram identity, question text, structured reference answer and subtype. We re-scored the authors' **11 model runs**, each with exactly **2,431** archived predictions. No model was called and no Nitro/Thor/Jetson GPU was used.

**Important source identity issue:** the three Qwen2.5-VL response logs use index numbers in a different sequence: all **2,431 index positions** disagree with the source-canonical order, but the **complete set of 2,431 actual `(diagram category, diagram filename, question, answer, subtype)` records is identical**. Index-based matching would compare each model answer to a different question and produce a completely invalid leaderboard. The independent evaluator instead rejoined each prediction by the exact reference question identity, preserving its originally produced response and the accompanying LLM-judge opinion. The eight other model logs use source-canonical indices. The source and raw predictions were never rewritten.

## Actual archived model output: direct comparison to ground truth, not more model agreement

Scoring was preregistered in the reproduction script: parse the authors' expected `{"answer": ...}` JSON output, enforce exact numerical answers and case/Unicode/whitespace/underscore-normalized **entity-name set** equality, preserving source-to-target orientation of graph edge pairs. We do **not** use fuzzy semantic equivalence, external LLM scores as gold, or unstated synonyms to make results look better. Parsing/formatting failures count as product-level failures under the prompt contract and are separately reported as such; the source authors capped model output lengths (e.g. 512 tokens), so a malformed/truncated answer does **not necessarily indicate a failure to visually recognize the diagram**. For text retrieval, we separately report spurious predicted entities (false positives) and missing required entities (false negatives). For numeric quantities, count the direction of errors, including undercount versus overcount.

Source-drawing-grouped bootstrap intervals were computed using **2,000 resamples of the 154 original diagrams**, rather than treating 2,431 questions as independent. Overall strict accuracy 95% source-group intervals included **69.0–74.3%** for Gemini 3 Flash and **66.7–72.5%** for Gemini 2.5 Flash. A *paired* bootstrap difference using the exact same diagrams showed Gemini 3 ahead by **+2.10 percentage points**, with 95% descriptive interval **+0.17 to +4.12 points** under these particular strict source-JSON rules; this does **not** mean a modern served model of the same name ranks identically, nor does it prove general deployment reliability. There were **1,456** questions both answered correctly, **287** Gemini-3-only correct, **236** Gemini-2.5-only correct, and **452** both wrong. Qwen models' shuffled indices were not scored at face value.

**Do not select a diagram judge on aggregate QA accuracy alone.** The source task mix is heterogeneous, with frequent trivial zero answers. Of the **1,372 numeric questions**, **345** have a reference answer of zero, so always returning integer zero would already obtain **25.1%** accuracy on the numeric slice. Some models fail even that constant baseline. The strongest model, Gemini 3 Flash Preview, has **80.5% accuracy conditional on successful parsed structured output** but only **71.7% end-to-end**; many malformed outputs are truncated by the source generation budget. Its *task-balanced* unweighted macro average across 24 different QA task types is only **69.0%**, while Gemini 2.5 Flash reaches **70.9%** under that different criterion. For correctly retrieved named diagram elements, Gemini 3's source-entity micro precision is **89.3%** but its recall only **45.7%** (large omissions), while Gemini 2.5 Flash precision is **78.9%**, recall **73.6%** (more spurious entities but better completeness). This is an important precision/recall tradeoff for design specifications and cannot be reduced to one best model.

Further explicit failure evidence on Gemini 3: its actual accuracy is **63.0% for counting total relation connections**, **48.1% for the number of relation types**, **69.3% for relation sources and 64.7% for relation targets** in the corresponding question families, and only **50.0% for identifying which relation has a given label**. Attributes and method-retrieval questions often lead to truncated structured replies even when equivalent *numeric* questions are answered. A diagram that looks plausible may omit or reverse an important edge: a confident 70% question-answering model is unsuitable as the sole quality judge for actual system architecture.

Source author LLM-as-a-judge outcomes are preserved for comparison but **not taken as authoritative diagram truth**. In the highest-scoring model's **2,431** cases, the source LLM judge disagreed with the independent strict normalized exact parser **95 times**. Of the 1,372 numeric questions, only around three such disagreements involve unambiguous count differences; most mismatches concern text-list synonym normalization, output parsing or the source LLM judge's lenient semantic interpretation. Do not claim the LLM judge is always wrong or that strict set equality is a perfect semantic evaluation; both judgment paths have limits.

## Original-source prompt and thinking effort sensitivity (same real diagrams, not independent model runs)

The SADU archive also preserves response logs for several prompting variants and thinking settings on **the same original 2,431 QAs**. `tests/research/sadu_prompt_thinking_quality_replay_20261025.py` independently re-scored those already-generated answers with the same strict JSON-reference evaluator, without initiating any new model call. On Gemini 3 Flash Preview with full task instructions, archived *default* achieved **71.70%**, *low thinking* **71.95%** and *high thinking* **71.04%** end-to-end exact. Low thinking versus default was **+0.25 percentage points**, with diagram-grouped 95% interval **−1.44 to +1.85 points**; there is **no demonstrated overall accuracy improvement**. It did change the subtype tradeoff: numerical questions became worse (**69.24%** versus **75.87%** default), while relation questions improved (**81.51%** versus **74.07%** default) under those specific archived responses. Low thinking also had **46** malformed/wrong-type JSON replies versus **265** for default and **270** for high. These are output-format and reasoning conditions combined, **not proof that a thinking switch independently changes physical visual perception**. Source mean total-token usage was **1,667** for low versus **1,918** for default/high, not actual latency on Nitro or a price estimate.

For Gemini 2.5 Flash, keeping the complete instructions gave **69.60%** strict source-question accuracy. Removing the task definitions reduced it to **61.83%** (**−7.77 points**, diagram-cluster interval roughly **−9.42 to −6.18**). Removing the output rules alone gave **69.07%**, within uncertainty of full instructions. This experiment confirms that parser/prompt semantics can materially affect delivered diagrams' QA reliability: do not use one generic model score as a fixed property of the checkpoint.

**Methodological trap explicitly excluded from model rankings:** the *question-only* variants were asked in natural language **without requiring JSON**, and appropriately responded with prose such as explanations and named entities. A scorer that requires `{"answer": ...}` therefore assigns those outputs a meaningless **0% strict JSON compliance**, not **0% diagram comprehension**. The raw source comparison records these literal zero parse results for provenance, while the published compact analysis *omits them from strict-quality rankings* and flags them as non-comparable prompt contracts. A separate human or source-grounded natural-language grader would be needed before comparing their semantic correctness.

## Verify the ground-truth counting oracle itself

The source provides *manually structured graph JSON* and *derived* QA. A separate read-only implementation recomputed six defined graph properties on **each of the 154 original graphs**, independent of the authors' QA/model evaluation programs: number of entities, relations, clusters, entities not included in a cluster, nonempty-labeled relations, and clusters with nested subclusters. All **924 source graph property checks agreed exactly** with the original answer references. The original source diagram and graph files' SHA-256 checksums are preserved in `/data/var/perceptual-independent-20261024/sadu-diagrams/sadu_154_independent_source_graph_QA_audit_20261025.json`, generated by `tests/research/sadu_154_graph_source_oracle_audit.py`.

This confirms **internal numeric source-label consistency**, not visual correspondence of every drawn arrow or label. A human can annotate the wrong graph, a diagram PNG can omit some labels, and a source graph might not represent the actual designer's specification. Source truth still needs visible-pixel verification and task-specific defects. Checking code/source answers does not replace testing real rendered output.

## Real pixel-only text recognition — separate complementary role

`tests/research/sadu_154_real_diagram_ocr.py` applies the predeclared CPU-only Tesseract 5.3.4 sparse text PSM 11 to the entire original 154 real diagram PNGs (longest side capped at 4096 px, 16-second per-image timeout), freezes OCR words *before* reading independent graph entity names, and checks **strict full-label coverage** as well as optimistic individual word coverage. The graph JSON contains **1,842 entity instances**; entity names can occur more than once and the comparator deliberately deduplicates names within each diagram. Source label recall measures one actual visual subtask, not arrow/connection correctness; OCR precision **cannot** be honestly calculated from an entity-only reference because the figures also contain true relation/legend annotations. Do not treat extra unrecognized/unlisted tokens as false-positive diagram elements.

**Completed local pixel-only result:** all **154 original diagrams** were successfully evaluated, with no timeouts. The human graph source contained **1,842 entity instances but only 1,733 distinct nonempty normalized entity-name labels within diagrams** after deduplication; Tesseract recovered an exact normalized phrase for **820 of 1,733**, or **47.32% recall**. Under an optimistic *individual expected reference word* test, coverage was **64.87%**; this is an upper bound on finding each full entity name, not a source-validated precision score. **59 of 154** diagrams had all independently listed entity labels found. Actual measured Tesseract image OCR subprocess time was **515.49 elapsed seconds**, running with one low-priority CPU worker for all 154, about **3.35 seconds per diagram** on busy Nitro; long image sides were capped at **4,096 pixels**, which may contribute to small-text failures. All original diagram PNGs and graph annotations remained unchanged.

| Real SADU original diagram class | Diagrams | Ground-truth distinct entity labels | Exactly found by OCR | Exact recall | Diagrams with all expected labels recovered |
|---|---:|---:|---:|---:|---:|
| Entity–relationship (ER) | 50 | 379 | 348 | **91.8%** | 37 |
| Behavioral/workflow | 51 | 515 | 209 | **40.6%** | 1 |
| Structural architecture | 53 | 839 | 263 | **31.3%** | 21 |
| **Overall** | **154** | **1,733** | **820** | **47.3%** | **59** |

This severe category dependence is a substantive tool-selection observation. Even before edge direction and diagram meaning, conventional Tesseract only reliably recovered most entity labels from the relatively regular ER diagrams; the dense and multi-style architecture and behavioral drawings were much less recoverable. The structural category's high 21/53 entire-diagram success is due to heterogeneity in image size and graph content, not proof it handles dense drawings consistently. Do not infer that every missed label was invisible to a human or that exact source-name equality is a perfect text ground truth. Additional legitimately drawn captions/relations make an OCR false-positive rate unidentifiable without a complete visible-text annotation reference. **This does not qualify an automatic screenshot or diagram acceptance gate.**


## Evidence-supported tool selection, and still-open owner requirements

For **source-backed generated diagrams**, validate that the graph specification has the intended node inventory, directed edges, relation names/types and axis/data constraints before rendering, then inspect the actual raster for expected labels and connectors and explicitly require human confirmation of ambiguous occlusion/overlap. A model can assist by proposing bounding boxes or answering questions, but model consensus and correct-looking descriptions do **not** guarantee structurally correct output. For **images without trusted source graph**, the task is qualitatively harder: robust OCR, link/arrow/region grounding and independent human reference are needed. Independent research such as [DRAGON](https://coral-lab-asu.github.io/DRAGON/) provides manually verified evidence boxes for diagram reasoning, while [SciFlow-Bench](https://aclanthology.org/2026.acl-long.807/) proposes graph round-trip evaluation of diagrams rendered from scientific specifications. Their published methods are relevant research candidates, not locally verified winning models.

The broader original question remains unresolved for physical industrial 3D and naturally occurring moving-video defects. Earlier **119 heldout GLB** results showed fixed source bounding-box overlap found only **9 of 33** human-labeled missing components with **20 false flags** among 86 negatives; mesh watertightness and generic 2D/3D overlap are not semantic part completeness. A simple video optical-flow score had apparently strong preferences but native frame rate explained **all 18 human preferences** in the sampled generator comparisons. On 24 genuinely human-time-annotated Spotlight clips, a warp-residual signal found only **5 of 9** motion-labeled clips, and the apparent nine of eleven peak-localization hits were close to a random-time baseline. A separate previously blocked 72-video run retrieval remains denied and was never retried. **No** actual deployed model/ensemble has passed a high-specificity, low-false-negative heldout gate for all requested GUI/diagram/3D/video media. A hybrid of browser `axe-core`/computed geometry, expected text OCR, authoritative graph/CAD physics, video timestamps/references and human evidence remains the defensible engineering path pending independent model-specific validation.
