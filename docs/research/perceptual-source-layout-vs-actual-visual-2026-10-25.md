# Perceptual analyzer research: source geometry against actual human-reviewed visual flaws

**Continuation:** 25 October 2026, SWAAG original owner testing/GUI/media-recording research. **Status: PARTIAL.** This is a new independent source-metadata versus real-rendered-image evaluation, following the previously published SlideAudit OCR/OpenCV and actual zero-shot CLIP ViT-B/32 tests. It does **not** finish the original requirement to qualify a trustworthy all-domain judge for real desktop/mobile GUIs, technical 3D machinery, scientific diagrams and moving videos. The source-linked aggregate and exact false positives/negatives are in `perceptual-real-source-layout-human-visual-2026-10-25.json`; original slide images, descriptions, human boxes, model weights and per-case raw data remain under `/data/var/perceptual-independent-20261024`, never committed in SWAAG Git.

## Owner's unresolved engineering hypothesis

The original owner testing recording of 23 September explicitly asks whether a GUI's **actual rendered geometry** can be checked by deterministic layout analyzers, and whether a tested specialized vision model is needed to catch content that ordinary programmatic coordinates miss. The applicable Infra `docs/guidlines/testing.md` and `gui/recipes/tests_and_verification.md` require a task-specific verified analyzer registry, independent expected outputs and honest false positives and false negatives. The earlier real-site baseline showed source-informed DOM clipping can be useful when the exact text and target are known; the previous human-reviewed SlideAudit study found OCR border and zero-shot CLIP error signals only partially useful on *actual pixels*. The new hypothesis here was to use an actual author-provided **structured layout-object description** from those *same* source slides, not a toy rectangle fixture, and compare it against independent released human visible flaws.

This is particularly relevant when a screenshot alone cannot reveal a completely hidden object, while source layout knows it exists. However, authoritative source coordinates and final rendered raster coordinates can disagree, authors can intentionally overlay objects, and a clipped text run can be cut off **inside** an otherwise entirely onscreen text container. These are concrete failure modes to measure, rather than assuming programmatic coordinates are automatically equivalent to perception.

## Original data and fixed rules, with independent labels hidden until prediction

Source: [SlideAudit (UIST 2025)](https://github.com/zhuohaouw/SlideAudit), GitHub revision `642d490b7c1d2e78a50a631bfd359433397f3ecf`, original [CC BY 4.0 license](https://creativecommons.org/licenses/by/4.0/), **2,400** published rendered slides, source descriptions, 19 visual-design flaw categories and three human raters per slide. The previously locked selection of **343 distinct raster slides** was retained; it has **all 82 strongly labeled overflowing/cut-off positives** matched to 82 category-specific strongly negative controls, **105 occlusion positives** matched to 105 controls, and **20 low-contrast positives** matched to 20 controls. Controls share `source_type` and augmentation/alteration type with each positive, but are *not* verified perfect on every unrelated flaw. Source material includes original and deliberately altered presentation slides, **not live application GUIs**.

The pinned upstream source-descriptions directory was accessed in a separate, external sparse Git checkout in `/data/var`, without modifying the 343 original images or any SWAAG production checkout. All **343** descriptions were matched by exact stable slide identity before any label comparison. The raw descriptions contain text, image, table and line object boxes in *normalized* coordinates, mostly text boxes and images. Across the selected slides the parser found **1,684 valid positive-area original object rectangles**, and forty-seven slides had at least one rectangle extending outside the slide by any amount. Most objects are inside canvas, and many overlap others. Input geometry was frozen *without reading any human annotations or pixel detector outcomes* in `slideaudit_343_source_geometry_frozen_20261025.json`.

Fixed predeclared source-only rules: flag cut-off if **any text box is more than 2% of its own area outside the physical slide**, and flag occlusion if **any two positive-area authored element bounding rectangles overlap over 10% of the smaller rectangle**. Continuous counterparts are the maximum text-outside-area fraction and maximum relative object intersection, both independent of human labels. Both thresholds were set in the source-analysis script *before scoring*. The original image-only comparator is the earlier frozen Tesseract+OpenCV OCR-word proximity to the outer raster boundary for cut-off, and text-word-box intersection for occlusion, using exactly the same locked images, original human labels and prior pixel-only predictions. The local pretrained CLIP model is included only as a previously verified comparator, not re-inferred or tuned. Missing/nonpositive source geometry is explicitly not silently recoded as a found visual defect.

## Correct source interpretation is property-specific, not universally better

| Actual human-reviewed visual task | Method | True human defects found | False flags on matched category controls | Recall | Specificity | Continuous signal ROC AUC |
|---|---|---:|---:|---:|---:|---:|
| Cut-off/overflow (82 + 82) | Source text box off-canvas | **9/82** | **7/82** | 11.0% | 91.5% | **0.561** |
| Cut-off/overflow (82 + 82) | Actual pixel OCR word near border | 58/82 | 26/82 | 70.7% | 68.3% | 0.723 |
| Cut-off/overflow (82 + 82) | Actual CLIP ViT-B/32 zero-shot prompts | 52/82 | 62/82 | 63.4% | 24.4% | 0.438 |
| Occluded content (105 + 105) | Source any object rectangle overlap | **93/105** | **33/105** | **88.6%** | 68.6% | **0.771** |
| Occluded content (105 + 105) | Actual pixel OCR word rectangle overlap | 24/105 | 12/105 | 22.9% | 88.6% | 0.558 |
| Occluded content (105 + 105) | Actual CLIP ViT-B/32 zero-shot prompts | 74/105 | 78/105 | 70.5% | 25.7% | 0.480 |

For **clipping**, the source-coordinate rule has extremely poor recall because text may disappear inside a container that still lies on the slide, or because the source geometry and final modified image no longer coincide. On the same human cases, the OCR-border **continuous** score exceeds the source text-outside score by about **0.162 AUROC**, with matched-pair bootstrap 95% descriptive difference (source minus pixels) **−0.277 to −0.050**. Source geometry can prove the explicit property "authored text object extends outside slide canvas," but that is **not** equivalent to the owner's broader intended "any actually unreadable or cut-off UI text".

For **occlusion**, source geometry is clearly the better *task-specific evidence feature*. Max source object intersection is associated with annotated occlusion much more strongly than OCR word overlap (ROC AUC **0.771 vs 0.558**, paired-source bootstrap difference **+0.131 to +0.297**). The source overlap-area aggregate, one of the other **predeclared** source features, scores AUROC **0.811** on this *already consumed benchmark*; it should **not** be promoted post-hoc as a separately validated better rule without fresh source-family holdout. This task distinction is important: when rendered text is truly occluded, OCR may not recover a box at all, whereas source rectangles preserve a potential occluding object. But source rectangles cannot tell whether the overlap is intended, whether foreground/background alpha permits visibility or whether two boxes only share empty padding.

A source-geometry overlap indicator has **33 false alarms among 105 controls** under strong human category-specific labels. That is far too frequent for automatic GUI rejection even on this enriched balanced sample. The vision model's high false alarms are worse; the result supports a source-aware geometric *triage* system, not automatic visual-quality certification. Source geometry is also **not a meaningful independent judge of text/background contrast**. The same fixed geometric overlap produces ten flags on twenty contrast positives and five on twenty category controls, but no color/luminance/glyph/background property was measured. That coincidence must not be relabeled a successful contrast analyzer.

## Do source-rectangle overlaps localize the actual human-visible occlusion?

The original positive occlusion slides include **104 cases with human-drawn affected-region rectangles** and one without. Before reading those human regions, we computed all source-object rectangle intersections covering over ten percent of the smaller box, sorted them by overlap fraction and kept **at most three** predicted intersection centers per slide. The original predictor output was frozen with the exact **343 original slide IDs and source-description SHA-256 receipts**. An initial attempt had a coding error where an inner loop variable replaced the slide ID and saved only 27 incomplete proposal records; that invalid intermediate file was **preserved separately and never scored**, the loop was corrected, and the complete source identity coverage was asserted before evaluation. Do not count that partial run as an independent result.

Of the 104 human-positive slides with an annotated region, **92** had at least one source-overlap proposal, and **85** had a top-three proposal center inside one of the human-drawn boxes. This is **81.7% of all 104** and **92.4% of the 92 slides with source proposals**. Such simple region-center overlap can be misleading because the human rectangles cover substantial canvas area: the average fixed-grid estimate was around **35% of the slide**. We therefore compared against **10,000 independent sets of uniform random points using exactly the same number of proposals per slide**, and scored whether **any** point landed in the **same** human boxes. Random placement produced **44.0 hits on average**, with its central 95% simulation range **36–52**, compared with the observed **85**. None of the ten thousand random-placement trials attained 85, giving an empirical one-sided bound **below 0.0001** under this *specific uniform spatial null*. Original slide bootstrap on observed-minus-per-case-random expected localization gave a positive **32.5–46.1 percentage-point** descriptive interval. The improvement was visible within all three original slide-source groups, not only one source family.

This **supports genuine spatial alignment** of source metadata intersections and human-marked occluded regions, above the deliberately conservative uniform-location chance comparator. It does **not** establish a geometric element-level bounding-box AP, object visibility, layering correctness or a reliable binary detector for whether that overlap is unwanted. The matched negative classification false alarms still matter. The human regions themselves may contain deliberately altered content or broad problem areas, and the source metadata may partially encode the augmentation responsible for the visual defect. This is exploratory evidence on a previously used sample, not a new untouched holdout.

## Combining real pixels and source geometry: more calls do not automatically improve quality

To test a simple complementary decision rule, we applied source geometry **OR** pixel OCR (sensitive to either concern) and source geometry **AND** OCR (must both agree), using the previously frozen outputs on exactly the same original reviewed slides. No threshold fitting or new image inference was performed. All performance columns retain false alarms, and no policy was automatically selected by comparing development outcomes:

| Human flaw | Fixed combined rule | Human defects found | False control flags | Recall | Specificity | Balanced accuracy |
|---|---|---:|---:|---:|---:|---:|
| Overflow/cut-off (82 per class) | Source **OR** image | 62 | 32 | 75.6% | 61.0% | 68.3% |
| Overflow/cut-off | Source **AND** image | 5 | 1 | 6.1% | 98.8% | 52.4% |
| Occlusion (105 per class) | Source **OR** image | 96 | 40 | 91.4% | 61.9% | 76.7% |
| Occlusion | Source **AND** image | 21 | 5 | 20.0% | 95.2% | 57.6% |

For overflow, OCR alone had balanced accuracy **69.5%**, slightly *better* than OR (**68.3%**) because the four additional detected defects cost six extra false alerts. For occlusion, source geometry alone had balanced accuracy **78.6%**, compared with **76.7%** for OR: adding OCR found only three extra defect cases while adding seven false alerts. AND is more selective but misses most true defects. These are **not universal principles against combining analyzers**: they are observed tradeoffs from one already-consumed SlideAudit source under two simplistic combination policies. The right implementation should use each analyzer only for the properties it is actually calibrated to measure, with explicit abstention and source/pixel mismatch reporting.

## Additional candidate research for genuine temporal video defects, not a verified video judge

Inspected the original [GeneVA human generative-video-artifact dataset, WACV 2026](https://www.immersivecomputinglab.org/publication/geneva/) hosted on the authors' public S3 storage, as a complementary alternative to the earlier twenty-four-video Spotlight experiment. The **112.7-megabyte source annotation JSON** was read into memory and summarized without persisting annotator account IDs or user-entered free-text artifact descriptions. The public source describes **16,356 videos** across Sora, VideoCrafter2 and Pika; the accessible annotation snapshot contained **16,361 annotation rows, 16,351 distinct completed clip IDs**, and approximately **487 thousand per-frame annotation entries**. Many of those are correlated/possibly interpolated bounding-box records, not independent human confirmations. The source annotates motion, physics, appearance/geometry and visual artifacts, with multi-label categories. It generally has **one annotator per video**. A few source video objects were verified accessible by read-only HTTP metadata requests, but **no new video quality model was executed**, no video clips from this source were scored, and no original third-party video files or annotation text were written to SWAAG.

This is a promising source for a future supervised *generated-video artifact region* benchmark. It does **not** provide the still-missing production-ready truth for **naturally occurring captured playback frame drops, freezes or judder compared against genuinely clean matched-FPS controls**. Broad motion/physics labels and empty regions cannot be silently converted into verified "bad versus perfect" stutter classes. The previously blocked seventy-two-video Spotlight result retrieval and warehouse source-resolution tail-frame retrieval remain denied and were not retried or rerouted. Neither qualifies a video-language judge on the owner's warehouse videos.

## Final task-specific analyzer decision

**Measure what is measurable.** When the source system is authoritative, browser `client/scroll` dimensions, clipping ancestors, accessibility trees, real `axe-core` contrast/ARIA checks, or source geometry/contact/graph physics constraints are better foundations than a vision model's confident prose. However, validate that those *sources* refer to the actual final render and distinguish intended overlaps. For screenshot-only GUI flaws, a tested OCR or specialized UI parser can provide candidate text/regions, but does not automatically know the design intent. Zero-shot CLIP ViT-B/32 on the same human-reviewed slides had ROC AUC **below 0.5** for all three visual error prompts, and previously ScreenParser source-target box matching was only **11/32 at IoU 0.5**, not sufficient for defect acceptance. For original architectural diagrams, deterministic source graph counts were consistent but source-label OCR recalled **820 of 1,733** distinct intended labels, and the best of eleven tested archived VLMs answered only around **72%** of the original human-source structural questions exactly. For generated technical 3D objects, 119 untouched source GLBs confirmed that mesh validity and box overlap fail human semantic missing-component judgments; real CAD identity/geometry/kinematic/occlusion truth is still missing. For moving video, preserve PTS, frames, approved source timeline and true human fault interval references, with neither the source labels nor physics reasoning extrapolated beyond their verified scope.

**Remaining unresolved owner requests:** independently adjudicated visible application GUI clipping/overlap/low-contrast heldouts beyond presentation slides; exact *industrial* CAD part completeness, rendering photorealism, physically impossible assembly motion and collisions on known-good known-bad source scenes; genuinely occurring time-coded video freeze/stutter/tearing with clean controls, on-production-hardware specialized video VLM testing and measured false alarms/misses. These require separate original-source research and/or free hardware slots; no universal quality judge can be declared complete. All experiments in this continuation were CPU/source reasoning only, in the existing isolated SWAAG research worktree, while rendering/voice/trading/other agents and GPU services remained active. Input records, original raw data and prior negative findings remain preserved; only verified source-linked code and compact aggregate research should be committed and pushed. **Objective state: PARTIAL.**
