# Real temporal video glitch QA: verified primary-model failure and full-release source shortcut audit

**25 October 2026. Research verdict: PARTIAL; no qualified autonomous video QA model.** This is a substantive incremental original-source study for the owner's September testing recording and SWAAG visual analyzer research. It does not repeat the already verified source-video edits, GUI/slide, diagram or warehouse mechanical experiments. We inspected the May 2026 primary paper [TempGlitch: Evaluating Vision-Language Models for Temporal Glitch Detection in Gameplay Videos](https://arxiv.org/html/2605.21443), its linked [MIT Hugging Face original dataset](https://huggingface.co/datasets/asgaardlab/TempGlitch), and reanalyzed **all 1,500 original release video file metadata entries**, plus **all twelve original published VLM confusion matrices** across **twenty-two model/input configurations**. The author's actual model calls were **not** repeated on Nitro, Thor or a paid API. Entire source video release about 60.3 GB was deliberately not downloaded because production GPU/CPU/network processes were active. Source HTML SHA256 and 1,500-file name-size manifests remain under isolated `/data/var/perceptual-independent-20261024/tempglitch-control-20261025`; only code and compact aggregated source-derived evidence are in Git.

## What is actually grounded by independent source and what is not

The benchmark consists of **750 buggy and 750 category-matched normal** real rendered gameplay recordings from two controlled Godot demo environments, divided equally into **blinking/flicker, incorrect shooting, velocity/teleportation, frozen character animation and stuck-in-place motion**. The bugs were deliberately injected by the dataset authors (and one existing shooting behavior), generally during a middle portion of the clip; the original normal pair is a similar gameplay situation and is *not necessarily a pixel-aligned alternate render of the same exact source events*. No blind independent human defect acceptance votes were provided for the full 1,500 clips. Notably, *frozen animation means the **character's pose** remains frozen while video/camera/world may continue moving*; it is not the same as a full-screen playback freeze measurable by FFmpeg `freezedetect`. The original paper evaluates **six proprietary and six open-weight VLMs**, open weights using **four NVIDIA L40S GPUs**, Gemini with native video input and other models with up to 50 sampled frames at one or five FPS, using a prompt requesting a JSON defect verdict. The authors retry malformed output until a valid JSON, so pure end-to-end format/latency reliability was not measured by the published accuracy.

The published source [main Table 3 and Appendix E confusion matrices](https://arxiv.org/html/2605.21443) contain exact true positives, false positives, false negatives and true negatives for every evaluated model. We independently parsed the actual arXiv HTML, recomputed accuracy, precision, recall and F1 from every original confusion row, validated all 22 reported source metric rows against the authors' table to within 0.11 percentage points, and checked exact checkpoint IDs against paper Appendix A. The primary table below is **author-run VLM inference**, not a local experiment, on **750 positives and 750 negatives** for each model configuration.

| Exact author model/run | Input | True glitches detected | Missed glitches | Clean videos falsely flagged | Correctly accepted clean | Overall accuracy | Clean false-alarm rate |
|---|---|---:|---:|---:|---:|---:|---:|
| Gemini 3 Flash | native raw video | 654 | 96 | 650 | 100 | 50.3% | 86.7% |
| GPT 5.4 Mini | sampled 5fps | 173 | 577 | 112 | 638 | 54.1% | 14.9% |
| Qwen3.6 27B | sampled 5fps | 409 | 341 | 402 | 348 | 50.5% | 53.6% |
| Qwen3VL 8B | sampled 1fps | 18 | 732 | 8 | 742 | 50.7% | 1.1% |
| Qwen3VL 8B | sampled 5fps | 2 | 748 | 0 | 750 | 50.1% | 0.0% |
| Gemma4 31B | sampled 5fps | 326 | 424 | 281 | 469 | 53.0% | 37.5% |
| GPT 5.5 | sampled 5fps | 32 | 718 | 15 | 735 | 51.1% | 2.0% |

The strongest original accuracy was only **54.1%** for GPT-5.4 Mini using five sampled frames per second, with 577 missed glitches and 112 false alarms on 750 clean clips. Qwen3-VL 8B at five FPS reported **two of 750 detected and 748 missed**, zero clean false alarms: apparently perfect precision is a consequence of almost never predicting positive. By contrast, Gemini 3 Flash with native video accepted only 100 of 750 clean clips, flagging **650 false alerts** while finding 654 positives. Qwen3.6 27B is more balanced but around 50.5% overall accuracy. On this balanced benchmark, a trivial model that always says **glitch** has 50% accuracy and **66.7% F1**, so F1 alone can actively mislead deployment decisions. The reported Qwen3-VL checkpoint is `Qwen3-VL-8B-Instruct-unsloth-bnb-4bit` and is **not a new test of the owner's existing Thor deployment**; Qwen3.6 27B also must not be conflated with Qwen3.8 27B workers.

## Independent full-release metadata-only negative control: 1,500 cases

The public original release lists every encoded `.mp4` source size even when the actual footage is not downloaded. We independently retrieved the authoritative source list from all five category directories, verified **150 clean and 150 buggy originals in each**, and corrected an easily missed identity issue: the Stuck in Place category has 75 Platformer source IDs and 75 TPS source IDs, reusing numbers one through seventy-five. Pairing by number without the original engine would be scientifically invalid. No data or original source media were modified. The complete source hash receipt is retained outside Git.

We then froze a simple deliberately **nonvisual** classification procedure: per-category/per-engine interactions with logarithm of MP4 byte size, L2 logistic regularization with fixed parameters and category-paired IDs assigned to train versus evaluation by deterministic SHA256. The model trained on **1,180** source files and evaluated on **320** previously withheld source files (160 source buggy, 160 source normal). The test produced **87 true positives, 73 misses, 66 false clean-video accusations and 94 correct clean results**, **56.6% balanced accuracy**, and **0.599 ROC AUC**. A 2,500-resample source-pair bootstrap gives descriptive 95% ROC interval **0.547–0.653** and balanced accuracy **0.519–0.613**. This does not establish model capability—**not a single video pixel was inspected**—but shows a measurable dataset-construction signal that should be included as a trivial control in future development benchmarks. The comparison is *not statistically head-to-head* against the 1,500-case published VLM leaderboard because the held-out sample and features differ.

File-size asymmetry varies by category. For **Frozen Animation**, original buggy median file size was about **36.5 MiB** versus **48.1 MiB** for the source clean category; size-only category-heldout ROC AUC was **0.724** over 48 reserved clips (24 per class). Other categories had different directions or weaker correlations. File bytes can reflect video duration, codec/bitrate, camera style or visual complexity; without separately accounting for these, a claimed new model improvement might actually be exploiting a source shortcut. The VLM paper fed videos or sampled frames, **not the exact encoded file-size feature**, so this source signal is **not evidence** that any evaluated VLM used it. The 320-file test comes from the same controlled two engine scenes, not unseen commercial production footage.

## Which real tool combination follows from these numbers?

The source-wide results independently support the original owner conclusion, with new concrete error rates. A release inspector should first enforce **documented source correctness** when available: strict frame timestamp order and duration, approved cuts/fades/holds, exact source video identity and audio synchronization. For computer-generated 3D game/video, use engine object state, position/velocity/pose and intended action constraints for genuine physical failures. Image-based OCR/CV, pHash, optical flow and FFmpeg freeze detection are task-specific evidence collectors, not reliable intent/physics/quality approval judges. A VLM can produce a candidate explanation for uncertain video segments but cannot override exact reference/physics checks or author-approved events without independent calibration. An intact 30-FPS presentation timeline does not itself prove continuous perceived motion. A character frozen in pose may occur while every full-screen frame changes, so no-reference video-level freezing algorithms can fail for structural reasons.

**Open decisive source gap:** a previously unused class of real production and game footage, independently human-reviewed as clean/defective with precise bad-frame intervals, paired with the same source, camera/FPS/codec settings and expected object behavior; evaluate specific deterministic source, object tracker and modern VLM choices for miss/false-alarm rate, event localization and resource cost. TempGlitch's 750/750 controlled source is useful, but self-authored in-engine labels and two demo engines are not a generalized industrial, live-stream playback or human-objectionable acceptance corpus. The former denied video result retrievals remain denied and were not retried, and no calendar events or production GPUs were used. **Overall objective PARTIAL.**
