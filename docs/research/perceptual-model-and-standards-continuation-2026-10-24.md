No validated general human-quality or physical-correctness acceptance system has emerged.

## Independently tested production-grade accessibility engine: axe-core 4.14.0

Downloaded the official pinned JavaScript `axe-core@4.14.0`, original bundle SHA-256 `20c09fe157a8a34a30e241aaa1fcdade657734f08ab379ecfbeb7d45cc46e87823e04` from unpkg into isolated `/data/var/perceptual-independent-20261024/w3c_act_contrast/`; version sourced from the W3C ACT implementation matrix. Unlike the previous handwritten CSS approximator, this is the actual deployed mainstream accessibility checker, run in isolated Firefox 146 headless. The official independently authored **W3C ACT rule afw4f7** on minimum contrast provided **34** original HTML cases: twelve expected passed, eleven failed, eleven inapplicable. Source reference: <https://www.w3.org/WAI/standards-guidelines/act/rules/afw4f7/>; official implementation report <https://www.w3.org/WAI/standards-guidelines/act/implementations/axe-core/>. W3C notes that a passed atomic rule alone is not universal WCAG conformance.

Exactly **two cases containing page-authored JavaScript were excluded** from execution rather than executing untrusted scripts or changing their HTML and claiming unchanged truth; external network requests were blocked in the isolated Firefox profile. Axe's `color-contrast` rule was called once per static test page; no original page content was rewritten and all outcomes were saved before comparing to gold. Among the **32 executed** cases: **seven** expected failures correctly reported as failed, **seven** passes correctly passed, **nine** inapplicables correctly inapplicable, **eight** returned *cannot tell*, and **one** expected pass reported inapplicable. There were **no false explicit contrast violations** among the determinate outputs, but one mistaken applicability classification and meaningful abstention are not success. Original full-matrix counts including the two excluded source-script cases: `passed→passed 7`, `failed→failed 7`, `inapplicable→inapplicable 9`, `passed→inapplicable 1`, `passed→cannot tell 4`, `failed→cannot tell 4`, `inapplicable→cannot tell 2`. Note the excluded cases are within the cannot-tell counts. Average observed execution was about **one second per case**, total **33 seconds** on loaded Nitro; no model or GPU needed. All source HTML and measurements remain outside Git; reproducible script `tests/research/w3c_act_axe_reference_eval.py` preserves exact results and will not replay completed actions.

The W3C's source documents that even the recognized axe-core implementation cannot decide seven of its 32 reviewed normative examples in its published compatibility assessment and lists text/background image, text shadow and browser rendering as boundary cases. **Selected role:** axe-core for accessible DOM-backed web pages as one **defect-evidence** signal, not all layout/overlap/caption/image/video quality and not blanket conformance. Real-product screenshots and intended text still require independent verification. It is more credible than the earlier handmade checker, which on the 34 cases detected only five intended failures, correctly passed six, wrongly failed one, had eleven pass/fail abstentions plus four inapplicability errors. Do not compare raw percentage accuracy without preserving class coverage and abstentions.

## Locally installed actual ScreenVLM 316M parser, not a defect judge

Official source: `docling-project/ScreenVLM`, revision pinned to `78df0cc8498bbea1a03eb2816056fc0a76d2f63d`, Apache-2.0 (model weights ~746MB, downloaded and SHA verified in isolated `/data/var/perceptual-independent-20261024/models/ScreenVLM/`). Author model card <https://huggingface.co/docling-project/ScreenVLM> and primary ScreenParse ICML 2026 paper <https://proceedings.mlr.press/v306/gurbuz26a.html>. It is an Idefics3-based 316M-parameter **web screen-element parser** that emits `ScreenTag` element classes and location tokens in a normalized 0–500 coordinate grid. It is trained on full rendered webpages, not on classifying layout as defective. The original paper reports 0.592 PageIoU vs 0.294 for a vanilla larger VLM on its own parser benchmark; the published 2026 `main` release uses a newer **v2** dataset so original paper numbers must not be reassigned to that newer checkpoint without evaluating it.

Installed `transformers 4.55.2` in a project-isolated Python interpreter and reused the existing PyTorch 2.5.1 library through a `.pth` path, leaving the shared production Python environment unmodified. Ran **only CPU**, one torch thread and `nice +18`, never touching Nitro GPU or the active user-facing Coder/Thor services. The test consists of two archived real website pairs, each clipped versus independently labeled clean, with Firefox captured target regions actually visible; the model receives only the rendered RGB crop plus the official generic task instruction, **not the real site's expected text or its clean/clipped label**. Source content ground truth and original page positions are kept outside model context. Generation uses max 384 output tokens and a fixed greedy method. This is a *screen parsing feasibility check*, not a clipping classification or a statistically valid parser benchmark. The run completed all **four** real-site cases (two independently labeled clipped, two paired clean). The output had **zero of four** complete expected source labels; the first clipped image was reduced to a single full-crop `<Image>` bounding box, its clean counterpart to a single `<Link>` box, and the second pair emitted many repetitive `<Link>` boxes without the known visible label. On the second pair the 384-token limit was reached without a closing `</screentag>`. Two of four outputs had syntactically closed ScreenTags. Elapsed **1,091.82 CPU seconds** total, **273.0 seconds per screenshot on average**, and approximately **2.93 GB peak RSS** in the overloaded single-thread Nitro environment. **This is a failed text/element parsing result for four tightly cropped real-site screenshot targets, not a defect classification or a fair general full-page model leaderboard.** The model's general capability may differ materially on uncropped screens or a stronger GPU; those were not tested because Nitro production workloads had priority. Correctness details, raw predicted ScreenTags, model revision and per-case seconds are preserved outside Git in `/data/var/perceptual-independent-20261024/visible-ui-real/screenvlm_v2_first_run.json`.

**Interpretation:** small local element crops are **outside this model's recommended full-webpage use case**; a failure here does not prove ScreenVLM inaccurate on ordinary full pages or explain the cause. Model-extracted bounding boxes and labels are only a candidate input to independent layout logic, not automatically evidence of clipping. The exact completed local outcomes and latency are recorded in the compact `perceptual-source-calibrated-evidence-2026-10-24.json`; that script rechecks raw inputs before publishing scores. No pending request is counted as completed.

## New independent 3D analysis — published model outputs checked against actual humans

**Strongest directly relevant public data:** `3D-DefectBench`, Zhao et al. 2026 <https://arxiv.org/abs/2607.10826>. This is explicitly about automatically judging **human-detected defects in rendered textured 3D meshes** (missing parts, fused structures, bad geometry, placement, extra fragments, incorrect surface/texture/prompt adherence). The paper evaluated 84 combinations of vision-model, camera view, visual channels and prompt configurations across 3.2M defect decisions, and reports that a compact six-view RGB configuration can rival denser or depth-augmented schemes while no tested judge matches trained expert human agreement. It is *not* a CAD tolerance certifier or engineering-physics benchmark. Authors provide public 1,000-asset metadata, human labels and VLM predictions. We obtained the latest pinned `aieval2026/3d-defectbench` release (commit `94a1ce5b7fe4b46e0388b2593d4a6f3cd3421b77`), stored original third-party data and SHA-256 outside Git, and **independently recomputed** defect confusion rather than copying leaderboard scores. This is a new source-based statistical analysis of authentic authors' image-based model inference, **not fresh Nitro inference by those commercial models**.

Five available models had exactly **998 common human silver-majority source assets × nine defect categories** under the same source-recorded binary, eight-view, split geometry/RGB texture, seed-one evaluation configuration, with no duplicate source/defect entries: `claude-sonnet-4`, `gemini-2.5-pro`, `gpt-4.1`, `gpt-5`, `qwen3-vl-235b`. The raw Gemini-3-Pro baseline folder mixes repeated configurations and was **excluded from this matched comparison** rather than taking a convenient duplicate. Each model saw the exact same source asset/defect labels, validated by source-hash equality.

On the predefined *mechanical category* subset (land/air/water vehicles, robots, tools, electronics), **368** assets had a human silver reference, of which **47** were majority-labeled `Incorrect Prompt Quantity/Missing Parts`. Direct re-scored class outcomes:

| Model | True missing parts found (of 47) | False missing-parts claims (of 321 negatives) | Precision | Recall |
|---|---:|---:|---:|---:|
| Claude Sonnet 4 | 15 | 46 | 24.6% | 31.9% |
| Gemini 2.5 Pro | 24 | 110 | 17.9% | 51.1% |
| GPT-4.1 | 21 | 70 | 23.1% | 44.7% |
| GPT-5 | 16 | 42 | 27.6% | 34.0% |
| Qwen3-VL 235B | 12 | 23 | 34.3% | 25.5% |

All five configurations are unsatisfactory as standalone automated mechanical completeness judges. Higher recall came with unacceptable false alarms, while selective models missed most genuinely human-labeled missing parts. Model names are historical model-family identifiers for **published May–June 2026** inference and do not imply evaluation of current/latest served models.

Stronger source label check: `golden_adjudicated_truth.csv` contains **100** expert-adjudicated meshes; **99** overlap the standardized released model predictions. Among the **99**, experts marked **31** as missing parts. Comparing those same five archived model judgments against expert references (for all source categories): Claude Sonnet 4 **7/31** true, **11** false; Gemini 2.5 Pro **18/31** true, **19** false; GPT-4.1 **14/31**, **19** false; GPT-5 **6/31**, **5** false; Qwen3-VL 235B **4/31**, **9** false. When restricting further to just mechanical expert assets there are only **30** examples and **nine** missing-part positives, too few for confident cross-model ranks. Silver majority labeling and expert adjudication differ; the relative numbers change materially. To avoid treating two generator outputs of the same prompt as independent experiments, we recomputed one thousand **prompt-cluster bootstraps** over the expert labels. The missing-parts recall 95% bootstrap intervals on all 99 expert assets were Claude **7.7–40.5%**, Gemini 2.5 Pro **38.5–77.2%**, GPT-4.1 **27.3–64.1%**, GPT-5 **6.9–32.1%**, and Qwen3-VL 235B **3.0–25.0%**. These intervals quantify substantial source-sample uncertainty; no pairwise superiority conclusion is justified from overlapping marginal intervals. The machinery-only expert subset has just 15 independent prompt clusters and correspondingly much wider/degenerate intervals. The exact code and per-model precision/false-alarm intervals are preserved in `tests/research/three_d_expert_bootstrap_uncertainty.py` and the linked aggregate evidence JSON. Raw independent-expert agreement also constrains the label ceiling. The authors release **199 original geometry expert annotation rows across 100 assets**, including **99 doubly rated**. On those 99 pairs, experts agreed on **76.8%** of missing-parts labels, **76.8%** of fused-or-incomplete labels, and only **67.7%** of overall form/surface-quality judgments. Pose agreement was nearly 99% but the defect itself is rare. The released *adjudicated* labels are preferred for scoring, but their existence does not erase human ambiguity; this is an important reason to record missed/false counts and source-rater disagreement together. The model cannot independently verify hydraulic reach, load-bearing integrity, exact linkage kinematics, real forklift manufacturing practice or unknown hidden geometry from images alone.

The original GLB images/source meshes for ten human-annotated machine-like golden assets were downloaded into `/data/var` with independent labels (four majority-labeled missing parts, six not); **none were rendered or rated locally in this continuation** because Nitro was already heavily CPU-loaded and a bounded specialized UI-model trial was running. Merely downloading an asset is not a vision-judge measurement. Do not classify the GLB parser count, valid mesh bounds, or source existence as proof of physical plausibility. The most relevant next benchmark is expert-labeled rendered machinery from multiple views *plus* independent CAD scene units, interpenetration/collision/joint/kinematic oracles.

Additional high-quality primary evidence not executed on this host: <https://openaccess.thecvf.com/content/CVPR2026/html/Puyin_QUANTIPHY_A_Quantitative_Benchmark_Evaluating_Physical_Reasoning_Abilities_of_Vision-Language_CVPR_2026_paper.html> (QuantiPhy, CVPR 2026, over 3,300 numerical video physical reasoning tasks), and <https://arxiv.org/abs/2607.18673> (MissingBench-Verified, July 2026 preprint) both document important limitations of vision-language models on physical quantities or missing object parts. OmniMech <https://arxiv.org/abs/2608.05539> introduces real dimensioned mechanical CAD paired with drawings and meshes but is about CAD reconstruction rather than providing a pre-certified visual defect judge. These are research datasets/limitations, **not locally verified numerical model rankings**.

## Video model candidate: capability is not production reliability

The prior continuation already verified source-frame timing/hashes on actual finished 3D product video windows plus 48 **injected** frame-edit scenarios; these are **not independent naturally occurring stutter errors** and are not rerun here. A highly pertinent newly available video judge is NVIDIA's <https://huggingface.co/nvidia/physical-plausibility-evaluator>. It uses a frozen V-JEPA 2.1 ViT-L video encoder and a ~2,049-parameter trained binary quality head, samples 64 frames, and outputs a score from a single video. The vendor documents ROC AUC **0.8258** on 998 held-out *same-generator* Cosmos 3 videos, with **562/698** bad videos detected (80.52% recall) but **94/300** human-good videos rejected (31.33% false rejection) at the default validation-selected threshold. The backbone is approximately 300M parameters, CUDA-dependent with PyTorch CUDA 12.8 and evaluated on an NVIDIA H100. **It was not run on the Nitro six-gigabyte RTX 3060**, its domain is not Blender machinery, and the classifier explicitly does not certify physical correctness. This supports using it as an **optional triage candidate** when runtime/license and domain are verified, not a go/no-go acceptance judge. For precise temporal frame faults, preserve original frames, video timestamps and intended editing commands; optical-flow anomaly is not automatically failure because camera cuts/holds can be legitimate.

## Task-specific decision and remaining independent requirements

**Measured useful subtool:** axe-core on DOM-backed web products; report violations and abstentions, verify target images and unsupported effects. **Measured unreliable gates:** image-only Tesseract/RapidOCR contrast-confidence heuristics on real-site screenshots with offscreen-label mismatch, simple paired UI MAE/SSIM on 311 human-annotated mobile screenshots (SSIM flags 157/186 tagged but 41/63 no-tagged controls), local frozen CLIP on 3D-object industrial photographs, and published big-VLM mechanical missing-part judgments reanalyzed above. **Candidate but no verified standalone judge:** ScreenVLM as element parser, OmniParser for pointer/element detection, trained PatchCore/EfficientAD for known-product photo anomalies, a calibrated NVIDIA physical-plausibility video model as triage, CGVQM+D as a matched-video reference metric. All require tested checkpoint/version, expected label definition, license, prompt/camera/render protocol and heldout good/bad cases.

**Still open:** modern specialized model comparison under full original UI context and clean/defect holdouts (including overlapping text vs purposeful overlays), stronger natural-source human truth for 3D mechanical geometry and physically impossible motion, actual captured temporal dropped/stuttering video with editorial source timeline, audio/video sync measurements and target-specific true acceptance reliability. Physically plausible machine/photorealistic output quality cannot be judged by a model's generic caption, no matter how confident. Do not promote an analyzer before it has passed this task's gold independent validation; no general system qualifies now.
