# Perceptual Analyzer Research: External Diagrams, Real Browser Layout and Video — 2026-10-24

**Owner question:** which available downloadable image/video models and deterministic analyzers can *reliably* judge actual visual software output—clipping, overlapping, contrast, diagram text and meaning, industrial 3D plausibility, video temporal defects—and how should the tools be selected from independent positives/negatives rather than from their own plausible reports?

**Decision after this continuation: NO general visual quality judge qualifies for autonomous production acceptance.** The evidence does support a narrow **browser DOM text-overflow check**, which classified all nine independently labeled real-site clipped text containers with zero false alarms on their nine paired clean controls, but did not generalize to the viewport-protrusion subtask. A known-good **approved final** video-frame timeline permits exact frame change detection; without the approved reference, editorial holds and defective freezes can be pixel-identical. The tested OCR and CLIP families continue to have extensive errors. No vision LLM is promoted on the basis of author-only benchmark claims. New complete aggregate data and raw input/report checksums in `perceptual-visual-continuation-evidence-2026-10-24.json`; runnable probes in `tests/research/`.

## 1. Previously pending RapidOCR — completed actual measurements, not a qualified gate

The predeclared RapidOCR ONNX 1.2.3, ONNXRuntime 1.17.0, NumPy 1.26.4 comparison completed all **70 external UIJudgeBench real-site screenshots**, requiring about **2,310 seconds CPU**, median approximately **30 seconds per page** on busy Nitro. Predeclared rule was the same as prior Tesseract: defect if OCR median confidence below 65% or any OCR region's estimated contrast below 4.5; this estimated image contrast is *not a WCAG computed-style criterion*. For dev real-site layout 26 items, TP 7, FP 3, FN 6, TN 10; for test real-site layout six items TP 2, FP 1, FN 1, TN 2. For dev contrast 41 items TP 4, FP 10, FN 0, TN 27; for test contrast 16 items TP 2, FP 6, FN 0, TN 8. Thus **even this improved OCR baseline** falsely accused six of fourteen compliant contrast test cases, and is too expensive for blanket CPU-only screenshot inspection. All raw independent decisions retained externally and reproduced from `tests/research/public_ui_rapidocr_benchmark.py`.

**CRITICAL: benchmark modality mismatch preserved, not erased.** UIJudgeBench labels are independently verified DOM/full-page judgments, but **12/16 defective real-layout target boxes were wholly outside the downloaded PNGs**. Two different defect-labelled DOM pages even had *identical screenshot bytes*. One cannot honestly estimate screenshot-only false negatives against an invisible defect. This limitation applies to both RapidOCR and earlier Tesseract scores; even successful agreement would not prove perception. Correct paired evaluation must scroll/render the actual target region, collect a full-page render, or use instrumented DOM. No model should be called a bad perceptual system solely because a task input lacks decisive information.

## 2. New actual Firefox DOM remeasurement of real websites

For the same externally labelled **32 L1 real-site layout cases** (16 defective/16 clean), downloaded the archived standalone real web pages, pinned UIJudgeBench `v0.4.0`. Firefox 146.0 + Mozilla Geckodriver 0.36.0 ran in an isolated profile, with network proxy disabled to invalid local endpoint and no external site navigation. Source HTML pages contained no executable scripts; source checksums preserved outside Git. The detector was given a **task-specific criterion and the CSS selector** of the target element, never the true yes/no label or author's measured value. The predicate for text clipping used scrollWidth/clientWidth and scrollHeight/clientHeight **plus computed overflow modes**. The first viewport-protrusion predicate used root document scrollWidth versus window innerWidth. Then compared every prediction with the authors' browser-measured gold separately by dev/test split.

Observed independently reproduced confusion:

| Firefox DOM criterion | Positives found | False alarms | Positives missed | Clean accepted | Total |
|---|---:|---:|---:|---:|---:|
| Clipped text element/protrusion | **9** | **0** | **0** | **9** | 18 |
| Element extends beyond viewport, root-scrollWidth method | **2** | **0** | **5** | **7** | 14 |
| Overall | **11** | **0** | **5** | **16** | 32 |

For developer-defined clipping, DOM geometry in the **observed** UI is strongly more direct and less false-positive-prone than screenshot pixel/OCR confidence. But nine positives is far below a deployment-sized validation set and the task depended on knowing exactly which element was under test. Critically, five viewport false negatives had element bounding-rectangle width **3,000px** and right edge beyond a ~1920px window, while `documentElement.scrollWidth` was **at or below the viewport**. The apparent contradiction comes from overflow-clipping ancestors or other layout rules: the root document extent is not the right signal for every hidden protruding child. An improved detector must inspect the *target's* actual `getBoundingClientRect()` and each relevant clipping ancestor and should distinguish intentional overflow. **That improvement was derived from looking at the failures, so the public `test` cases are now consumed; no independent post-fix holdout accuracy is claimed.** Raw separate Firefox measurements, errors and receipts remain under `/data/var/perceptual-independent-20261024/uijudge-v0.4.0/firefox_dom_independent.json`.

## 3. New real scientific diagrams, with independently supplied source text

External reference <https://huggingface.co/datasets/AIGrounding/Diagram-MMU> (**ECCV 2026**, authors' released `testmini` canonical diagrams): 300 real curated, compilable TikZ diagrams balanced across chart, graph, planar geometry, 3D shapes, chemistry and circuit genres. The full benchmark contains 3,744 source-backed diagrams and 18,305 human-validated evaluation instances across parsing/editing/question-answering tasks, so it is an appropriate **source for future diagram model evaluation**, not a generated teaching mockup. Downloaded pinned `testmini` Parquet about 11.7MB; retained source SHA. To isolate an objectively checkable property without a VLM, predeclared a **strict** literal TikZ `\\node` regex accepting only single ASCII-alphanumeric label bodies, then compared screenshot OCR tokens against original human-curated source code. Among 300 diagrams, **37** had source labels eligible under the deliberately restrictive parser, with **134 distinct literal label instances** in these cases.

Tesseract **5.3.4** on original rendered images: PSM 6 recovered **42 of 134** literal labels (about **31%**), and PSM 11 **30 of 134** (about **22%**). All strict-label success on every eligible diagram happened in **8 of 37** cases for PSM 6 and **3 of 37** for PSM 11. Runtime about 28 seconds and 25 seconds respectively, not counting dataset preparation. These figures are **not overall chart or diagram reasoning accuracy**; they reveal poor OCR text coverage on the restricted eligible set. The parser intentionally ignores rich LaTeX labels, equations and graph relations; a missing OCR match can also reflect font size, rendering and tokenization rather than a model's failure to understand an otherwise legible diagram. Thus the external source supplies intended labels, not independently human-scored legibility for each printed glyph. False-positive OCR words cannot be scored soundly from an incomplete source-label parser. Full results and inputs remain in `/data/var/perceptual-independent-20261024/diagram_mmu/`; reproduction `tests/research/diagram_mmu_source_label_ocr.py`.

**Stronger primary research for model selection:** the Diagram-MMU authors' published benchmark results (<https://vi-ocean.github.io/projects/diagram-mmu/index.html>) report Qwen3-VL-8B **47.12%** diagram-question accuracy and **44.66** average diagram parsing F1, compared with Gemini 3.0 Pro **86.46%** diagram QA accuracy on their protocol. These author scores are not local measurements, do not predict clipping performance, and full diagram understanding differs from exact visual reconstruction. A capable 8B captioner should therefore not be accepted as a reliable structural diagram judge. External human-evidence-grounding benchmark DRAGON (<https://coral-lab-asu.github.io/DRAGON/>) provides box-level answer-support labels across six diagram families; directly compare local candidate grounding against those external boxes before permitting chart/diagram QA use. A raw rendered diagram can still be false semantically if its underlying specification is wrong; use authoritative chart data/TikZ/edge lists plus visibly rendered label/geometry checks, not single-caption agreement.

## 4. An additional CPU-only industrial image method, and limits of physical plausibility

Previous independent mini study: eighteen actual **MVTec LOCO AD** photographs of an industrial pushpin organizer, eight normal/ten anomalous, not generative machinery renders. Zero-shot global CLIP classified two defects and falsely rejected three normal images; one-class global-image CLIP nearest-neighbor using four calibration normal images found three defects and falsely rejected one of four holdout normals. No model fine-tuning on defect labels.

This pass implemented a **patch-feature nearest-normal proxy** from the already installed `openai/clip-vit-base-patch32`, PyTorch float32 CPU only. Predeclared 95th-percentile nearest normal patch distance, threshold calibrated **only from leave-one-out comparisons of four nominal examples** and kept fixed for the remaining fourteen images. Observed one of ten actual anomalies detected, **zero false alarms** among four other normal images, with image-level AUROC about **0.725**. Recall **10%** is unusable for this task; the absence of false positives on only four normal examples does not establish specificity. This method is **not official PatchCore**: CLIP patch features are not the authors' multiscale ImageNet WideResNet features plus memory-bank coreset. A higher AUROC with an extremely low thresholded recall does not establish meaningful improvement. Original image hashes, calibration group, scores, confidence/cost retained outside Git; reproduction `tests/research/public_industrial_clip_patch_memory.py`.

The official PatchCore method in CVPR 2022 (<https://openaccess.thecvf.com/content/CVPR2022/html/Roth_Towards_Total_Recall_in_Industrial_Anomaly_Detection_CVPR_2022_paper.html>) reports up to **99.6% image AUROC on MVTec AD** with trained target-class normal patch features; EfficientAD WACV 2024 (<https://openaccess.thecvf.com/content/WACV2024/html/Batzner_EfficientAD_Accurate_Visual_Anomaly_Detection_at_Millisecond-Level_Latencies_WACV_2024_paper.html>) uses learned student/teacher plus global autoencoder to detect local **and logical** anomalies, reporting GPU inference around two milliseconds for its benchmark. **Neither model has been replicated here and neither published number means it can detect a nonsensical hydraulic forklift render.** In real Blender/glTF machinery, first use authoritative physical scene units, world-space bounding shapes, exact collision/contact, joints and motion constraints and multiview depth/normal passes; nested parts, ground recesses, cast shadows, specular highlights and modeling conventions require intended-contact exceptions. Photorealism/real-world industrial authenticity need human-rated or independently sourced matching mechanical exemplars; remain unverified.

## 5. Measured temporal failures on completed real 3D product videos

Four existing finished videos (two scenes: forklift and machinery pack, each full-HD and published 720p derivatives), read only and source hashes recorded. Each supplied two fixed **64-frame** source windows; no production render was restarted. Across eight genuine visual windows we generated exactly **48 evaluation sequences** with reproducible independent frame-index policies: unchanged source, unintended three-frame hold, dropped three frames, reversed three frames, deliberately **approved** freeze of the identical sequence, and **approved** camera cut to another real view. Input frames are all extracted from the real videos, though alterations are controlled and **do not constitute observed unplanned production errors or subjective human-rated stutter**. Two scene families mean delivery encodings and windows are correlated; fifty tests are not fifty independent productions.

| Comparator | Detected 24 injected faults | False alarms on 24 unchanged/approved controls | Missed faults |
|---|---:|---:|---:|
| Exact repeated-frame runs (at least three) | 8 | 8 | 16 |
| Global pixel difference spike: median + six MAD | 24 | 24 | 0 |
| Exact original-frame sequence full reference | 24 | 16 | 0 |

After *excluding* deliberately approved holds/cuts, a matched **unedited original reference** identified all 24 controlled frame-sequence deviations with no false alarms among eight unchanged-source controls. That narrower result tests exact **frame identity**, not perceptual viewing quality. It does not survive lossy reencoding as exact-hash matching; real deployments need a known-good final edited reference and metrics tolerant of encoding. Approved editorial holds and unintended pauses were **bitwise/pixel-hash identical** in eight pairs despite opposite labels; no video-image-only oracle can derive an invisible editorial intention. Raw source videos and any altered media are **not in Git**; reproducible hashes and full per-case metrics in `/data/var/perceptual-independent-20261024/real_render_video_continuity/`; regeneration script `tests/research/real_render_video_continuity_eval.py` refuses replay of completed results.

Primary relevant temporal research: NR-FFM, Dumic and Bjelopera, *Sensors* 2019 DOI 10.3390/s19214655 (<https://pmc.ncbi.nlm.nih.gov/articles/PMC6864624/>), compares no-reference freezing assessments against human-rated **LIVE Mobile** streams with known frame-freeze distortions, not arbitrary movie stutter and not a locally measured model. Intel's **CGVQM+D** (Jindal et al. 2025, <https://www.intel.com/content/www/us/en/developer/articles/technical/cgvqm-d-computer-graphics-video-quality.html>) uses matched reference + learned 3D CNN features for rendering artifacts with human-rating evaluation; its metric **has not** been run here. The official LIVE mobile dataset requires an access form and was not downloaded. Public temporal tampering sets such as CSVTED have very large archives and were not silently downloaded to solve the benchmark by brute force. A reliable production workflow must preserve presentation timestamps, expected frame indices, audio offsets, deliberately allowed cuts/holds, actual final playback and human-rated examples, not just large frame derivatives.

## Tool selection status after this pass

**Narrowly evidenced:** DOM `client/scroll` clipping checks on *known target elements* in real websites, plus exact reference-backed checks for matching delivered frames before destructive publish actions. Even these need more browser/project families and untouched holdout verification. **Useful measurements, not quality oracles:** pixel OCR, computed CSS foreground/background accessibility contrast, parsed UI elements, signed mesh collisions/constraints, color/flow/timestamp signals, cut/motion segmentation. **Rejected as solo decision judges on tested tasks:** our Tesseract/RapidOCR pixel-confidence+contrast heuristic, local global/patched CLIP on real industrial photographs, raw frame difference spikes, Thor Qwen3-VL 8B four-image gate. **Research candidates without local measured acceptance:** ScreenVLM (316M UI element/text/box parser; ICML 2026 <https://proceedings.mlr.press/v306/gurbuz26a.html>), UI-UX specialized VLM for user experience, official PatchCore/EfficientAD target-trained anomaly, larger VLMs on DRAGON/Diagram-MMU evidence-grounded tasks, and CGVQM on matched-reference moving renders.

For the owner's video/3D work, there still is **no calibrated photorealism, industrial engineering plausibility or full-video natural judder judge**. The independent positives and negatives already establish failure modes and eliminate unsafe simplistic gates. A credible final selection needs externally annotated physically correct/incorrect 3D **rendered** assemblies from relevant equipment, human-referee judged photorealism, and genuinely bad/normal captured and final encoded videos with frame-level time truth. Test exact model checkpoint, license, quantization, GPU/CPU memory, and error rates on idle hardware. Prefer a small trustworthy specialized instrument with a strict contract over a high-parameter captioner whose output only sounds plausible.
