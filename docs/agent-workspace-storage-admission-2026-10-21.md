# SWAAG agent workspace: conservative disk-write admission

The recording-derived Infra requirements call for durable evidence, bounded growth, resource stewardship and safe failure under shared-disk pressure. Thor currently shares a nearly full volume with large local models, research evidence and other projects. The agent must not interpret free disk as permission to remove old evidence without inspecting ownership and original-source obligations.

The agent-owned `agent_workspace.write_text` path now validates **UTF-8 byte length**, not merely Unicode character count, against the named `agent_data.max_workspace_write_bytes` limit. It checks the kernel's `statvfs` user-available byte count under the existing write lock before creating parent directories or replacing the previous file. Since replacement is atomic, the calculation reserves the entire new temporary file without claiming that the old file's occupied blocks are immediately free. Oversized text, unavailable filesystem counters and insufficient remaining free space are explicit admission failures, not silent partial writes. Existing workspace files remain unchanged. The tool's successful text-write result records both character and byte counts.

For sandboxed shell, Python and package installation, the same free-space check now happens **before launching the writable subprocess**. The configured `agent_data.min_free_disk_bytes` is a conservative admission floor. Read-only `read_text` and `list_files` remain available even if disk space is critical. Both thresholds are named, validated, documented and configurable; defaults are sixteen MiB per direct text write and two GiB user-available reserve.

**Limitations:** This does *not* enforce an aggregate filesystem or cgroup quota. Another process can allocate space after admission, and a sandboxed command or package installer may allocate beyond the observed floor while it runs. The existing command timeout and exact output capture ceilings are separate protections, not evidence of host disk isolation. Full per-process and cross-project disk/RAM/VRAM quota enforcement still requires measured OS-level resource controls and concurrent load acceptance, and remains open in the Infra compliance audit.

Tests independently cover multi-byte Unicode sizing, refusal before mutation, atomic revision preservation, no creation of new nested folders after refusal, unavailable statvfs counters, write and command admission, configuration invalid zero/negative values, existing workspace recovery, and the rest of the existing SWAAG suite. These tests establish the specific guards, not unrestricted host-wide compliance. No existing large test histories, models or work products are deleted by this change.
