# Swaag implementation TODO

This is the gap list between the current repository and the intended architecture in `docs/design-principles.md` and `docs/context-management.md`. It is an implementation checklist, not a list of ideas. Items marked **partial** already have useful foundations in the repository but still differ materially from the target semantics.

## P0 - context compilation and semantic ownership

- [x] **Replace message-count-triggered history compression with budget-driven context pressure.** Compression is now triggered by actual next-call overflow rather than message count.
- [x] **Remove fixed character sizing as an architectural control for runtime summaries.** Runtime summary targets are token-budget-driven. Benchmark-only character checks may remain only where they measure an output property rather than model context capacity.
- [x] **Create an explicit context-compiler abstraction for production worker, summary, tool-result-projection, and model-backed capability calls.** Future semantic operations must use the same compiler as they are added; direct capability-owned model clients are forbidden.
- [ ] **Make the context compiler account for every serialized component explicitly.** **Partial.** Current budgeting handles output reserve, estimator/fixed safety, schemas, prompt framing, individual completion-evidence results, and attachment references as named components. Obsolete unmeasured fixed-overhead and safe-input reservations are removed. Extend/prove accounting for retrieved/web material and every future protocol or semantic-operation component with provenance.
- [x] **Persist per-call context accounting/provenance for current production LLM operations.** Extend the same record to every future semantic operation and benchmark export.
- [ ] **Make all semantic context inclusion/exclusion decisions LLM-owned.** **Partial.** Current history compression and durable-note compaction are model-authored central semantic operations. Durable notes now carry model-authored free-form categories and support add/replace/remove/consolidate. Before every action, a separately compiled LLM sees every exact note plus the specific upcoming action context and selects relevant IDs; categories are semantic hints, never deterministic routing keys, and selector failure includes all notes. Selected exact notes and the complete live workspace manifest then enter full-fidelity-first context, with only measured overflow permitting objective-specific LLM projection and exact recovery paths. A checkpointed production-path `note-behavior` harness covers distinct category authoring, identity-preserving revision/erase, and current-step isolation; run it live across model sizes. `history_analyze` likewise admits every exact event up to its action boundary instead of preselecting by lexical rank, recency, or event count. Cross-worker status lookup and task inspection expose complete exact semantic-status and inference-request histories rather than fixed last-five/last-ten views. Audit every remaining place that drops, clips, selects, prioritizes, or summarizes semantic information and move meaning-dependent choices behind an LLM decision with hard numerical constraints enforced afterward.
- [ ] **Never silently truncate semantic material to recover context space.** **Partial.** Browser search/page previews report every reduction and retain exact raw provider responses and diagnostics in integrity-checked artifacts; failed browser processes, attachment extraction, and model-completion HTTP errors now commit their complete response bodies or stdout/stderr before exposing bounded error text. Shell/test output has the same durable bounded-read contract. Durable notes reject storage overflow rather than clipping or dropping content, and compaction uses bounded hierarchical LLM reduction over every exact source note. Continue auditing history windows, prompt assembly, file reads, benchmark adapters, and remaining provider wrappers. Where truncation is only a transport/display safeguard, preserve a durable raw reference; where it affects model knowledge, use semantic reduction or explicit bounded retrieval.
- [x] **Make overflow recovery iterative and semantic for current production operations.** Action and independent completion-evaluation calls calculate measured overflow, semantically project the largest reducible raw tool result or runtime-context source, rebuild, and re-tokenize for bounded rounds while retaining raw provenance. Workspace/note projections are durable but bound to exact source and objective hashes, so source or request changes invalidate them. History compaction receives the exact deficit, starts with the smallest mechanically sufficient source prefix, derives its target from measured source/provenance cost, and records actual recovery rather than using a context ratio. History analysis and evidence/tool projections shrink only by the current deficit plus fixed framing slack instead of deterministic halving. An exact source that cannot fit a reducer is segmented without dropping fragments, while every reduction and recombination is model-authored. Every future semantic operation must use the same measured, iterative pattern.
- [x] **Make output reserve operation-specific and semantically appropriate.** The compiler separates per-call operation minimums from per-call desired headroom, preserves full-fidelity input that fits the minimum, and reconstructs every production structured semantic call after backend-reported output starvation. Dynamic reducer targets set desired output directly instead of inheriting a static ratio; if an expanded hard minimum causes overflow, evidence-bearing operations return to bounded semantic reduction.
- [ ] **Benchmark context ordering and positional retrieval per model and operation.** **Partial.** The resumable positional-retrieval harness uses the connected server's exact chat template rather than plain or model-specific prompt text. The balanced cyclic-layout harness places task instructions, current request, history, tool definitions, tool results, and retrieved evidence at every user-message position while also checking the system instruction, records exact token fractions, and checkpoints each live case. Both derive a per-case soft verification output maximum from the live context and current exact input instead of starving reasoning-capable models with fixed 96/192-token caps. The first live 13,118-token early-position case passed but required 2,440 seconds under concurrent host load. The bounded 8,192-token positional matrix passed all 9 early/middle/late probes at approximately 10%, 50%, and 90% utilization, and the balanced semantic matrix passed all six 50%-utilization rotations with 42/42 exact field checks. Exact latency, queue-contention evidence, and provenance are documented in `docs/live-benchmark-results.md`. Both harnesses distinguish authoritative server capacity from an explicit smaller benchmark working window, allow bounded subsets, and now default to the documented 900-second live-experiment timeout with explicit CLI overrides. Run selected full-window semantic cases and additional models; do not hard-code a universal production order from one model's bounded results.
- [x] **Eliminate any mismatch between model-reported context capacity and actual request serialization.** Live llama.cpp compilation takes authoritative per-slot `n_ctx` and model/chat-template identity from `/props`, serializes model-neutral role/content messages through `/apply-template`, proves exact component reconstruction, re-verifies identity before inference, and records/replays exact renderings without network fallback. Remote OpenAI-compatible compilation selects and hashes stable model metadata from `GET /models`, discovers explicit provider capacity (`context_length`, `max_model_len`, or equivalent), uses a vLLM-style message-tokenization extension when available, and re-verifies metadata before inference. Because the standard OpenAI Models API exposes neither capacity nor private chat serialization, generic providers remain honestly provider-opaque: exact role/content offsets are retained, unavailable tokenization is estimated with disclosed safety, and live capacity fails closed unless `model.remote_context_limit_fallback` was explicitly configured. OpenRouter routing fields are isolated to OpenRouter and optional bearer credentials are read from a named environment variable without entering history or identity.

## P1 - worker lifecycle, multi-tasking, and communication

- [x] **Implement multiple independently addressable worker instances.** Each durable worker has its own task identity, session/history/projection state, mechanical lifecycle, event cursor, and control/cancellation path while retaining the simple sequential inner agent loop.
- [x] **Add worker lifecycle operations: create/start, inspect, message/redirect, cancel/stop, resume/reconstruct, and archive.** Cancellation is durable and stops active inference; archive retains the actual terminal state rather than inventing a new execution state. A true suspended backend state is intentionally not claimed as pause.
- [ ] **Separate user-facing communication from busy worker execution.** **Partial.** The long-running communication service owns a bounded multi-worker executor and transport-neutral task API, can redirect/cancel active inference, and uses an independent compiled operation session for status interpretation. A configured separate communication model avoids preempting the worker; same-model operation uses explicit cancel-and-exact-replay. Benchmark priority/latency under real long inference and tools and extend this separation beyond status.
- [ ] **Implement a communication agent with explicit escalation.** **Partial.** A configured separate communication runtime now makes a constrained semantic escalation decision for status questions. A positive decision preempts the main call when necessary, sends the same exact evidence snapshot to the strong runtime at control priority, then durably links request, resolution or failure, operation sessions, answer hash, and semantic-versus-mechanical trigger before exact main-call replay. Mechanical assistant failure fails over to the strong runtime using the failed operation's exact source references rather than making status unavailable. The production CLI/service actually constructs the configured runtime rather than ignoring its endpoint. Broader communication work and live model-size policy remain open.
- [x] **Let the communication agent read durable worker history and deterministic runtime state without receiving entire worker contexts.** Status questions use a dedicated operation session and contract, exact target-event snapshot plus deterministic mechanical state, central context compilation, measured overflow, hierarchical semantic projection, exact source references, and bounded validation repair. The operation never writes target worker history, avoiding stale-writer races.
- [x] **Support user interruption at arbitrary worker stages.** Instructions enter the durable pending-control queue before preemption. A newer snapshot invalidates stale unexecuted actions; controls delivered during tool execution preserve completed evidence and abandon unstarted calls; controls during completion evaluation, response presentation, structured output, or terminal commit keep the result provisional and start another durable run cycle. In-process control delivery and terminal transition share an atomic boundary so a control cannot be stranded on a completed worker.
- [x] **Define conflict semantics for instructions arriving while inference/tool execution is active.** Delivery order, stale-snapshot invalidation, completed-versus-unstarted tool boundaries, and cancellation mechanics are deterministic. Every exact pending control is compiled into the next LLM call in order; the LLM decides semantic compatibility, conflict, replacement, and reconciliation without keyword/source-priority handlers.

- [x] **Remove obsolete configuration knobs whose semantics are superseded by per-call context compilation.** Fixed note-compaction character, note prompt-token, workspace manifest-count, and recent-message retention targets are removed; legacy config files remain loadable. - [ ] **Ensure benchmark adapters use the same production context compiler and semantic policies.** Avoid benchmark-only shortcuts that hide real overflow/compaction behavior.
- [x] **Make context/accounting replayable for recorded model tests.** Exact request cassettes retain model-call payloads, token counts, and server-rendered chat prompts keyed by request metadata. Model cache identities and benchmark namespaces include output-affecting model file/server/template/generation facts while excluding volatile `/props` instance noise such as sleep state and random media markers, so a server restart does not invalidate an otherwise identical replay and an actual model/protocol change cannot silently reuse it. Immutable history shards carry their schema version too; append-only JSON events retain their existing per-event version and integrity chain.
