# Swaag implementation TODO

This is the gap list between the current repository and the intended architecture in `docs/design-principles.md` and `docs/context-management.md`. It is an implementation checklist, not a list of ideas. Items marked **partial** already have useful foundations in the repository but still differ materially from the target semantics.

## P0 - context compilation and semantic ownership

- [x] **Replace message-count-triggered history compression with budget-driven context pressure.** Compression is now triggered by actual next-call overflow rather than message count.
- [x] **Remove fixed character sizing as an architectural control for runtime summaries.** Runtime summary targets are token-budget-driven. Benchmark-only character checks may remain only where they measure an output property rather than model context capacity.
- [x] **Create an explicit context-compiler abstraction for production worker, summary, tool-result-projection, and model-backed capability calls.** Future semantic operations must use the same compiler as they are added; direct capability-owned model clients are forbidden.
- [ ] **Make the context compiler account for every serialized component explicitly.** **Partial.** Current budgeting handles output reserve, estimator/fixed safety, schemas, prompt framing, individual completion-evidence results, and attachment references as named components. Obsolete unmeasured fixed-overhead and safe-input reservations are removed. Extend/prove accounting for retrieved/web material and every future protocol or semantic-operation component with provenance.
- [x] **Persist per-call context accounting/provenance for current production LLM operations.** Extend the same record to every future semantic operation and benchmark export.
- [ ] **Make all semantic context inclusion/exclusion decisions LLM-owned.** **Partial.** Current history compression and durable-note compaction are model-authored central semantic operations. Durable notes now carry model-authored free-form categories and support add/replace/remove/consolidate. Before every action, a separately compiled LLM sees every exact note plus the specific upcoming action context and selects relevant IDs; categories are semantic hints, never deterministic routing keys, and selector failure includes all notes. Selected exact notes and the complete live workspace manifest then enter full-fidelity-first context, with only measured overflow permitting objective-specific LLM projection and exact recovery paths. A checkpointed production-path `note-behavior` harness covers distinct category authoring, identity-preserving revision/erase, and current-step isolation; run it live across model sizes. `history_analyze` likewise admits every exact event up to its action boundary instead of preselecting by lexical rank, recency, or event count. Cross-worker status lookup and task inspection expose complete exact semantic-status and inference-request histories rather than fixed last-five/last-ten views. Audit every remaining place that drops, clips, selects, prioritizes, or summarizes semantic information and move meaning-dependent choices behind an LLM decision with hard numerical constraints enforced afterward.
- [ ] **Never silently truncate semantic material to recover context space.** **Partial.** Browser search/page previews report every reduction and retain exact raw provider responses and diagnostics in integrity-checked artifacts; attachment extraction now commits complete stdout/stderr diagnostics on both success and failure, and failed browser/model-completion HTTP paths likewise retain exact evidence before exposing bounded error text. Foreground shell/test output and every background-process poll, completion, and kill apply the same durable bounded-read contract: no process event or tool result inlines an unbounded stream, and every reduced stream reports its exact artifact/hash/size recovery locator. Workspace literal/regex searches expose deterministic `start_index`/`next_index` pages and an honest `finished` flag instead of silently returning only the first fixed number of matches; both safe search capabilities are available to normal staged semantic selection. Ranked history search now discloses both its result limit and any bounded ranking-candidate pool, while exact history windows expose `next_sequence`/`finished` for complete traversal. Durable notes reject storage overflow rather than clipping or dropping content, and compaction uses bounded hierarchical LLM reduction over every exact source note; the obsolete recency/token-cap note selector has been removed so it cannot silently reintroduce deterministic semantic dropping. Continue auditing prompt assembly, file reads, benchmark adapters, and remaining provider wrappers. Where truncation is only a transport/display safeguard, preserve a durable raw reference; where it affects model knowledge, use semantic reduction or explicit bounded retrieval.
- [x] **Make overflow recovery iterative and semantic for current production operations.** Action and independent completion-evaluation calls calculate measured overflow, semantically project the largest reducible raw tool result or runtime-context source, rebuild, and re-tokenize for bounded rounds while retaining raw provenance. Workspace/note projections are durable but bound to exact source and objective hashes, so source or request changes invalidate them. History compaction receives the exact deficit, starts with the smallest mechanically sufficient source prefix, derives its target from measured source/provenance cost, and records actual recovery rather than using a context ratio. History analysis and evidence/tool projections shrink only by the current deficit plus fixed framing slack instead of deterministic halving. An exact source that cannot fit a reducer is segmented without dropping fragments, while every reduction and recombination is model-authored. Every future semantic operation must use the same measured, iterative pattern.
- [x] **Make output reserve operation-specific and semantically appropriate.** The compiler separates per-call operation minimums from per-call desired headroom, preserves full-fidelity input that fits the minimum, and reconstructs every production structured semantic call after backend-reported output starvation. Dynamic reducer targets set desired output directly instead of inheriting a static ratio; if an expanded hard minimum causes overflow, evidence-bearing operations return to bounded semantic reduction.
- [ ] **Benchmark context ordering and positional retrieval per model and operation.** **Partial.** The resumable positional-retrieval harness uses the connected server's exact chat template rather than plain or model-specific prompt text. ## P0 - durable history, projections, and recoverability

- [ ] **Treat append-only history as authoritative and every prompt history as a derived projection.** **Partial.** Before every worker action, Swaag now reconstructs every exact `message_added` source event and compiles that richest history candidate. A larger later window or smaller call therefore restores raw fidelity automatically. If that exact candidate overflows, tool/results and runtime sources first receive their own measured reduction opportunity, then a new action-specific semantic history projection is built from authoritative messages against the remaining exact deficit; an older compacted view is never admitted merely because it already exists. The reprojection event stores every admitted message plus exact transitive source lineage and rebuilds identically after restart. Candidate/admitted accounting records authoritative versus dynamic history and both message counts. Status, completion, and analysis likewise start from exact event evidence. Generalize the same rule to every future operation and source type.
- [ ] **Track provenance from every summary/projection back to exact source events.** **Partial.** History summaries and tool-result projections retain exact event hashes, session-aware ranges, transitive source references, and their own projection-event identity across replay. Runtime workspace/note projections retain exact source hashes plus deterministic re-expansion locators and are invalidated on source changes. Apply the same lineage contract to future derived views such as attachment projections.
- [x] **Support dynamically sized history projections per call.** `history_analyze`, communication status, completion evaluation, and worker actions compile complete exact operation-specific history first. A measured action overflow now derives a fresh target from that call's deficit, semantically summarizes the smallest sufficient authoritative prefix (hierarchically without dropping bytes when necessary), retains exact recent messages, and rebuilds/re-tokenizes. The resulting `history_reprojected` event carries the complete admitted message view and transitive source references so restart replay is exact; it never mutates or replaces append-only source messages.
- [x] **Support re-expansion from raw history after compaction.** Summary prompts identify exact session-aware source ranges and direct the worker to history-window retrieval. Search/window results preserve exact event hashes, including immutable archive shards, and their lineage survives subsequent tool-result projection and summary compaction.
- [ ] **Benchmark hierarchical summaries versus targeted retrieval versus recent-verbatim-plus-summary projections.** No single strategy should be assumed universally best.
- [ ] **Add compaction-preservation evals for dates, identifiers, user constraints, negative constraints, causality, unresolved questions, promises, file paths/references, tool outcomes, and task completion state.** **Partial.** A checkpointed production-runtime harness and benchmark CLI verify all categories together after each semantic compaction cycle with exact marker checks and source lineage. The new `long-horizon-context` profile adds explicitly untrusted contradictory later decoys, a separate constrained semantic-retrieval probe after every cycle, multiple measured-overflow/projection trials, and independent scores for exact preservation, provenance/recoverability, semantic retrieval, adversarial-conflict resistance, and true overflow handling. Run and retain repeated live Jetson/model-size results before closing.
- [ ] **Test repeated compaction over very long tasks for semantic drift.** **Partial.** The compaction-preservation harness repeats model-authored compaction over the same authoritative facts and records per-cycle drift; `long-horizon-context` adds contradictory later decoys and semantic retrieval after each cycle plus measured-overflow provenance trials. Production compaction now semantically evaluates contiguous history regions instead of choosing the oldest prefix, can compose adjacent non-protected windows for large recovery targets, recursively inspects oversized messages, and replays arbitrary contiguous compressed spans with backward compatibility for legacy prefix events. A semantic-reduction working-set cap can hierarchically fragment local-backend reduction calls before inference when executable memory headroom is smaller than the advertised context window. Extend the live profile to much longer trajectories, delayed queries where an early fact becomes relevant only after many unrelated turns, process restarts between phases, and multiple backend working-set profiles.
