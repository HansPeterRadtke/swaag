# Swaag implementation TODO

This is the gap list between the current repository and the intended architecture in `docs/design-principles.md` and `docs/context-management.md`. It is an implementation checklist, not a list of ideas. Items marked **partial** already have useful foundations in the repository but still differ materially from the target semantics.

## P0 - durable history, projections, and recoverability

- [x] **Treat append-only history as authoritative and every prompt history as a derived projection.** Every turn/resume/control entry point now refreshes caller-held `SessionState` from append-only history before opening a run, so long-lived workers cannot continue from stale in-memory projections after out-of-band durable writes. Action compilation independently reads exact authoritative `message_added` events and always attempts that richest history first; if it fits, older compacted state is ignored and raw fidelity is restored automatically. Only measured overflow can trigger a fresh action-specific semantic reprojection, and that reprojection is derived from authoritative source messages rather than reused merely because an older projection exists. Replay never writes projections directly, checkpoints are only replay accelerators, `history_reprojected`/compression events remain derived state with exact lineage, and status/completion/analysis/worker inspection rebuild from append-only evidence. Regression coverage proves authoritative re-expansion after compaction, dynamic projection only after measured overflow, stale-state refresh on normal turns, resumed turns, pending-control turns, and exact replay across restart.
- [x] **Track provenance from every summary/projection back to exact source events.** The projection audit is complete. History summaries/reprojections carry exact session-aware source-event ranges, hashes, transitive references, and their own projection-event identity. Tool-result and completion-evidence projections carry the exact source tool/event hash plus nested lineage. Communication status retains the complete target-event references even when its evidence is semantically projected. Runtime workspace/note projections use exact source SHA-256 plus deterministic `list_files`/notes recovery locators because those live sources are not single append-only history events; source changes invalidate reuse. Durable prompt-instruction projections retain exact instruction references, source hash, projection hash, and an explicit recovery capability/identity set. External MCP results enter ordinary tool-result lineage, and attachment content is no longer projected by SWAAG at all—layer two carries raw attachment references whose source event/hash identifies the authoritative object. Guardrail tests cover transitive summary replay, tool projection lineage/reuse, runtime-source recovery, completion artifact/event projections, notes, attachments, and history-window re-expansion.
- [x] **Support dynamically sized history projections per call.** `history_analyze`, communication status, completion evaluation, and worker actions compile complete exact operation-specific history first. A measured action overflow now derives a fresh target from that call's deficit, semantically summarizes the smallest sufficient authoritative prefix (hierarchically without dropping bytes when necessary), retains exact recent messages, and rebuilds/re-tokenizes. The resulting `history_reprojected` event carries the complete admitted message view and transitive source references so restart replay is exact; it never mutates or replaces append-only source messages.
- [x] **Support re-expansion from raw history after compaction.** Summary prompts identify exact session-aware source ranges and direct the worker to history-window retrieval. Search/window results preserve exact event hashes, including immutable archive shards, and their lineage survives subsequent tool-result projection and summary compaction.
- [ ] **Benchmark hierarchical summaries versus targeted retrieval versus recent-verbatim-plus-summary projections.** No single strategy should be assumed universally best.
- [ ] **Add compaction-preservation evals for dates, identifiers, user constraints, negative constraints, causality, unresolved questions, promises, file paths/references, tool outcomes, and task completion state.** **Partial.** A checkpointed production-runtime harness and benchmark CLI verify all categories together after each semantic compaction cycle with exact marker checks and source lineage. The new `long-horizon-context` profile adds explicitly untrusted contradictory later decoys, a separate constrained semantic-retrieval probe after every cycle, multiple measured-overflow/projection trials, and independent scores for exact preservation, provenance/recoverability, semantic retrieval, adversarial-conflict resistance, and true overflow handling. - [ ] **Test repeated compaction over very long tasks for semantic drift.** **Partial.** The compaction-preservation harness repeats model-authored compaction over the same authoritative facts and records per-cycle drift; `long-horizon-context` adds contradictory later decoys and semantic retrieval after each cycle plus measured-overflow provenance trials. A semantic-reduction working-set cap can hierarchically fragment local-backend reduction calls before inference when executable memory headroom is smaller than the advertised context window. Extend the live profile to much longer trajectories, delayed queries where an early fact becomes relevant only after many unrelated turns, process restarts between phases, and multiple backend working-set profiles.
