# Android voice UI guideline gate — Oct 21, 2026

On Nitro, the concurrently modified Android repository completed offline local Gradle unit tests for `:apps:android03:testDebugUnitTest` and `:apps:voicebutton:testDebugUnitTest`: 21 and 89 cases respectively, no failures in their JUnit XML results. This does **not** establish UI/phone behavior. The first attempt to run Android03 instrumentation on the existing shared `infra_voice_api34` emulator was **not an app test**: the installed app had a later version and Android refused to downgrade it. It was deliberately not overwritten or uninstalled.

A **separate temporary Android 34 emulator**, `swaag_ui_ephemeral_20261021`, was created from the installed system image and isolated from the user's shared emulator. Both current Android03 debug and instrumentation APKs installed into the temporary device. Four Espresso UI tests began, but Android's **SystemUI was in Application Not Responding state and owned window focus**. All four returned `RootViewWithoutFocusException`, so they cannot be counted as successful product tests or as evidence of four application-code defects. The attempt's raw output is `/data/var/android03-isolated-ui-test-20261021.log` on Nitro. The temporary emulator was gracefully stopped and only its own temporary AVD directory removed; the shared emulator and its newer installed app were unchanged.

**Still required:** acquire a stable clean emulator with working SystemUI focus, rerun the four local instrumented tests and check layout/permissions; then inspect native Android UI real text selection/editing, automation controls, persisted draft and recording, playback transport, time/seek controls and interruption in the physical phone app. Real microphone, STT, TTS, simultaneous work, first-audio latency and mobile reconnection are separate unreleased acceptance gates. The Android main worktree is dirty with ongoing user project modifications and was not reset, merged or changed by this audit.
