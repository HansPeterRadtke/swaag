# SWAAG compact delegation experiment — October 19, 2026

## Problem and exact constraints

Production Coder must choose the correct control action while Qwen3.8 Q8 continues to run background work. Before this experiment, even a clearly specified single finite worker required the extensive multipurpose `orchestration_control` JSON Schema, with dozens of nullable fields and deeply nested `plan_spec`. Actual controlled voice requests produced 485–510 generation tokens per first action, contributing to a first committed acknowledgement around 28 seconds even in recent accepted cases.

## Candidate

This **isolated experiment** registers `orchestration_delegate`, an independent, small, explicit seven-field schema for exactly **one finite worker**: the overall plan objective, worker objective, chosen model key, positive priority, semantic finish and abort criteria, and reporting mode. A model still chooses this tool and all semantic details. The implementation validates the input, creates a complete one-worker finite `plan_spec` using the same existing authoritative plan validator, and executes exactly one existing `OrchestrationApi.execute('plan.apply', ...)` call. This is not a parallel authority mechanism; durable plan admission, user permissions, worker status and results remain owned by the existing orchestration subsystem. There is no automatic selection by keywords, no bypass of independent completion evaluation, no claim of completed effects from a dispatch receipt, and no forced use of the tool for complicated plans. Multi-worker, dependent, revised or continuous work retains the existing `orchestration_control` route.

The experiment adds the capability to the default *foreground* communication catalog, **not** the Qwen Q8 background worker tool list, and does not mutate installed `/etc/swaag` configuration, any resident server, production sessions or other active source worktrees. Production `/etc/swaag/voice-agent.toml` explicitly enumerates its own tools and does not automatically enable this new capability. To qualify for release, the installed foreground tool policy needs explicit review, followed by a controlled comparison on the real Coder and Q8 endpoints and physical voice tests. Do not report this test-only capability as deployed or as successful semantic speedup before completing those gates.

## Tests

`tests/test_compact_delegate.py` tests the genuine `plan.apply` handoff through a recording API boundary, one default-model worker with exact user-provided objectives, source input immutability, portable JSON Schema, rejection of malformed or unsafe inputs and refusal to execute without a bound orchestration capability. Existing tool and orchestration tests also need to pass. The full model-free suite is a separate acceptance gate from actual language understanding and natural Android speech.

## Real model acceptance, observed failure and corrected result

The first isolated live Coder-to-Q8 trial proves model selection of the small new tool: Coder selected `orchestration_delegate`, generated an action in 18.495 seconds using 169 completion tokens, and SWAAG durably created one Q8 worker. However, that worker's model-authored objective was **only a marker string**, not a complete imperative instruction. The Q8 worker legitimately treated it as an invalid instruction. The trial's full acceptance **failed**, even though the orchestrator reported queueing and the worker's lifecycle record eventually marked a terminal outcome. This is a semantic failure; it was not counted as an end-to-end pass and no production state was touched.

The capability description was revised to explicitly require a complete *imperative* worker objective, with an example contrasting an instruction such as `Reply with exactly MARKER` against a bare token. This does not auto-transform the model's chosen objective or replace semantic decisions with deterministic text handling. The second isolated live trial selected `orchestration_delegate`, generated its first action in **19.089 seconds** with 189 completion tokens, and durably created exactly one Q8 worker whose real objective was `Reply with exactly CROSS_ROLE_COMPLETE_42, without tools or files`. The worker later returned exactly the expected marker, the durable plan and worker reached completion and the independent isolated harness **passed**. Foreground final reply took **85.5 seconds**, total worker completion and foreground took **124.352 seconds**. Four independent completion-evidence model calls dominated the remaining foreground latency. One corrected live success does not establish robust semantic reliability or real-time voice quality.

Before the revised guidance, the entire offline test run recorded **1,518 passed, 3 skipped, one failure** involving `test_peer_reader_still_rejects_same_size_external_tampering`. That individual test passed when immediately rerun with the ten compact-delegation focused cases (**11 passed**), suggesting a non-deterministic interaction that requires investigation rather than an assertion of a clean suite. The post-guidance full-suite run is a separate release gate. No Android/physical microphone, continuous duplex or remote-VPN acceptance was obtained.

The new tool is deliberately not installed or enabled in the production `/etc/swaag/voice-agent.toml` tool-policy list. These trials used an isolated configuration including the new foreground capability and private model-inference histories, so the deployed voice agent remains unchanged. The experiment is not an automatic or keyword-based planner and should not be released without full current-revision tests and more varied live natural-language holdouts.

## Final isolated source qualification and unbiased live trial

After the imperative-worker-objective clarification, the complete offline SWAAG suite finished **1,519 passed, 3 skipped, zero failures in 263.19 seconds**. Source log: `/data/tmp/swaag-compact-delegate-full-final-20261019.log`. This is a different frozen full run from the earlier transient history-tampering failure, which remains documented. The new tool does not bypass independent model completion evaluation or change worker service configuration.

A third actual-model test deliberately used the original ordinary user instruction with **no reference to the new tool's name**. Coder spontaneously selected `orchestration_delegate`; the orchestration API accepted exactly one durable worker dispatch, and Qwen3.8 Q8 subsequently completed the expected exact-marker task with no tool error. The model's first constrained action took **18.198 seconds (161 generated tokens)**. The user-facing final answer took **48.7 seconds**, and the experiment including background Q8 worker completion took **88.593 seconds**. Source: `/data/var/swaag-benchmarks/compact-delegate-natural-20261019`. These are single-task, few-run observations and not evidence of generally reliable, interactive voice behavior. At this stage the experimental branch is not installed on production; the existing user conversation, models and services remain unmodified.

The attempted rapid-path reduction is important but insufficient: even an 18-second first semantic action falls far short of near-real-time speech. Independent completion verification and natural-language worker objective quality remain the major outstanding costs. Any production activation requires a genuine broader held-out semantic test, complete Android streaming/audio testing, and a graceful rollback plan.

## Simple conversation negative holdout

A separate isolated live identity-question holdout used the unchanged real Coder model but exposed the new delegation tool in the available foreground capability index. It **did not create any worker**, as desired. However, the model's final answer omitted the explicit SWAAG identity and the test **failed** its semantic identity criterion after **74.393 seconds**. Multiple independent completion checks contributed to the delay. This finding is not a coding failure of the new delegation API, but it remains a real current voice-quality acceptance failure. The raw result is saved under `/data/var/swaag-benchmarks/compact-no-worker-20261019/`. Do not deploy the candidate or describe the user-facing voice agent as fully qualified based on the narrower successful worker-delegation trial.
