# Low-latency foreground world context — October 19, 2026

This source change follows the complete existing Infra agent guidelines, especially `agents.md`, `agents/architecture.md`, `agents/fast_user_facing_dispatch_and_preemption.md`, `agents/user_goals_and_answer_first_communication.md`, `agents/voice_turn_taking_and_priority.md`, and `gui/core/06_action_acknowledgement_and_progress.md`. The user-facing Qwen3-Coder should receive compact SWAAG identity, a truthful current global snapshot, applicable user task history/goals, and the finalized user utterance. Qwen3.8 Q8 workers remain quality-oriented and need not run as quickly. Full history and detailed capability schemas belong outside routine short foreground requests and remain available through configured discovery and exact evidence lookup.

The existing source already had staged capability discovery (`staged_discovery=true` in the installed `/etc/swaag/voice-agent.toml`) and a Coder foreground / Q8 worker split. The existing previous worktree added background snapshot refresh. This change extends the canonical snapshot to include every active plan's actual graph nodes/dependencies and every nonterminal worker's most recent *persisted* progress/status report. These facts are assembled on the background snapshot refresh path, not by an LLM inside the voice call. The full canonical snapshot stays recorded as an exact durable history event for inspection/retrieval.

The model-facing `foreground_world_view` preserves full active worker identity, objective, lifecycle, configured backend route, latest report and errors, as well as every active plan goal, revision, nodes, dependency edges, live controls, timestamped runtime supervision, configured model identities and route keys. It exposes a derived active task-goal view from explicit plan/worker objectives; it does **not** fabricate inferred personal goals or promote notes to user instructions. Relevant durable user goals and corrections still come from their independently scoped original conversation/notes contexts. Finished work is represented with an exact total/status count, a small latest-outcome index and a canonical retrieval pointer, rather than putting all terminal worker histories in each simple conversation. A user explicitly requesting full history can use the existing exact snapshot read capability. This protects the difference between a short user-facing briefing and a complete evidence corpus. Worker reports are marked worker-authored and not certified external effects.

The new projection is chosen only in the foreground communication action path when both the compact action protocol and orchestrator capability are present. Worker/action/semantic calls outside that role still use the prior exact snapshot view and independent safety contracts. The existing independent completion review and user-authority/version fences remain in place. There is **no** keyword-based router, speculative disabling of the whole verifier, automatic side-effect parsing from spoken text, change in LLM context sizes or model loading.

Baseline measurement before this change: direct Qwen3-Coder llama.cpp inference on Thor began generating text in ~0.2 seconds for a tiny prompt, with ~65 generated tokens/s for a 119-token response. A SWAAG staged-discovery foreground simple question still consumed thousands of prompt tokens, and real user-facing response varied from seconds to tens of seconds. This correction eliminates historical terminal metadata from the routine foreground prompt while retaining live worker state; reducing the remaining permanent instruction set and introducing reliable two-stage reply/dispatch remain separate semantic and latency acceptance obligations.

The implementation is not considered deployable solely because unit tests pass. Before release, check the full test suite, source prompt byte/token accounting on the actual Coder, a representative live status query, an actual worker start while the foreground speaks, and preservation of all production history and real ASR/TTS functionality. The prior Coder-to-Q8 acceptance recordings and production model routing remain authoritative.

## Verified code qualification (October 19)

The complete offline SWAAG suite against this branch passed **1,524 tests**, with **three optional skips** and no failures in 294.40 seconds (`/data/tmp/swaag-world-final-full19.log`). The focused snapshot, replay, active-goal/dependency and background-report regressions also passed, including 24 explicit prompt-view tests and 52 existing communication tests. One additional focused test for newest worker-event selection was added after full-suite test collection and passed in the separate 24-test run. Existing worker, orchestration, and replay contracts were not disabled or bypassed.

A real model Coder-to-Q8 isolated voice-operation trial with current installed model endpoints, staged capability discovery and disposable sessions passed. Coder selected tools semantically, loaded the orchestration tool on demand, started one default Q8 worker, and returned a verified foreground queue acknowledgement in **49.6 seconds**. Qwen3.8 Q8 completed the requested exact `CROSS_ROLE_COMPLETE_42` result; the complete experiment took **85.674 seconds**. Source evidence: `/data/var/swaag-benchmarks/world-full-live-20261019/live.log` and its SQLite journal/result under the same directory. Prompt token accounting of that live trial observed approximately **7,433 input tokens** for the first foreground action, with the model-facing world snapshot about **1,331 tokens**, a compact capability index about **813 tokens** and only a small `load_tools` schema at **365 tokens**. These are measured values, not a claim of adequate near-zero-latency voice response.

The experiment preserves the already-deployed background precomputation, authoritative snapshot recording, independent completion evaluation, finite-plan state and existing worker permissions. Remaining significant latency comes from a large permanent system/instruction context, the constrained action schema, and multiple Coder action/verification calls for tool-heavy work. Physical-phone/Android, full-duplex interruption, long-conversation history, and simultaneous Q8 GPU contention remain separate requirements. The model is not inherently slow; the runtime must be simplified further without losing semantics or safety.
