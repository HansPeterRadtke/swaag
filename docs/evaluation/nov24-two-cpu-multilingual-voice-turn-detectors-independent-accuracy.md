# SWAAG: two genuine local CPU end-of-turn models fail safe speech completion acceptance

**Date: 24 November 2026. Actual independent result: both candidates are REJECTED for automatic live voice turn completion despite successful, fully local CPU inference.** The models were not installed in SWAAG or the Thor gateway, and their results grant **no** authority to send messages, use tools, infer a speaker's identity, or decide if a human has finished speaking. This is a bounded **text classifier** comparison, not live speech or a full end-to-end agent demonstration. The existing gateway remained HTTP 503 because its separate dedicated classifier is missing; existing Qwen, Coder, Whisper and Jetson voice services were preserved.

## Why these two independent candidates were tested

The prior Qwen2.5-VL 3B classifier failed 10 of 35 tests and was substantially too slow: median roughly 3.3 seconds, 95th-percentile approximately 8 seconds. A different, larger Qwen3 4B model was downloaded and SHA-verified in the previous Wave67 but **a specific GPU resource reservation was DENIED**; no inference on that denied attempt was made or retried. During Wave72, the owner project researched **new, much smaller, CPU-only end-of-turn detectors** rather than interfering with existing GPU models or rewriting the denied Qwen request. A separate Raspi broker reservation of 3 GiB RAM and two logical CPU cores was granted, consumed, verified and released for each model in turn. Both tests used on-device ONNX Runtime with `CPUExecutionProvider`, **zero external inference or provider calls**, no Whisper/Phonon synthesis, no microphone, no speaker authentication, and no SWAAG agent/tool operations.

The first candidate, [Namo Turn Detector v1 Multilingual](https://huggingface.co/videosdk-live/Namo-Turn-Detector-v1-Multilingual), was anonymously downloaded at exact Hugging Face revision `59245aac1f0a0f170277ebecc32ddaea418083b4`. The source has an original Apache 2.0 `LICENSE`; the quantized ONNX file has 308,985,714 bytes and SHA-256 `67be31dac7c49abd43a277a105222c9031a0e22ac37f0e22dab395f68b318fc9`. The other public model, [FireRedChat turn detector](https://huggingface.co/FireRedTeam/FireRedChat-turn-detector), was anonymously downloaded at `1a53b2145cdac39f247a8d55922630635aadfaef`, with an Apache 2.0 model-card declaration. Its `multilingual_best_model_q8.onnx` file has 178,152,959 bytes, SHA-256 `285cafedb0263b065d83964ecc728b795bb281688b0d6525f6c7ca6cb1f756df`. FireRed's model card **only documents Chinese and English**, so the German subset below is expressly **outside its stated language support**, even though its underlying BERT tokenizer handles German tokens. We do **not** infer commercial rights from an arbitrary third-party model merely because the source is public: the publisher's Apache declaration is recorded and downstream reuse should retain relevant notices.

## Fixed benchmark before either ONNX evaluation

We used SWAAG's original source-backed, completely unchanged 35-case classifier oracle at `src/swaag/benchmark/fixtures/voice_classifier_oracle_20261104.json`, SHA-256 `929f4fd01e21a12a2535db824034699fbe6359d9ecf872d978449f291cc9a26e`. It contains **17 text turn-completion cases** (nine finished and eight unfinished) and **18 semantic interruption cases**. Both new models were evaluated **ONLY on the 17 completion cases**; the interruption cases were never sent to either model and are **not** reported as passed, failed or otherwise qualified. The normal Thor gateway needs **both** semantic completion and semantic interruption decisions with confidence, so a successful binary completion model would still not be an interchangeable production dependency.

A separate 34-case English/German synthetic holdout was authored and frozen **before any model inference** as `scripts/demos/fixtures/voice_namo_bilingual_holdout_20261124.json`, SHA-256 `f84271eb1cb110ce1fcdd6fbf129ec9bd09281c0396248a4dd9a8c888b7b9ef8`. There are 17 English examples (eight finished, nine unfinished) and 17 German (same balance), emphasizing unfinished prepositions, corrections, halfway-abandoned thoughts, completed questions and a contradictory revised folder command. These are **assistant-authored test sentences**, not owner recordings, unobserved independent human dialogue, natural pauses or a scientific test dataset. Neither model was tuned on their answers or rerun after the held-out results became known. Prediction thresholds were predeclared before inference: probability **0.50** as the ordinary decision rule, and **0.80** as an additional conservative falsification screen. The predeclared production-quality research bar required zero false early completions, zero invalid results, perfect agreement with both original and new source sets, and inference 95th percentile at most 0.30 seconds. Meeting such a text-only bar would **still not authorize** real voice or agent actions.

## Genuine model outputs and response times

These are **actual different one-use ONNX model executions**, not mocked scores or a model-card marketing statistic. The model load and non-oracle warm-up were excluded from the per-case ONNX timings. The verdict uses the normal 0.50 threshold; every invalid output or timeout is a failure, not a correct negative. Recorded values below are observed ONNX inference timings on Nitro while other workloads were present, not phone playback latency or a universal hardware service-level claim.

**False early completion is the important error:** If the user pauses after saying “Please open the…”, the assistant may mistakenly treat that fragment as finished. Namo made fourteen such errors across the 51 inputs at 0.50. FireRed improved substantially on English examples but still made four early-completion errors overall. Raising the threshold to 0.80 did not eliminate the unsafe early-completion problem for either model. Both models also missed some truly finished utterances. A model that performs well on easy complete questions cannot compensate for unsafe premature actions or an untested interruption path.

The raw result and independent verdict remain in private Nitro storage; **none** of the original one-use model requests was replayed for verification.

The FireRed run used a **different** public model, code, cache, broker lease and private one-use result. Its frozen executed source was `scripts/demos/run_isolated_firered_multilingual_cpu_once.py`, SHA-256 `81d0519d5b2c53a7df89eda437c3f48468473ae753219d2ae5dc1c5d9346ca3e`. Separate no-inference analyzer `scripts/demos/analyze_isolated_firered_multilingual_cpu_result.py` independently verified every result and aggregate and issued the same rejection. Its independent verdict file SHA-256 is `d6fe340839a48d590a3e2f46b7abf09b95dac1aaec0e0274f97434bcbb1d4ba0`. The two original result files, exact source-model checksums, download manifest, separate broker admission and release, all 51 probabilities and per-case timings reside under Nitro `/data/var/swaag-benchmarks/owner-serial-000072-20261124` in separate `namo_...` and `firered_...` private roots, inaccessible to public Git.

The fixed no-action evaluation commands require a separately granted CPU/RAM broker lease for the exact owner string, a fresh unused private output directory, explicit environment opt-in, exact Hugging Face revision and locally SHA-pinned model files, the original source oracle hash and the separately frozen holdout hash. The scripts write a unique attempt record **before any ONNX inference**, so an uncertain crash is retained and **must not be replayed**. Both experiments used the already installed CPU ONNX Runtime through a read-only existing Python environment. The source code is committed; no model weights, private audio, source recordings, tokens, Hugging Face account credentials or machine-local configuration files were committed. The only public requests were anonymous retrieval of public model weights/metadata; no private user material was sent to these repositories.

For Namo, the model publisher's quick-start uses a Hugging Face `AutoTokenizer`; the one-use runner loaded the same pinned tokenizer bytes through `tokenizers.Tokenizer.from_file` instead. A separate **read-only tokenizer comparison, not a second model inference**, confirmed that the encoded input IDs exactly matched the publisher-style AutoTokenizer for four fixed English/German examples: “Who are you?”, “I was going to”, “Wer bist du?” and “Ich wollte eigentlich”. We do **not** claim full tokenizer equivalence for all possible text or audio transcriptions. For FireRed, the README example uses `add_special_tokens=False` and 128-token padding; the separately published sample `inference_onnx.py` uses its tokenizer defaults, which may include special tokens. The one-use FireRed evaluation explicitly follows the README example with no added special tokens. That source-recipe variation is another reason not to treat its small sample as a universal accuracy benchmark; the original model source is preserved, and **neither completed one-use inference experiment was replayed with a new tokenizer recipe**.

## Release decision and next useful work

Neither model solves SWAAG's dedicated semantic turn classifier or the separate user-speaker authentication problem. The real Thor gateway remains unready with classifier HTTP 503, while the 30B Coder/27B Qwen, speech-recognition and existing Phonon services must remain operating for other projects. The guarded voice WebSocket candidate from the previous waves is source- and private-test qualified but **not deployed**. The actual Blackview SWAAG app is not installed and its physical microphone, playback, long-term network recovery, genuine multilingual spoken pauses, user liveness and resistance to replayed or cloned voices have not passed acceptance. The tests above do not demonstrate the required **real SWAAG multi-step computer task with actual permitted tools**; the prior genuine agent run exposed model/tool recovery failures and that work remains independent.

Continue targeted discovery of **license-compatible, resource-admissible, dedicated fast completion-and-interruption** classifiers, using genuinely labeled natural speech and strong negative tests. Preserve the separate Thor 4B GPU denial; this CPU work was a different independently admitted model test and is not evidence that the denied model could be run safely. A reversible manual-review-only Jetson update and Android physical acceptance must remain gated on actual dependencies and coordination with the Android worker. Intermediate technical test counts and rejections are recorded in the internal Raspi project exchange; they are not advertised as a new released product, model achievement, or owner-facing MP3 report.
