# SWAAG local turn-classifier candidate: complete real 35-case rejection

**Test date: November 24, 2026. Result: reject the tested model for live voice turn classification.** The resident local speech recognition and language models were preserved. The ordinary Thor voice gateway still reports HTTP 503 because its **dedicated classifier is not running**. A separately launched, preinstalled **Qwen2.5-VL-3B-Instruct Q4** model was evaluated, in text-only mode, using the real version-pinned SWAAG gateway's completion and interruption classifier functions and **all 35 existing source-backed cases**. This was not a model simulation, model-card benchmark, or test-file existence check. The 3B model did start and answer locally, but its accuracy and latency did not qualify it for release.

## Fixed sources, permissions, and execution

The model already existed on Thor as `Qwen2.5-VL-3B-Instruct-Q4_K_M.gguf`, 1,929,901,056 bytes, SHA-256 `d02fe9b69ad8cadbbd228e387667af66612c44bed29ffc8eb1e7caf9ac486c12`. It was loaded using Thor's existing native GPU-enabled `llama-server` binary, isolated from all installed user-facing services: new loopback listener at **127.0.0.1:14921 only**, unique private model alias, context 2,048, two CPU threads, no warm-up at startup, one parallel inference slot, and full GPU layer offload. Neither model weights nor user recordings were downloaded or uploaded.

The source classifier acceptance runner was the already published `src/swaag/benchmark/voice_classifier_acceptance.py`, SHA-256 `ed10fb53850003a463d9a01f99c06ea4daf17ddbfb55910cdb3e59522534e947`, with the existing unchanged 35-case oracle `src/swaag/benchmark/fixtures/voice_classifier_oracle_20261104.json`, SHA-256 `929f4fd01e21a12a2535db824034699fbe6359d9ecf872d978449f291cc9a26e`. The real Thor gateway source SHA-256 was `23d5206072297c5910dc3d2fb98aa7136308a5fc96471af14843df7f3130de78` and its configuration module SHA-256 `38439178736d363f73ef9d63e1162495b8f26d7c684c9b4766a9e4bcc3ed10ee`.

The test was authorized **only for transcript classification, not incoming audio or user actions**. The actual SWAAG evaluator imported the gateway's real `classify_turn_completion` and `classify_interruption` functions into a separate Python process, supplied an isolated classifier configuration pointing to the private localhost model, and left the deployed gateway config/server untouched. The evaluation script's strict parser rejects malformed JSON, timeout, missing confidence or unexpected decision. An invalid answer is **never credited as a correctly negative classification**. The fixed oracle contains 17 turn-completion cases and 18 interruption cases, with English, German, hesitation, incomplete clauses, corrections, backchannels and legitimate takeover examples.

Before model startup the Raspi resource broker **granted** a temporary Thor reservation of 4 GiB of GPU/unified memory and two CPU cores to the SWAAG project. Source tests and pin checks passed. The unique one-use marker was written **before** the first process start and model request. The model and evaluator were started only as new test-owned children, without modifying systemd units or existing model configuration. An isolated new warm-up prompt was used, distinct from all oracle cases. The actual benchmark was executed only once. On completion, both children were confirmed reaped, the localhost model listener was closed, and the broker lease was explicitly released. Existing Thor Coder, Qwen, resident Whisper ASR, voice gateway, and Jetson WebSocket services retained their original PIDs and continued running. No Android/Blackview app install, message Send, phone action, external tool, website/account change, purchase or trading operation occurred.

## Observed model results, independently checked

| Category | Tested | Passed | Invalid responses | Median response | 95th-percentile response |
| --- | ---: | ---: | ---: | ---: | ---: |
| Turn completion | 17 | **9** | 2 | 3.235 s | 8.044 s |
| Interruption | 18 | **16** | 2 | 3.476 s | 8.041 s |
| **Total** | **35** | **25** | **4** | **3.342 s** | **8.041 s** |

The worst single case took **8.044 seconds**; the gateway's source-level per-model timeout is eight seconds. Four cases had invalid responses/timeouts and were counted as failures. There were substantial false decisions in the turn-completion family: five incorrect/missing positives and three incorrect positives for examples expecting the user to keep speaking (as reflected by the source-grounded case counts). The interruption family had two failed expected-positive takeover cases, **both caused by invalid/time-limited responses**; these are the same two invalid interruption cases, not two additional errors. Importantly, these are **35 predetermined development cases**, not a statistically representative population or a biometric authentication rate.

The own isolated model reported healthy and ready after approximately **3.028 seconds** and answered its one-use non-oracle warm-up in **3.237 seconds**. The complete local start + warm-up + all benchmark cases + shutdown took **144.738 seconds**. That is benchmark-specific latency on shared Thor hardware, **not** microphone-to-voice response latency. A predeclared conservative engineering gate required all 35 cases valid/correct and at most two seconds at the 95th percentile for a candidate to advance to further **isolated** voice tests, not to production. It missed both requirements; **do not deploy, promote, or route live microphone audio to this model**.

To reproduce this **kind** of experiment on a separately approved future model candidate, start from a fresh SWAAG checkout and a newly unique private evidence root. Use the resource broker to reserve enough unified GPU memory/CPU, inspect all other active consumers, pin the exact benchmark source/fixture, and limit a separately owned model to localhost. Execute a bounded model-only benchmark with no phone or provider actions; verify every source-grounded classification, latency, tool-independent result and child-process termination. Do **not** repeat the exact one-use request/effects above or unilaterally overwrite the live gateway's classifier target. The scripts intentionally refuse an existing evidence directory and unexpected source, model, port, or listener.

## Remaining project work

A suitable fast dedicated classifier is still **not established**. Candidates must be judged on genuinely unseen, multilingual and correction-heavy speech cases, with confidence, negative-class correctness and latency measured independently. The larger already-staged Jetson 8B model may be evaluated **only** after checking resource broker admission, Xavier's heavy CPU load, existing dependencies and rollback-safe isolation. Another small locally available text-instruction model may be better than the vision-language 3B candidate tested here; do not infer from parameter count alone. Until a robust classifier and server-side authenticated speaker safeguards are accepted, live voice automation remains gated for manual review. Also outstanding: a coordinated, reversible guarded Jetson WebSocket release and actual Blackview microphone, Whisper transcription, speech playback, interruption and network-reconnect acceptance.
