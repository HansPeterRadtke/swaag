# SWAAG — prevent a superseded voice connection from invalidating new input

**Status, 24 November 2026:** Two genuine source-control race failures were independently reproduced against the **undeployed** W70 Jetson voice-server candidate and corrected in a new one-module, source-pinned W71 candidate. Four distinct **real private WebSocket server processes** then passed manual-review cancellation and reconnection tests without new model or tool actions. The new candidate is **not deployed**. The owner phone's physical microphone, live Whisper/TTS, user speaker authentication and protection against recording replay remain unverified.

## Observable failure one — predecessor control invalidated the newer microphone session

The W70 source already guarded new speech from old ASR responses and recovered persisted input revisions after a process restart. However, it now used `await run_blocking(advance_conversation_intent_epoch, ...)` in six asynchronous handlers to preserve unrelated heartbeats during slow disk writes. An old connection could start handling an accepted `draft_claim`, pause at the executor boundary, and become superseded before its background thread actually advanced the conversation's revision. When it resumed, the old control silently incremented the shared epoch **after** a newer WebSocket had started a new manual recording. The recorded newer speech was then incorrectly considered stale.

A distinct new Jetson private test used the actual `VoiceSession.control` coroutine and real `VoiceCore` atomic JSON persistence, with an explicit test-only barrier that held the old `draft_claim` **before** the executor call. It then replaced the active session, executed the new session's `begin_manual_utterance`, released the old action, and tried to persist one currently valid speech draft. The actual source began with the genuine prior saved conversation, SHA-256 `bdde160a4996a1f38e8a88366bf2bb63e6ad3a65b2ebd26687326a03158102fc`. With W70 source SHA `f3283c43a196595c4b1fade69e6f2ef0f23943dc6d0b91c5b5ab63f16c17c996`, the new session had epoch **3**, but the delayed old control advanced the global epoch to **4**. The legitimate new speech draft failed its real atomic persistence check. The original failure result, not replayed or retconned, is SHA-256 `ca9d663171a1a0e4c1ce047e40db1ec267394e7df239f6385e28af97b2e3b79a`.

The W71 candidate adds **connection ownership validation under the same per-conversation lock that advances the epoch and persists speech**. The background worker refuses to mutate state if the source connection has been closed, marked superseded, or replaced by a different active session. All six relevant asynchronous source handlers now pass their session identity and stop on a rejected advance. Early checks prevent already-obsolete input from entering `control`; additional post-await guards prevent the stale caller from proceeding with a manual recording, typed turn or semantic interruption. The one-module source is deterministically derived from exactly seven W70 source modules by `scripts/demos/prepare_isolated_voice_stale_socket_intent_owner_guard.py` and must hash to **`873e3d10e507b73d422bda818c0e03b1d03ae89c99813e479e9ea78dbe811acf`**. The six supporting source modules remain bit-for-bit identical. Its private manifest SHA-256 is `f361faa9283b55e708f4c7f590d3b0e5a90bd1eeb9aa16fe2f88876e8c6df6d0`.

The separately executed corrected source test preserved global and new-session epoch **3** despite releasing the old delayed control. The new manually captured speech draft was genuinely written as one new private JSON `draft` row, while the earlier unsubmitted speech was preserved as `superseded`. The corrected source receipt is SHA-256 `31543580fd540b432c36e760fe4de89ae21e0bbf0f5cc3aa02999a4e1072455e`. These **two tests use actual source coroutine and storage code but fake in-memory WebSocket objects**, not a real phone or network socket; the operation explicitly avoids any model/agent action.

## Observable failure two — an old socket could reach the typed-message submission boundary

The voice protocol also accepts `text_turn` with a `client_request_id` and tries to replay the *same* already-accepted turn if its original acknowledgement was lost. The code awaited an existing-turn database lookup and then called `submit_turn` directly without rechecking whether the requesting WebSocket still owned the conversation. In a separate new test, a `text_turn` arrived on the older still-active socket; its source `get_turn` lookup was delayed at a test barrier. A newer socket replaced it; the old lookup then returned a matching prior typed turn. The W70 source invoked the agent submission boundary **once after losing connection ownership**. The test explicitly replaced `submit_turn` with a **non-operational recorder**; there was **zero real remote/model/tool submission**, so this result is a source-backed *would-call* demonstration, **not** a genuine completed external tool effect. The preserved W70 failure result is SHA-256 `d6080dcfb72adede6bdcc357959a4d6fc936b5a300e1fbb598cc919f7041a09d`.

The W71 source checks connection ownership immediately **after** the asynchronous existing-turn lookup and **before** any idempotent retry crosses `submit_turn`. With a new, independent private run of that corrected source, the old socket made **zero** submission-boundary calls. The already durable typed history was retained unchanged. The result SHA-256 is `6d89895e71e811b70f326529092f625b3c462700ed0ab0e13638243a6e4d28a4`.

An intermediate W71 patch that addressed only the first source-level issue was also tested and retained privately (source SHA-256 `19fbb3169a0778c9018b0560c6f6da3a259d6498c4c7fda664ca2d45f3d88767`; result SHA-256 `ff519fbc98fd096d2a5c7efe3bc8a15f1eb7d237622e33cef21e7cd283a2ea55`). This exact private intermediate copy is **not** represented as the final qualified candidate. Its source and receipt are left intact, not overwritten, so all development steps can be independently reconstructed.

## Real private WebSocket regression checks on the final W71 source

To make sure the source-owner guard did not break already working audio input and reconnection, four **new, independent** Jetson WebSocket server processes were started from the final source SHA, each with a unique localhost port, temporary fake bearer, private conversation root, and no active model/provider/tool endpoint. Each received genuine previously generated SWAAG/Phonon PCM (fixed prior recording SHA-256 `56e81fe7050641490a634e064705673a1f6c61ee2cf46d6b09f33d8270e7fae7`), while a **separate local fake ASR relay** held then returned one controlled artificial transcript. This verifies server behavior and WebSocket control flow, **not new Whisper accuracy or owner physical microphone capture**. The real source logs and private durable history were inspected after each test. All four child processes exited and were reaped.

| New source-backed private server process | Observed behavior | Immutable real result SHA-256 |
| --- | --- | --- |
| Reconnect and start new manual recording before old ASR returns | **No stale draft** | `9324dd4e51f965554efb51284f95dd3eec17e108c97ee93006195d00973b5175` |

All four WebSocket cases used actual separate listener/connection/session processes and verified historical and new state. There were no submitted speech/tool turns, no new LLM/Whisper/TTS calls and no owner/provider actions. The two old-source failures plus two corrected-source acceptances used real asynchronous source coroutines and durable JSON, but with fake in-memory WebSocket objects. These categories are **not interchangeable**. Together, **eight** new bounded source or server-process cases were independently adjudicated.

A second independent source/disk verifier, `scripts/demos/verify_isolated_voice_socket_ownership_results.py`, read all eight immutable receipt hashes, the exact seven original and corrected source module hashes, the genuine prior saved W69 history, four actual WebSocket event logs, and the after-test private conversation files. It required the original failure pairs to show the precise negative outcome, the new source results to show the expected positive outcome, and all cases to have zero external tools or submitted text. It first encountered a read-only verification-schema assumption that treated the source-coroutine result and real WebSocket result metadata as identical. That **first read-only check failed without writing any final receipt**. The original checker revision was archived privately, then its schema compatibility was corrected. The successful independent recheck used the original immutable results **without replaying the model/source/WebSocket tests**. Its SHA-256 is **`75a6ed317dd238edf43624c5b37ada358bcc5a9c63489a95db62b3f42dc1960d`**. Pure offline unit tests additionally check that the verifier refuses altered receipts, wrong source hashes, fabricated submissions, unsafe URLs and missing audio-review restrictions.

## Remaining technical and user acceptance boundaries

For reproducibility, the W70 old-source `draft_claim` experiment was originally executed from its frozen private script SHA-256 `637a913867fa57babf0942ac9f13b5a0f5f5231b7d47772ce0cf772969f90b49`, and its separately executed typed-ACK-retry case used original private script SHA-256 `67c888275628424d9ff7d224b075075960e2bd86cdaa78c008cea6e0e884b400`. The final V2 experiment used **new, separately copied and SHA-frozen** admission scripts (`dfb3c3104385fe0d3f9530bd9772175aa0af89f707c663e127cd2682f44df8a3` for the delayed control and `605371ccea655aa8837d62cc8cbfe1ff11ae7968637af968c4d5792b4426632d` for the ACK retry). These script revisions differ in their frozen newly eligible source hash, not the actual old-source/history side effects. The original already-completed experiments were **not rerun** merely to match final published helper SHA. Their exact as-executed private scripts remain preserved with the original immutable result receipts.

The corrected source is **not deployed**. The live Jetson `jetson-voice-ws.service` still runs its earlier SHA-256 `561183f64ae76a9aa92e18b8f2a8c1192b7f9fecc7597233bb363bb64e85415f` at PID `3413413` (observed during Wave71) and remains `ready=false` while Thor's dedicated fast turn classifier health is HTTP 503. Existing Qwen/Coder/Whisper processes and other projects' dependencies must not be stopped to make room for an unqualified model. The previously denied four-billion-parameter classifier request was not retried. The Blackview XPLORE 1 physical phone does **not** currently have SWAAG `myapp.app` installed (earlier read-only ADB verification), and no phone microphone, human speech liveness, anti-recorded-voice-replay, physical playback or network reconnect acceptance occurred in these new tests. A high speaker-similarity score remains **not authorization** to execute tools.

This is a bounded correction for an **already accepted old control that resumes late** and the idempotent typed-message retry path; other event-loop action families may require further independent interleaving coverage. Actual unbounded stress/performance on multiple real clients, cross-process shared JSON storage, and a real authenticated owner speaker are outside this result. The source test guarantee is process-local. The guarded source and tests are versioned on SWAAG canonical `main`, and the private Jetson/Nitro evidence and exact one-use scripts remain in `/data/var/swaag-benchmarks/owner-serial-000071-20261124`. No user recordings, private access tokens, source transcripts or model weights are committed. No website listing, user report, MP3 or storefront action is implied.

**Next acceptance step** is a reversible guarded Jetson release only with real classifier health, idle-session/rollback gates, owner-approved device-safe Android client acceptance and genuine replay-resistant human speaker authentication. Until then the production auto-send path cannot be described as safe or complete.
