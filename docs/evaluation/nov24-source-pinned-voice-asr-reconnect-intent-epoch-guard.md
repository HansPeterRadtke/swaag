# SWAAG: confirmed and corrected late speech-result race after reconnection

**November 24, 2026. Result: the previously unreleased server candidate has a verified out-of-order speech-result bug and a separately verified, source-pinned fix.** This is a **private candidate repair**, not a release to the actual Jetson phone/voice service. An isolated real Jetson WebSocket-server process received a previously generated authentic SWAAG/Phonon voice waveform, while a **local fake ASR service deliberately delayed returning a controlled transcript**. A replacement phone-like WebSocket then began a different manual recording. With the original unreleased source, the delayed earlier result was incorrectly stored as a new **speech draft** belonging to the conversation; the running client could see unrelated old text. With the corrected source, that stale result was suppressed. No voice turn was submitted to SWAAG, no external account or user phone was changed, and no local speech/LLM model was called in these tests.

## Source-level correction and scope

The patch is reproduced by `scripts/demos/prepare_isolated_voice_asr_intent_epoch_guard.py`; it explicitly admits only the seven exact SHA-256-pinned baseline modules and writes a **new** private directory with **one changed module**, never copying anything to `/etc`, an installed systemd unit, or a user-owned source checkout. The revised server file must be exactly SHA-256 **`e0939fd23aefd11f6d3d8bfd0158508b7b2f0a4f75fb70467e67bced5d06f030`**. The original other six helper modules are byte-identical. A private manifest additionally records all original and changed hashes. Both original and corrected code are archived privately and never changed in place.

The original delayed ASR `process_final_pcm_audio` checked only its *old socket's own* generation and draft revision, plus whether the replacement had claimed a draft. A replacement's **new manual-recording start** was not reflected in that old session's own fields. Consequently the old ASR could append a speech draft **after** a newer manual recording was underway. The correction maintains a per-conversation, process-wide **new-user-intent epoch**. Ordinary idle reconnects do not advance it; explicit cancellation, draft discard/claim, text submission, beginning a new manual recording, or new detected speech do. When an asynchronous old ASR returns, its captured epoch must still match the conversation's current epoch before it can write or emit the result. This guard remains effective even after the successor WebSocket disconnects; it is therefore materially stronger than checking only the currently active replacement object's flags. Cross-conversation epochs remain separate.

The new code has its own pure, deterministic test suite and true private integration tests. Its exact source and result hashes are retained. This is **not** a proof against every possible filesystem interleaving: the current `record_draft` uses an executor and atomic JSON storage; an exotic change to the epoch in the narrow interval **after the final epoch check but during a slow storage write** could still produce a stale persisted draft before the post-write check catches it. A future source-level atomic compare-and-write with per-conversation synchronization should be tested before permitting automatic actions; do not describe this narrow fix as full concurrency correctness or as already deployed. The stale-result repair is a meaningful measured improvement, not authorization to enable unknown-speaker submission.

## Reproduction guidance and exact limitations

Read the module and checker source under SWAAG canonical `main`: `scripts/demos/verify_isolated_voice_superseded_asr_race_once.py` (original failure source), `scripts/demos/prepare_isolated_voice_asr_intent_epoch_guard.py` (exact deterministic patch), `scripts/demos/verify_isolated_voice_intent_epoch_guard_once.py` (different, real four-case corrected source), and `scripts/demos/verify_isolated_voice_epoch_real_results.py` (independent results examiner). The test tools require the original **private** source archive, already recorded PCM and prior SHA-pinned receipt, and an **unused** private destination, plus explicit environment/CLI opt-in. They are not generic model or client benchmarks. The source-checking tests can run without any private audio or Jetson service. Never replay a completed one-use private request merely to reproduce an expected checksum; create a different fixture and experiment only when separately authorized.

Earlier projects already verified real resident Whisper recognition and actual Phonon reply/audio reconnect with separate source evidence. The present exercise deliberately did **not** contact resident Whisper/Phonon, and does **not** verify an Android physical microphone, playback, user biometric speaker identity, the authentication of recorded/imitated owner speech, a fast turn classifier, or natural latency. The current live Jetson server is unchanged and still cannot be declared safe for owner-unverified automatic instructions. The Thor live voice gateway still returns HTTP 503 until a qualified dedicated turn classifier is running. The separately downloaded Qwen3-4B Q4 candidate was **not run** on November 24: the central resource broker explicitly **denied** its fresh 4 GiB GPU reservation after updated physical CUDA capacity fell below the required safety margin. No denied request was retried or rerouted, and existing shared Qwen, Coder, Whisper and owner-selected Phonon services were preserved.
