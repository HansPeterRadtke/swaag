# Canonical SWAAG voice no-action acceptance, November 20, 2026

## Exact scope and source of truth

This evaluation uses pre-existing checksum-verified public-domain recorded speech and independent Jetson/Thor model services. It is not owner voice enrollment, a physical Android test, production deployment, a TTS generation, or an authorized user command. Raw speech, exact private model responses and WebSocket credential fixtures remain in restricted host-private evidence folders and are not published. The dedicated Jetson voice WebSocket production service has not been restarted, modified or upgraded here.

**Two distinct execution boundaries are tested**, not falsely treated as one complete production system: (a) Jetson's isolated local voice WebSocket plus resident Thor Whisper and independently called **tool-free** resident Qwen text candidates, and (b) Nitro's actual **canonical SWAAG foreground orchestrator** using the recently captured **review-only** ASR text as a new, isolated input. A separate staged stream uses a previously prerecorded, inert reply to test actual PCM playback/reconnect. No evidence here proves that Jetson's production voice service sends a verified owner turn to the deployed SWAAG orchestrator and synthesizes its answer into audio.

## Canonical SWAAG runtime: first response and authority fence

The previous source branch failed to parse under declared Python 3.11 due to a multiline f-string. Its compatibility repair and the real read-only developer tool demonstration have now been safely integrated with latest `origin/main` on Nitro, tested and **pushed** to canonical GitHub `main`; no other worker's dirty main checkout was overwritten. The separate Python 3.12 process used earlier lacked `opentelemetry.context` and was an **environment dependency failure**, not a software assertion failure. Tests use the existing private Python 3.11.9 + SQLite 3.51.3 runtime without weakening the minimum SQLite requirement.

The verified first canonical `swaag ask` on the actual reviewed ASR text returned an appropriate clarification, with one successful model response, zero invoked tools, zero workers and a durable finished turn. However, direct runtime inspection showed its config's empty `tools.enabled` list and `allow_side_effect_tools=false` were silently replaced by communication-orchestrator defaults. Its model prompt contained approximately **17,387 input tokens**, including nearly six thousand tool-description tokens and over seven thousand workspace-file-manifest tokens; ~74.42 seconds model generation and ~84.61 seconds entire process. No action happened **by chance**, not because the effective orchestrator permission boundary was secure.

The repaired **explicit deny-all** configuration is accepted by the source loader, and `CommunicationService.from_runtime` now preserves zero effective exposed tools and false staged-discovery/stateful/side-effect flags when caller expressly requests `tools.enabled=[]` plus `staged_discovery=false`. An independent before/after construction probe verified both the actual effective tool inventory and permission flags. The strict new canonical `swaag ask` model call used a **fresh separate durable session**, returned a truthful clarification question with zero tool/worker starts and a finished terminal turn; reduced input to approximately **5,829 tokens**, model time ~58.32 seconds, total CLI ~65.39 seconds. It was still far too slow for interactive voice and its first token appeared after ~21.17 seconds. One before/after observation with different output lengths is not a statistical causal latency guarantee. The hard permission repair never reroutes normal nonempty production tool configurations.

## Verification and remaining quality limits

The tool-free configuration loader and core agent tests passed **224** targeted cases. The strict canonical no-action authority guard passed the new construction tests and an actual single live model turn, while ordinary nonempty production settings retained their intended tool registry. The additional queued-voice cancellation race uses the exact durable control status, including canceled receipts, so it cannot falsely claim that a processed or absent control was withdrawn. The first affected communication/history/preemption regression group completed with **230 passes and no failures**; final incremental acceptance and publication should be recorded from its actual logs and remote revision, not inferred from a successful subprocess launch.

A separate real-input **silent PCM** regression passed: existing resident Whisper produced an empty transcript, zero durable user turns and returned to listening. Nineteen offline ASR-outage/retry and complete-stream parser tests passed, with five explicit optional live cases skipped. These supplement, but do not replace, real mixed-speaker and clean-speech acceptance. The faster standalone Qwen tool-free candidate used a tiny purpose-scoped prompt and is **not** the same performance or authority as the canonical SWAAG orchestrator.

## Remaining work

The main production gap is still the **actual authenticated owner speech → verified speaker/semantic end-of-turn → canonical orchestrator answer → live generated TTS → Android playback** integration, across multiple realistic recorded utterances, interruptions, corrections, simultaneous load and safe reconnection. Speaker authentication is not proven; the semantic turn classifier is not release-accepted; partial words and recorded misrecognitions still require owner correction; live server runs older source; physical phone acceptance was not authorized/completed. Full production reliability is **not** demonstrated by these isolated checks. Do not rerun a denied lost-ACK physical test, silently interpret an unverified voice as authorization, or treat a successful model answer as evidence that an action executed.
