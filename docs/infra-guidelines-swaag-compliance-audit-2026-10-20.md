# SWAAG versus the complete Infra guideline corpus — engineering audit

**Audit date and host:** October 20, 2026; NVIDIA Thor. **Infra baseline:** `04a46a7d4d88b1f763680fed8148b25cfce24912`. **SWAAG source baseline:** `a8f4f9f5bc7e55ad50be75b543efb4fe5827ada9`. All results here concern the source checkout and isolated test state. The running SWAAG communication service and active Qwen3.8 workers were **not** restarted, cancelled, migrated or altered by this audit.

## Coverage, boundaries, and what “complete” means

The source inventory `/data/var/swaag-audit/2026-10-20/guidelines-source-complete-inventory.json`, generated by `complete_guideline_repo_inventory.py` in that directory, read every tracked source path in the requested scope, computed its SHA-256 and size, parsed Markdown section headings, and parsed all tracked `src/swaag/**/*.py` modules with Python AST. The trace covers **250 Infra paths** (all tracked `docs/guidlines/` files plus root `AGENTS.md` and `README.md`), **5,199,820 bytes**, including **169 original-preservation/source files**, and **454 tracked SWAAG repository paths**, **7,974,041 bytes**, including **166 Python modules**, **2,129 parsed functions** and **330 classes**. There were **zero read or AST errors**. All original guideline/recording source files are unmodified.

This is exhaustive **file-level inventory and mechanical read coverage**, not a claim of exhaustive semantic verification of 2,129 methods, all branches, every historical original recording or all end-to-end product variants. Meaningful requirements were cross-checked using the canonical derived guidance and prior complete-recording audit (`docs/guideline-comparison-2026-10-15.md`) and targeted inspection of the current code. As required by Infra, an implemented mechanism, unit-test result, or tracked guide cannot be represented as a verified effect that has not been observed. A positive source-level regression does not substitute for physical Android/audio, live-workload or operating-system isolation acceptance.

The Infra guide itself distinguishes **requirements**, **options for experiments**, **illustrative examples** and **domain-specific project requirements**. We did not incorrectly convert proposed robot algorithms, investment backtests, GUI layouts for unrelated apps, or optional model topologies into mandatory generic SWAAG runtime features. The domain-specific bodies remain relevant when SWAAG actually works on those domains, and the cross-cutting testing, provenance, safety, context, memory and resource requirements still apply.

## Code and test work performed here

New source `src/swaag/fast_authority_context.py` supplies scoped, exact user/user-wide durable policies and lower-trust goal notes to the constrained Coder foreground when within configured budgets, eliminating unnecessary slow fallback. `src/swaag/config.py`, `src/swaag/assets/defaults.toml` and config parameter descriptions now define and validate those budgets. `src/swaag/communication.py` repairs old receipt journal scans and the contradictory core policy. `src/swaag/foreground_fast.py` uses the admitted context without changing the user message or tool grants. Tests `test_fast_policy_context.py`, `test_orchestrator_indexed_receipt_replay.py`, `test_fast_foreground_reply.py` and `test_control_authority.py` verify these changes and both negative and positive cases. Existing streaming tests protect receipt/delivery semantics.

An initial focused package of affected suites had **40 passing tests**. A later policy suite expanded to verify real loader validation, authority order, modified core-policy content, transcript and result integrity, and policy/notes changing during in-flight inference. The latter forces a return to the full controller rather than committing a stale fast answer. A read-only exception from the optional fast-stage policy database now also returns to the authoritative controller, rather than terminating the user turn solely because the shortcut failed. The full controller may still report a real underlying policy-store fault instead of silently ignoring authority. This is verified with an injected SQLite failure. To save fixed-prompt tokens safely, the two built-in orchestration-only policy documents are omitted from the short prompt **only when their exact versioned content SHA-256 digests and source authority match reviewed values**; unknown or modified policies are included or trigger the complete-context fallback. The initial package had forty tests. The expanded policy suite subsequently reached **fifteen passing tests**, with controlled global policy-update, note-update, content-digest, invalid configuration and SQLite-failure cases; the final integrated count is given in the full regression result. Remaining tests are reported in the final full-suite log. The source was then exercised on the *actual configured Qwen3-Coder backend*, with isolated session/global stores: a German answer policy produced a German identity answer in one model call; a warehouse goal note produced the correct goal answer; an action-only shell policy was not injected into an unrelated plain-language decorator question. Measured isolated wall times were approximately **16.17, 6.94 and 13.51 seconds**, respectively. First-audio Android latency was **not measured** in these tests. The actual generation speed and GPU contention remain dominant latency factors; reduction of Python bookkeeping does not erase LLM inference time.

Additional evidence: `/data/var/swaag-audit/2026-10-20/fast_policy_real_coder_audit.log` and the reproducible input script alongside it; source inventory and full regression logs in the same audit folder. The test and source code belong to the isolated worktree until after final full verification and a deliberate fast-forward merge. No device service/model restart is necessary for these source-level audits.

## Release decision and known residual obligations

**Do not declare every guideline fully satisfied or activate a risky runtime change blindly.** A completed audit must distinguish present code mechanisms, observed test behavior, known semantic errors, optional research and genuinely unsupported deployment features. The most significant residual risks are: reliable relevance/supersession across very old exact history; typed goal lifecycle and context selection; real microphone-to-speaker timing and interruption; worker long-duration true progress; shared-model scheduling/slot release under contention; cross-host resource quotas and operational retention; and independent heldout quality measurements of natural-language task classification. Many domain/project-specific requirements apply to products controlled by SWAAG rather than to the SWAAG core.

After a clean full-suite pass, source can be committed and fast-forwarded into the main SWAAG checkout. The idle-safe activation timer for Thor has its own exact source revision pin and must only be repointed after verified merge. **A continuing Qwen3.8 worker blocks restarting the SWAAG communication process.** The timer may activate the tested code automatically when the main orchestration state is idle, but production behavior must never be claimed before that restart is verified.
