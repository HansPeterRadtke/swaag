## Corrections integrated against current main, not old checkout

At this stage `main` already contained important subsequent changes: a worker inference output ceiling to avoid open-ended generations, exact native llama.cpp backend-slot observability, deterministic cleanup of phantom supervision sessions after foreground turns, and avoiding repetition of terminal process output in model context. The earlier audit patch was **cherry-picked onto that later source**, preserving the newer fixes and their tests. It did not replace model weights, force-stop live workers, delete histories or alter other machines.

The extra corrections address actual failures found in source and real Coder trials:

* **Durable user scope and goal notes in fast speech.** Applicable session/user-wide trusted policies, revision/authority/provenance, and exact bounded user notes are now available to one small Coder call, instead of forcing the full multi-call orchestrator whenever any durable user fact exists. The exact governing source is never partially truncated. A new or modified core policy must match its reviewed identity and SHA-256 before omission from the small role prompt; learned-model pseudo-policies are not silently elevated to system authority. A change during inference invalidates the old quick reply. The full controller takes over on missing authority, database failure or size overflow.
* **First speech and side-effect receipts.** A stale embedded SWAAG role policy claimed that the acknowledgement only appeared after successful tool receipts. The versioned v6 policy instead distinguishes a committed *intention* from started work, queued worker controls, actual tool results, and postcondition verification; existing user-authored durable policies survive migration. Deep work, tool permission and replay remain solely the authoritative orchestrator's responsibility.
* **Indexed durable replay.** A processed user receipt previously forced an all-event history materialization, including large model prompts and tool output. The replacement uses indexed source lifecycle events, preserves exact old control identity, supersession and resumed effects, and passes a regression that forbids reloading the entire journal. This is an actual performance/correctness improvement, not removal of audit evidence.
* **Fast-state grounding.** The first model context now places recent exact dialogue (with *unverified* prior-assistant claims labeled) before the fresh timestamped worker-state facts, keeping the authoritative current user wording last. A read-only worker fact anchor is generated from all active workers. A real Thor test had initially reproduced an erroneous model claim that a still-working warehouse worker had stopped, caused by a contradictory earlier assistant message. The reordered evidence fixed that observed example; a narrow deterministic contradiction guard now conservatively delegates rather than speak a false completed-worker claim if the model repeats it. This is not a general guarantee against all LLM hallucination.
* **Evidence-safe quick audio.** Real model testing found false `I can hear you` claims from finalized *text* input, premature `Stopping all tasks` effect language, and refusals asking the user to provide repository files that SWAAG's full controller can retrieve. The new bounded evidence guard repairs the known text-only microphone question from observed message receipt, prevents unsupported completed/ongoing actions before tools execute, and passes missing-evidence work to the full controller. It preserves safe future intentions. A recognized exact number of words can be independently counted to complete the simple answer without a second inference, otherwise strict constraints delegate. These are output-contract checks, not a replacement for semantic user-intent classification.
* **Configuration and performance bounds.** All important fast communication admission thresholds are now named and validated in TOML: maximum input tokens, exact current message characters, recent whole messages, bounded exact history characters, worker-snapshot age in seconds, minimum/desired structured-output tokens, user-policy characters and goal-note characters. Cross-setting output reservations reject contradictions. The default fast input cap is four thousand and ninety-six measured tokens, with conservative fallback to the full controller; exact current messages and user policies are never sliced to fit. Semantic units, risks, defaults and source precedence appear in configuration metadata. Fast output defaults to concise spoken prose without lists, identifiers or social filler, except requested exact/machine formats.

Fast-response generated speech is subjected to a narrow evidence-only consistency gate: quoted/machine text is not a tool call, a finalized text message is not proof of microphone or audio playback, a delegated intent cannot honestly report work already performed, and a fresh `working` worker cannot be described as stopped. A mechanically recognizable exact word count can be verified without another model. The guard is conservative, can delegate an ambiguous answer, and **cannot certify all arbitrary model claims**. The latest real Coder evaluation contained twenty-four new routing scenarios; all twenty-four were classified into the expected direct/deep paths, but qualitative review exposed the unsupported claims which motivated these guards. Those twenty-four cases were thereafter development data, not untouched validation.

The fast system description now explicitly distinguishes durable control acceptance, executed tool results and independently observed requested effects. It labels precedence: current user corrections, trusted observed current state, past assistant statements, and model-authored worker reports. A fresh state snapshot proves its own observation time and content, not audio playback or successful outside-world changes.

## Evidence

The unmodified later-main integration completed its full deterministic regression suite with **1,593 passing tests and three skipped**. Later revisions were individually tested against focused suites for policy/database failures, precise configuration boundaries, receipt replay, worker status and source-quality claims. An isolated new twenty-four-case Coder semantic evaluation scored **twenty-four of twenty-four expected `answer`/`delegate` choices** on its first run. That result alone was insufficient: reviewing *actual text*, not just mode, uncovered unsupported microphone assertions, action-completion wording and unnecessary requests for user-supplied files, which were then corrected. That case set became development/evaluation data after changes; it must not be called untouched independent final acceptance. The further adversarial worker-state test specifically caught the model accepting a false older assistant claim that a current `working` worker had stopped, despite fresh contradictory facts. Reordering exact dialogue before fresh state and appending an observed active-worker anchor yielded a correct real-model answer in a repeated targeted trial. The narrow contradiction guard now conservatively delegates an obviously conflicting model response rather than report an unsupported status. Neither prompt ordering nor that guard proves universal LLM grounding. Runtime artifacts, real model replies and test logs are retained under `/data/var/swaag-audit/2026-10-21-*`.

The current source's complete final regression must be rerun after all changes. A passing deterministic regression does not prove phone microphone-to-speaker quality, actual external effects or arbitrary semantic routing. Do not describe code as deployed until the process PID/revision, installed profile and actual service health confirm restart.

## Requirements that still need distinct independent proof

The Infra requirement for **correct relevance selection from very old exact history** is only partially satisfied. SWAAG preserves old history and retrieves/semantically selects portions on demand or when context overflows, but an always-good semantic selection independent of the final model's ability is not provable by a fixed recent-message window. Full instruction provenance and relevant notes improve high-recall context but do not establish automatic full goal-memory lifecycle, user-scope supersession, long-distance discourse or correct interpretation of every historical negation. Those deserve independent adversarial, untrained holdout experiments, not a general-purpose regex router or silent deletion.

UI-local action acknowledgement within a frame, VAD/STT end-of-turn semantics, natural interruptions, physical Android audio playback and genuine first-sound latency require live device verification. A separate concurrent Thor/Jetson/Nitro integration has now proved a successful Android **emulator** foreground-voice-service/AudioTrack chain and observed streamed audio under background/rebind conditions. Its measured server speech path improved from roughly forty-eight to eleven seconds, with first valid audio improving from roughly forty-seven to ten seconds on the same fixture. This is genuine emulator/audio evidence, not a physical-phone test or a guarantee that interruptions and reconnects work in all cases. Shared GPU and queue scheduling correctness must be measured under both Coder and Qwen3.8 Q8 contention and under injected errors; a backend heartbeat is activity evidence, never automatic success. Any outstanding questions, progress percentages or ETAs must be shown only with genuine state and explicit progress observations; an intentionally continuous task never has a fabricated completion percentage. Likewise, OS sandbox hardening, cross-host file/resource quotas, logging retention and resource usage of long-lived helper processes require host-level evidence. Thor's `/data` storage was **ninety-eight percent utilized**, with roughly **twenty-five GiB free**. The largest allocated area was deployed model weights and the user-data corpus; no model/history evidence was deleted merely to make a metric look better.

No design can truthfully certify perfect semantic behavior for arbitrary natural language or all possible hardware/network failures. The release gate is concrete: source integration, regression and measured heldout behavior, durable correctness under replay/correction, current model route verification, noninterference with active workers, and observed working service; any unverified area remains explicitly open.
