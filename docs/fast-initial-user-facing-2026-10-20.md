# Fast first user-facing response and independent deep SWAAG execution

Date: October 20, 2026. Thor. Source branch `fix/fast-conversation-20261020`.

## What this changes

The existing production foreground was still slow even after eliminating the second verifier for tool-free replies. A full orchestrator action prompt consumed about **6,466 input tokens** on an empty state. An ordinary identity reply took around **22.2 seconds**, despite requiring only one semantic reply; an explicit calculator request required four subsequent action/reviewer calls and did not speak its first acknowledgement until roughly **30 seconds**. The core Coder and the worker Qwen3.8 Q8 run on different model endpoints but share physical GPU resources.

`communication.fast_initial_reply` is an **independent opt-in switch, disabled in library defaults**. The accepted finalized user receipt is persisted immediately, and one small constrained Coder operation produces `{mode: answer|delegate, reply: text}` using trusted short SWAAG identity/backend facts, the complete unchanged current user message, and a bounded number of the most recent **whole, exact** conversation messages. It also discloses how many prior conversation messages remain available only to the full orchestrator. Any ambiguity or need for more context must be delegated. The separate model has **no tools and no authority to perform a side effect**.

An eligible self-contained conversation answer is durably committed as the ordinary orchestrator turn, with `control_message_processed` and `turn_finished`; only one LLM inference occurs. In the delegated case, the first user-facing reply is durably recorded against the exact pending receipt and emitted as an `assistant_progress` stream event before the full controller is called. The main controller then receives the untouched full user request, context, tools, constraints, corrections, and durable control fences. The accepted acknowledgement is already available for TTS while worker/tool planning or execution continues. Fast acknowledgement does not say a tool has run or a worker has started; final outcomes and failures still appear through the existing reply/failure path. Reconnect/replay uses the same receipt and cursor, without repeating completed side effects or rewriting the authoritative original.

Prompt-instruction stores, explicit session instructions, durable notes, open questions, pending deferred tasks and attachments are **not silently dropped** to make the quick prompt smaller. The quick stage declines such tasks and the full controller is used. The transcript is never shortened: a long message bypasses the quick step, and earlier conversation history remains exact and fully accessible to deep processing. A generated `mode=answer` accompanied by a promise to check, start, investigate or execute is demoted to `delegate`: the model's own incomplete answer cannot be treated as verified completion.

The voice gateway already consumes committed SWAAG progress and starts streaming TTS on the first such event, with audio delivery and deep execution concurrent. No additional Android or voice-side reasoning authority is introduced.

## Actual model measurements and limits

- A live canonical isolated orchestration identity request, using the installed Coder and current Thor GPU workload, completed with **one constrained model inference**, **991 prompt tokens**, and **about 6.55 seconds wall time**, including about **2.28 seconds** to the model's first generated token. Answer: the assistant correctly identified itself as SWAAG. An earlier full-action baseline used about 6,466 prompt tokens and took around 22.2 seconds for a similarly short identity question. These are not a paired under-identical-load statistical benchmark.
- A live actual calculator task emitted the first spoken progress message **3.69 seconds after receipt**, before the model selected or executed its first tool. The exact end-to-end task took **about 90.6 seconds** with five total LLM calls, including the one fast model call. Its first deep action alone took about 27.9 seconds. Deep call count and task correctness are separate from first-speech latency; the final verified calculator result was forty-two.
- The existing dedicated voice-transport and committed-speech tests passed **25** cases, demonstrating that an early committed SWAAG event can start TTS without waiting for final inference, while preserving durability and failure signaling. This is not a physical Android microphone-to-speaker acceptance test.
- An earlier four-case two-field fast classifier skipped a requested calculator tool and therefore was **rejected**. A more explicit prompt passed the calculator and mixed-command cases, with one false-positive delegation in twenty-four candidate inputs and a truncated JSON generation requiring fallback. The complete production-shaped helper was then tested on sixteen varied real-model inputs. It revealed two overconfident `answer` decisions: an exact seven-word reply (which actually fulfilled the exact output) and a promise to check live worker status (which did **not** fulfill the request). The latter demonstrated why the consistency check and conservative fallback are required. Zero misrouted tasks is not guaranteed on arbitrary natural language; the model remains fallible. Do not claim otherwise.

## Safety and test contract

The change is deliberately optional until source regression, live model semantic routing, replay/interrupt/failure recovery and production release are confirmed. New deterministic tests cover single-call identity responses, durable direct-turn reconstruction, quick speech before the deep model and tool, no side effects before the authoritative full controller, exact original user request, change-of-mind while the quick inference is still in flight, invalid quick output fallback, shared and per-session user policy, a false `answer` that merely promises to check, hundreds of earlier conversation messages, real-sized latest message lengths, and quick event replay without redundant generation.

A quick semantic `answer` is not independently LLM-reviewed. Its verification scope is explicitly `fast_foreground_unreviewed`. Strict verifiable effects, unknown live state, task mutations, privacy-sensitive operations and incomplete context must continue to the full authority; having a fast reply is not evidence the user heard it, and accepted control is not a completed external operation. Any source release must preserve current active Qwen3.8 workers and model servers. A SWAAG process restart is required for the running Python service to import the updated code; changing the repository or profile alone does not hot-reload the resident runtime. Restart only when worker/process liveness and outstanding effects make it safe.

## Configuration / rollback

The two existing flags `communication.single_pass_direct_replies` and `communication.early_tool_acknowledgement` remain independent. The additional `communication.fast_initial_reply=true` enables the new short first-stage response. The library default is false. Turn it back off and restart only SWAAG in a verified safe window to return to the previously deployed full-action path; preserve the original source and all history. The Coder and Qwen3.8 model servers are separate, are not replaced, and must not be stopped for this change.
