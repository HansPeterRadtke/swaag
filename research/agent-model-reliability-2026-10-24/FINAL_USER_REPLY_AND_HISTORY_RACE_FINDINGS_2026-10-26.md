## Separately exposed JSONL history-read race

A first streaming run using the same immutable 23-case inputs **aborted at `s12` candidate** with `HistoryCorruptionError: Invalid history JSON at line 4` while `OrchestratorEventCursor.caught_up()` called `HistoryStore.has_history_at_or_after()`. That initial run had no append-only result journal, so **no aggregate scores were claimed from it**. Its temporary file no longer exists, and the exact transient root cause of that one occurrence is not independently provable. It was a local, synthetic, isolated session with no external effect, not a real user or production failure. A new **versioned** complete attempt used per-case `fsync`-persisted receipts and strict source/case hash checks; all 46 paired cells then completed. No uncertain or denied real-world effect was repeated.

A separate **deterministic fault injection** into the unmodified `src/swaag/history.py` proves a compatible reader/writer window. The writer's appending UTF-8 JSONL event was intentionally split into two parts inside a temporary session. A separate reader observed `HistoryCorruptionError` while the final JSON line was incomplete; after the writer completed the exact same append, the reader recovered and the entire event hash chain validated. Source `history.py` SHA-256 was `74ede3f4b58bf387ffc6a9478c8fdc0b56f6b48cc042f0f69a5bfd6e2486516a`. The relevant code writes `complete_history.jsonl` before committing the parallel SQLite event and `_ensure_session_indexed()` can scan JSONL without synchronizing with that in-progress append. The injected race is evidence of a missing observation boundary, **not proof that the first spontaneous error was caused by that exact interleaving, nor a measure of spontaneous incidence**. Reproduction and source-hash proof are in `probe_history_partial_append_20261026.py` and `evidence/final-foreground-receipts/history_partial_append_v1.json`.

**Safe next engineering work:** Add concurrent writer/reader acceptance with SQLite commit-snapshot or shared/exclusive file locking as appropriate while retaining tamper detection, exact event-chain checks and crash recovery. Do not paper over genuine malformed/forged history with a generic JSON parse retry. Reproduce a genuine concurrent interleaving against the chosen fix and rerun streaming/control-id receipt tests before touching installed services. No production history implementation was modified during this research round.
