# External task-relevance reference benchmark — preregistered 2026-10-25

Purpose: supplement authentic SWAAG engineering-report relevance studies with **independently sourced public question-document pairs**, explicitly separating source-provided labels from independently audited human judgments. This is a fixed external *development* set, **not a new unseen final holdout** once model responses are inspected, and not direct live SWAAG worker tasks. Frozen before any new Qwen calls.

## Raw origin and provenance failure mode

Source: Stanford FutureData ARES repository's public `datasets/example_files/nq_labeled_output.tsv`, https://github.com/stanford-futuredata/ARES/ and https://raw.githubusercontent.com/stanford-futuredata/ARES/main/datasets/example_files/nq_labeled_output.tsv. Exact original 39,777,701 bytes, SHA-256 `649321a57e4dfe404d43c9ecb2443889b89cdff12e5ec62cca04cc42602bf236`, stored only under Nitro's private temporary path outside source control; it is **not** downloaded to Thor. This file parses as **6,189** rows; 2,653 contain Context_Relevance_Label `1.0`, 1,768 contain `0.0`, and 1,768 have blank context relevance. The latter 1,768 include repeats of question/document pairs with a defined positive label but different answer fields. The demo uses source-supplied relevance labels and a mixed/generated evaluation structure; the original annotation method and human validation of **every labeled row** have *not* been independently established. Therefore the original claim that the entire file is human adjudicated is **unsupported**. Treat the labels only as external reference judgments with possible label noise. The ARES paper uses human annotations for calibrated evaluation but that does not certify each row of this demonstration file; see Saad-Falcon et al., NAACL 2024, https://aclanthology.org/2024.naacl-long.20/.

## Frozen balanced reference extraction

The source-processing script `sample_ares_reference.py` verifies the entire TSV checksum before parsing. It excludes unlabelled rows and filters queries between twelve and 175 characters, with three or more ordinary word tokens, and **complete untouched passages** of 120 to 1,350 characters. It chooses one positive passage and, for each original question with both classes, the negative passage having the most query-token overlap. Queries are stratified by this negative overlap into three groups and exactly eight queries are sampled from each by seeded selection. Each of twenty-four natural question texts has one full label-one passage and one label-zero passage: **forty-eight examples**. The complete source text, record index and individual paragraph SHA-256 are frozen in `ares_nq_reference_v1.json`. It is not a natural-frequency sampling distribution: the balanced classes, overlap stratification and minimum passage lengths make it especially inappropriate to use its mean as overall prevalence in SWAAG or ARES systems. Other domains, longer passages, actual tool results and user goals require their own study.

## Locked inference matrix

For each source query/document pair, ask the *currently loaded* local Qwen3-Coder Q4 and Qwen3.8 Q8 for a relevance score on an ordered nine-level scale. The rubric, question and complete passage are exactly the same; only the single output instruction and constrained output type changes between (a) integer zero-to-eight and (b) ordered textual enum names. Temperature zero, seed seventeen, thinking disabled, maximum forty-five output tokens, strict JSON schema, and top-p one. Per-item model/format exposure order is pre-shuffled using the fixed October twenty-fifth seed. The complete matrix is forty-eight source judgments times four model/encoding combinations = **192 calls**, but each tool invocation is capped to twelve and must stop at the first non-idle admission or uncertain output. No inference is made without zero active SWAAG requests, zero pending production workers, fresh supervisor evidence for **both** model endpoints, two idle native slots and existing host reserve. GPU and disk/owner activity supersede research. No model loading, restarts or modifications to production state.

Preregistered evaluation metrics: schema validity; binary concordance with the external label using `score >= 5`; sensitivity, specificity and balanced accuracy when denominators exist; ordinal score distribution, fraction of equal-score label-opposite pairs, within-query positive-over-negative score fraction (treat ties separately), and same-model same-query/doc numeric/text disagreement; full response wall latency, prompt and generated tokens and missing/censored-cell counts. **Never pool across unpaired model/encoding samples to claim one format wins**. No chance-adjusted human-rater statistics are justified because these demo labels have unverified human provenance. “Score” is an ordered task judgment, not a probability of truth. The two Qwen endpoints use *different architectures and quantizations*, so no pure precision conclusion is available.

Independent SWAAG task-context and downstream-call results remain under `CONTEXT_GROUNDING_PROTOCOL_2026-10-24.md` and `evidence/context-grounding/`; the ARES reference work cannot replace them. Prior synthetic source reasoning and local small-model decomposition failures stay in their original ledgers, not silently rescored. Raw results must be append-only, record request complete role/content plus runtime/schema/seed/usage/admission and return exact Qwen output, and be transported back without changing previous bytes. Unknown model effects remain unknown, not replayed.

## Further independent primary context

The official NIST TREC Deep Learning 2019 passage judgments distinguish *related to the same topic* from evidence that **actually answers** a question (a level-one passage is expressly not relevant for binary question-answer relevance): https://trec.nist.gov/data/deep2019.html. ARES separates context relevance, answer faithfulness and answer relevance and applies prediction-powered inference to reduce human-label cost: https://aclanthology.org/2024.naacl-long.20/. CheckEval (Lee et al., EMNLP 2025) finds more robust evaluation in its tasks from explicit checklists of binary attributes rather than broad subjective Likert judgments; this is a **different hypothesis** from text-versus-integer encodings of one ordinal scale: https://aclanthology.org/2025.emnlp-main.796/. Lee et al. (COLING 2025) document inter-scale and self-consistency issues across judge models: https://aclanthology.org/2025.coling-main.710/. Together these justify making relevance *purpose-grounded and externally validated*, not choosing a textual/numeric field because it looks natural.
