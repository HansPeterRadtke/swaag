# SWAAG agent relevance and reliability — original source → real tool → final speech/state → restart, round nine

**October 27, 2026, Nitro research worktree; overall owner research remains PARTIAL.** The owner asked for a **complete, measurable real source-to-target roundtrip under original task constraints**, preserving source version, persistent state, identity and final result rather than counting intermediate JSON or model-vote ratings. The exact controlled original-file experiment and outcome acceptance gates were preregistered before the run in `ORIGINAL_DOC_ROUNDTRIP_PROTOCOL_2026-10-27.md`. The actual installed/hosted Qwen specialist + reviewer GPU calls were **not** run; prior Thor multi-call/data-transfer permissions were denied, and this research does not repeat or reroute them. The only live process operations were passive host resource checks; no production model/worker/scheduler/Google/Youtube file or service was modified.

## Original research hypotheses and verified prior limits

1. **Role-conditioned relevance:** User-facing explanation, worker action and orchestration need different evidence/constraints, including the current user request and later overrides. Existing 64 context-labelled SWAAG pairs from 29 original project excerpts show at least eleven investigator-labelled role-dependent flips, but independent human relevance gold is absent. A previous actual SWAAG **foreground harness** test with scripted outputs showed 12/23 unsupported terminal answers versus 1/23 under an in-process candidate guard, with 24 versus 37 *fake-model* calls. It was not Qwen quality data; most extra safe fallback answers did not complete the user task. The last read-only cross-genre source-ranking test used real BEIR NFCorpus citation-derived grades: on 323 test queries, BM25 graded nDCG@10 **0.3081**, TF-IDF **0.2946**, RRF **0.3054**, query-blind hash control **0.0131**; BM25 retrieved 150/576 strong-grade citation links within its top-ten list. Those are relevant-source **navigation outcomes**, not verified scientific entailment or owner worker effects.
2. **Numeric versus ordered textual ratings:** Five same-task/model/source/role/seed Qwen pairs both exactly matched 3/5 single-researcher ordinal anchors; summed ordinal errors 10 (numeric) versus 16 (text), not independently adjudicated. No winner or calibrated probability of truth.
3. **Direct versus model selector/reviewer:** Six matched original Qwen questions had complete direct answers at **5,593 tokens/20.874 seconds** total, versus **5,600 tokens/21.827 seconds for source-selector stage one alone**, with zero second-stage final answers. On 209 separate independent expert-labelled scientific claim/paper controls, two CPU lexical reviewer classifiers agreed and were both wrong in 103 cases; a reviewer override fixed nine original mistakes and introduced ten new ones. These are not new real-Qwen results or an end-to-end reviewer-cost estimate. In a separately externally graded real-software-task reanalysis, post-output escalation sometimes rescued original tasks and sometimes overwrote correct answers, but per-task GPU cost is not in the source.
4. **Training-time syntax auxiliary loss:** Published controlled studies show some syntax-specific gains and some regressions, but no paired modern-Qwen training FLOPs/data/initial-weights study has been run. This round neither trains a model nor substitutes syntactic prompting for actual training.

**Conservative operational decision unchanged:** One capable initial user-facing call, exact original source/revision/time and applicable user authority, independently verified effects for costly work; no unconditional reviewer or extra semantic selector ahead of the spoken first result. This is a provisional workflow, not a proven optimal routing policy.

## Verified complete code path and saved-state result

The tests exercised **real** `AgentRuntime`, `CommunicationService.iter_orchestrator_message`, `read_file` tool execution, file-reading environment, actual append-only event history and SQLite indexing, final streamed `accepted → assistant_progress → completed` output, tool-event provenance, and durable `turn_finished`/`control_message_processed` receipts. The model outputs were fixed scripted `FakeModelClient` responses with a source-containing final-prompt assertion, **not actual model inference**. All service sessions/tools and source copies lived in temporary directories, never in production owner workspace paths.

**Observed results:** The source-backed arm completed **2/2** versioned tasks with exact source-correct final answers, **2/2 actual `read_file` calls/results and `filesystem_read` source events**, full byte-exact document content delivered to the model and original tool source-event lineage in the follow-up prompt. The old source produced “No. The specified source revision does not contain the October 26 journal-lock follow-up.” The newer source produced “Yes. The specified source revision contains the October 26 per-session journal-lock follow-up.” Every result was scored against the frozen immutable original Git file, not against the scripted model's confidence.

There were **6 fake model requests** total for the two grounded source tasks: per turn, one initial delegated speech response, one `agent_action` executing **the real `read_file` tool**, and one final answer. Total wall for these two complete flows was **9.875 seconds** on an occupied Nitro, with **15,244 whitespace-delimited prompt words** passed to the fake tokenizer/accounting. These are end-to-end **harness** work and prompt-length proxies, not Qwen tokens or GPU-generated answer latency.

Crucially, the actual persistence/identity sequence was exercised **across two service restarts** with the same physical SQLite/session root:

- Old accepted `control_id` = `exact-source-revision-old`, `tool_result` sequence **33**, finished turn sequence **50**. A restart after the source changed replayed the **historically correct** *old* answer without any new model call or tool effect.
- Fresh `control_id` = `exact-source-revision-new` on **the same original session ID** read the new active source, not the old source from previous messages or the historical same-named decoy; source tool-result sequence **78**, final turn sequence **95**. The later tool receipt/hash and source byte checksum differ from the old ones.
- A **second fresh runtime/service restart** reproduced both old and new final answers under their original control identities, **zero additional fake-model requests and zero duplicate tool invocations**. The persisted history still contained precisely **two actual file reads, two tool results and two finished turns**, and the original event count and final chained hash agreed with `rebuild_from_history()`.
- Reusing the old control ID with a different finalized user message raised `ValueError` before any new effect. Old controls remain *historical event identities*, not a command to silently recalculate their answer when the external source changes. A new control is required for new source authority.

This establishes correct **source-to-final user-visible output, saved state, source identity, end-of-turn boundaries, and restart replay**, with real local tools and independent byte-level source checks. It does not prove a production model will select the correct source or interpret a new instruction, or that a real user would prefer the final response.

## Matched negative controls, false positives and unknowns

For both of the **same actual source revisions**, a separate isolated SWAAG service ran two ungrounded controls:

| Scripted response policy | Old source | New source | Actual source-tool calls | Verified completed original source tasks |
|---|---|---|---:|---:|
| Direct affirmative with no read (`unguarded_direct_yes`) | **Wrong final assertion accepted** | Affirmative text coincidentally matches source, **still unverified** | 0 | 0/2 |
| Explicit inability to verify (`cautious_no_tool`) | Safe abstention, unresolved | Safe abstention, unresolved | 0 | 0/2 |
| Actual source-first tool + final answer | **Correct negative result with source receipt** | **Correct positive result with source receipt** | **2** | **2/2** |

The scripted ungrounded direct-positive control made one fast-model request per source version and the existing foreground accepted both as complete terminal answers, including **one exact source-gold false assertion**. A reply coincidentally matching the new source was **not** scored as source-verified without the tool call. The cautious model had **two fake requests per version** because the foreground guard routed its inability-to-verify message to the original deep controller, which still delivered an unresolved cautious answer without claiming a completed read. Total scripted requests for the four negative-control runs = **6**. False-positive/false-negative numbers are within these explicit **investigator-authored hard controls**, not representative natural Qwen error rates; there are only two independent source versions. This is a real code-path observation of the risk from an *unverified completed claim*, not a new model quality measurement or a deployed guard fix.
