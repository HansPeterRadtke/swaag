**Four frozen arms on the exact same original six cases** (24 actual final user-facing SWAAG streams, isolated per arm/case). Model outputs are **scripted** and never passed off as Qwen:

- `read_accurate`: first foreground `delegate`; actual `read_file`; terminal scripted controller returns the exact yes/no from the read bytes. This mechanical oracle-in-a-test-stub deliberately shows only harness source retention, *not natural model accuracy*. Expected 6/6 correct source statements and 6/6 real tool receipts. Three positive and three negative exact source outcomes.
- `read_inverted`: **same actual tool and original source**, same three fake model requests, but terminal controller intentionally answers the opposite of the read bytes. Expected 6/6 factually incorrect completed user-facing answers while 6/6 original source read/tool receipts are valid. This falsifies the claim “source availability/tool result implies final conclusion is independently correct.”
- `direct_yes_no_tool`: first model returns affirmative `answer` without reading; expected three source-correct-by-coincidence and three false affirmative claims, *zero* genuinely source-verified completions even when text happens to match. May be transformed/delegated by existing guard, and all deviations must be reported, never deleted or relabeled.
- `cautious_no_tool`: scripted first response says it has not read the file and cannot verify; if the real guard escalates, the fake deeper controller also abstains. Expected six unresolved but truthful answers and zero tool receipts; extra fake model calls must be fully counted. Abstentions are not correct completed tasks.

**Final acceptance** checks actual `CommunicationService.iter_orchestrator_message` progress and exact terminal answer; actual SQLite + append-only JSONL `control_message_processed`, `file_read_requested`, `tool_called`, `filesystem_read`, `tool_result`, `turn_finished`, hash-chain event sequence and original request; exact current tool source bytes; all actual model-call contracts, sum of prompt whitespace words (not llama.cpp/BPE tokens), wall time; idempotent same-control reconnect, plus a **fresh `AgentRuntime` and `CommunicationService`** reopening each isolated session root with an empty model client and returning the exact completed answer with zero new calls/effects. Do not carry out any external side-effecting tool, production service action, state alteration or Google action. Any run error is saved to an **append-only journal**, leaves previously completed receipts intact and counts as unknown/unverified, not semantic failure. Each original source case/arm is a distinct throwaway SQLite session; never retry a denied external operation or conceal uncertainty.

**Preregistered quality reporting**: counts of final factual TP/TN/FP/FN defined **by original exact-heading predicate**, source-grounded completed tasks, real source tool executions, user-visible wrong final claims, ungrounded coincidentally correct replies, safe unresolved abstentions, actual model requests per arm, source text/identity retention and restart identity successes. A claim with a real tool receipt but wrong final statement is **NOT** correct. A direct positive that matches the source but never read it is **NOT** source-verified. Independent blinded human relevance labels are absent; six mechanistic cases have no statistical generalization guarantee. Negative cases are *explicitly known absent headings*, not unjudged unknowns.

The precommitted acceptance rule for **harness ability only** is `read_accurate` 6/6 correct with six authentic tool results and all 24 restarts/idempotent replays sound; `read_inverted` must expose final errors despite authentic source receipts; the direct and abstain controls retain their false-assertion and unresolved counts. The result may support a deployment decision to **require an independent output-specific verifier before claiming source-backed factual completion**, but no verifier is deployed automatically from this study.

**Remaining limitations**: no actual Qwen Coder or Qwen3.8 completions, tokenizer token costs, GPU contention attributable to model calls, full two-stage specialist/reviewer results, independent user-vs-worker human relevance gold, numeric-vs-enum accuracy, or compute-matched syntax-auxiliary training. No denied Thor multi-call/source movement is retried; no running GPU service, worker or original source file is disturbed. Reproduce only in an isolated existing SWAAG Python 3.12 venv with process-local SQLite 3.51.3 compatibility lib and test model backend at never-listening port 9999.
