# Independent hard-source negative evidence audit — October 26, follow-up round three

## Operational verdict relative to the original SWAAG questions

**User-facing versus worker relevance:** Different caller goals need different evidence. Exact source paragraphs, the most recent authoritative user instruction and current tool/effect receipts remain primary; lexical similarity and permanent global relevance labels are not truth. **Numeric versus named ordinal scale:** existing five Qwen paired trials had 3/5 exact matches for each under the researcher's nonblinded labels; no winner. **Direct versus decomposed/reviewer:** prior actual same-task/model archival pairs found 5,593 tokens and 20.874 seconds for six complete direct answers, versus 5,600 tokens and 21.827 seconds for the corresponding *selector first stages only*. No model-selected second-stage answer was completed, and the original source-role labels leaked from `r1/r2` IDs. **Grammar auxiliary training:** published improvements and regressions are task-dependent; no matched modern Qwen FLOPs experiment exists. This round does not overwrite those facts or claim an end-to-end SWAAG worker winner.

## New source-gold experiment and why its negative labels are valid

A separately *independently expert-annotated* source test was conducted using the original SciFact 2020 scientific claim–paper pairs, with the reference document and true expert evidence sentence sets. The original unchanged SciFact release on Nitro, `/data/tmp/agent-model-independent-qrels-20261025/scifact_original.tar.gz`, has SHA-256 `11c621288d41ac144d29b13b0f8503b3820b7d6e8b1f6ff24dff335c196d76be`. The previously computed BM25 source selections have verified SHA-256 `0e0f797b9cafdd0abb7a15ff06b898b9ad8ef4d15bdf4f22ec609831872a076e`. **All 209 original development claim–paper records**, their polarity labels and exact expert rationale alternatives were checked against the archive before scoring; no silent source version upgrade. Eight real abstracts have under five sentences, so top-five uses *all available source sentences*; none was excluded or padded.

For each genuinely labeled pair, **SUPPORT is positive** and expert **CONTRADICT is a true negative for the binary question “does this paper support this claim?”**. A contradictory paper is still *relevant evidence* and is **not** a negative example for retrieval relevance. Papers with missing or unknown expert labels are never designated negatives. Source claim/paper identifiers are retained in the full compressed error ledger, but copyrighted original texts stay private on Nitro, outside the Git artifacts.

The fixed source split (with two exact shared claim strings removed from training) supplies **564 labeled training pairs across 505 original claims**; evaluation is **209 human-labeled pairs across 188 original claims**, 138 SUPPORT and 71 CONTRADICT. One candidate per original claim/paper is scored, with all source alternative rationales retained and shortest valid alternative chosen deterministically only for the oracle-evidence upper bound. Four **small CPU supervised** fixed-parameter TF-IDF/logistic classifiers train on the original train-source *expert rationale* and use the same fitted weights across evaluation source variants; the fifth control always predicts SUPPORT. Classifiers cannot identify valid rationale or paper without oracle/BM25; they are deliberately inexpensive *sanity controls*, **not Qwen model calls, agent workflows or reviewers**. The definitions and algorithm settings are in `HARD_SOURCE_POLARITY_PROTOCOL_2026-10-26.md`; no outcome-driven model selection was carried out. The first source validator failed before scoring because it incorrectly demanded five sentences from eight shorter actual abstracts; the validator was corrected to the source's exact `min(5,n)` behavior without changing data or method.

## Actual confusion against independently annotated true negatives

The following methods received the *same original 209 dev claim/paper inputs* and the expert-selected shortest complete rationale. TP = correct SUPPORT; TN = correct CONTRADICT; FP = incorrectly SUPPORT a contradictory original source; FN = incorrectly CONTRADICT a genuinely supporting source.

| Scorer | TP | TN | FP | FN | Correct / 209 | False-support fraction, among 71 contradictions |
|---|---:|---:|---:|---:|---:|---:|
| Always SUPPORT (zero learning) | 138 | 0 | 71 | 0 | 138 (66.03%) | 100.00% |
| Claim text only | 79 | 20 | 51 | 59 | 99 (47.37%) | 71.83% |
| Evidence rationale only | 72 | 20 | 51 | 66 | 92 (44.02%) | 71.83% |
| Joint claim + rationale, word n-grams | 78 | 19 | 52 | 60 | 97 (46.41%) | 73.24% |
| Joint claim + rationale, character n-grams | 80 | 23 | 48 | 58 | 103 (49.28%) | 67.61% |

**Substantive falsification:** the joint word classifier corrected 19 of the majority prior's false SUPPORT labels on original CONTRADICT cases, while breaking **60** previously correct SUPPORT cases. Net **41 fewer** correct results than the zero-learning baseline. Character features fixed **23**, broke **58**, net **35 fewer**. Claim-only and evidence-only were also worse than the majority baseline. These are independently graded error results for the installed *CPU lexical* methods, not claims that a future Qwen model would fail at those rates. A claim-clustered 1,000-resample descriptive interval for joint word minus constant prior accuracy was **−19.62 percentage points [−29.57, −9.60]**, 188 unique claim clusters; joint word minus evidence-only was **+2.39 points [−1.36, +6.28]**. They are not corrected for choosing a winner after looking at the results, and this development split has previous retrieval-study reuse.

## Multiple interpretations, hard evidence requirements and source budgets

The same fitted models were evaluated at identical **claim/paper cases**, while changing the source context from exact expert evidence to previously frozen BM25 source selections or the complete abstract. The original annotated rationale is an **OR** across each complete valid expert sentence set; individual fragments are never counted as complete.

| Evidence provided | Complete gold rationale available | Mean source words (not tokenizer tokens) | Joint word accuracy | Joint char accuracy |
|---|---:|---:|---:|---:|
| Expert shortest complete rationale (oracle) | 209/209 | 32.94 | 97/209 | 103/209 |
| BM25 top 3 original sentences | 168/209 | 78.87 | 97/209 | 96/209 |
| BM25 top 5 (or entire shorter abstract) | 185/209 | 127.92 | 97/209 | 102/209 |
| Entire original abstract | 209/209 | 235.43 | 100/209 | 107/209 |

Merely supplying more text or a complete rationale did **not** make these classifiers reliable. Extra retrieved sentences may add distractors; the trained classifier uses a different distribution from its oracle training data; the original task evidence may be intrinsically too subtle for bag-of-words features. The experiment cannot identify a single causal reason for each failure. **Fourteen** independent heldout cases had no valid one-sentence rationale at all; **85** had multiple alternative complete expert rationales. On the hard fourteen, joint word with expert rationale correctly decided only **8/14**, including **zero of three** original CONTRADICT cases; giving a fragment as proof would mask the underlying error. No conclusion about full SWAAG Qwen performance follows.

The heldout set includes **ten claims with multiple original expert-annotated paper instances** (31 claim/paper pairs). Same-claim expert labels have identical polarity across those papers. The oracle-trained character classifier nevertheless changed its prediction across papers for one original claim (`873`); evidence-only changed across papers for four claims (`261`, `452`, `597`, `873`). This is **measured sensitivity across real source instances**, not fabricated alternative prompts. The full source-keyed ledger also retains variant-specific predictions for each paper rather than selecting a favorable version after the fact.

Two concrete *incorrect* original-label outcomes, retained as identifiers without copyrighted text: claim `1029`, paper `13923140` was expert CONTRADICT with minimum two-sentence rationale `[2,3]`, but the joint word classifier returned SUPPORT (raw support probability **0.706457**); claim `1379`, paper `16322674` was expert SUPPORT with alternative expert sentences `[5]` or `[6]`, yet the same model returned CONTRADICT (raw probability **0.235443**). These probabilities are logistic outputs, **not calibrated probabilities that the underlying scientific statement is true**. All other false positives and negatives, even if unflattering, are kept in `case_errors_v1.json.gz`.

## Versioning, selection bias, costs and unchanged production

Exactly **124/209 evaluation pairs** use paper IDs that appear in training even though *no verbatim original claim text* appears in both splits. This is an important document-reuse limitation; the experiment is **not** blind to every paper. In the joint word oracle condition, the previously seen-paper stratum had **39/124 correct (31.45%)**, while unseen-paper IDs had **58/85 (68.24%)**. The groups have different label proportions, repeated claims and differing source distributions; this contrast is descriptive, not evidence that unseen papers are easier or a statistically identified document-overlap effect. The development split had been used for earlier SciFact retrieval studies, also limiting claims of a fresh untouched benchmark. Independent science annotations establish binary reference labels, not exhaustive relevance for all other documents or a verified SWAAG user task completion.

Four lightweight CPU classifier fits required approximately **0.35, 0.41, 0.29 and 4.50 seconds** each in this run; across all source parsing, source-hash verification, fitting and the twenty classifier/context condition evaluations, total wall time was **22.80 seconds**, with a reported process peak resident memory of **327,212 KiB**. These times were observed on Nitro under other machine workload and are not isolated model GPU inference costs. **No Qwen call, tool execution, reviewer inference, GPU reservation, model service restart, production code change, denied file movement or new event occurred.** Neither model tokenizer costs nor real queue contention can be inferred from whitespace words or CPU times.
