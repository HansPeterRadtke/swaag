## Original owner questions: bounded answers, not conflated with harness reliability

The owner explicitly asks (1) how evidence relevance for the user, background worker and orchestrator differ while preserving exact source and current user authority, (2) whether numeric 0–100 or ordered text labels work better, (3) whether one rich call or specialized selection/answer/review calls best maximize *independently true final results per total tokens/latency/GPU resource*, and (4) whether **training-time** grammar/syntax auxiliary tasks improve Qwen. The Oct 17/18 source recordings, Sep 27 training recording and applicable current Infra guidelines were checked again. The original findings remain:

- Role relevance genuinely depends on consumer and current task, but 64 role-conditioned labels over 29 actual SWAAG snippets are *researcher-assigned*, not independently human-adjudicated final-task correctness. Existing context task IDs universally encoded expected relevant IDs as `r1,r2`, preventing claims of independent model evidence-selection precision. The previous 23-case **scripted foreground harness** study saw 12/23 unsupported terminal claims in committed SWAAG versus 1/23 under an **undeployed** guard extension, at 24 versus 37 fake model calls. Safe but unresolved delegation is not a correct user answer.
- Five matched numeric vs nine-level ordinal-word Qwen pairs each scored 3/5 against those researcher labels; numeric absolute deviation total 10 vs 16, without independent gold or end-task outcomes. Neither format is established as more reliable or a calibrated probability.
- Six real archived Qwen cases needed 5,593 tokens and 20.874 seconds for **complete direct outputs**, versus 5,600 tokens and 21.827 seconds for **only selector stage one**; no corresponding full selector→answer→reviewer result was completed. External published software-task evaluations demonstrate both rescue and harmed original final outcomes under nonoracle alternative-architecture routing, but lack the installed Qwen model's actual total GPU, queue, token, and VRAM cost. No universal decomposition win.
- Published syntax auxiliary-training research reports task-specific gains *and* regressions. Local Qwen same-starting-weights, same-training-FLOPs experiments have not been performed. This round used **zero** Qwen model inference or training; scripted models and exact-heading matching do not test grammar training.

**Interim operational recommendation:** one capable initial foreground user-facing response with source-purpose/context; independently verified tool/effect receipts and final-claim checks for consequential work. A second model vote is not validation. Prior tests showed two CPU reviewer classifiers both wrong in 103 of 209 expert-labelled scientific pairs; a blind override fixed nine first-classifier errors but created ten. These *surrogate* figures are never reported as Qwen review precision.

**The decisive independent negative control:** SWAAG persisted **all six deliberately incorrect final answers despite six genuine source-tool executions and six correct source-event receipts**. The actual source bytes were present in the final-model input with the original user request, exact active filename and source event provenance. It is therefore demonstrably wrong to count an LLM's final claim as objectively verified merely because its upstream tool returned a valid source and it had a legitimate receipt. Conversely, the six mechanically correct final statements had valid source reads, but their correctness was scripted and does not establish a real model's semantic skill. The three ungrounded positive guesses that happened to match the correct source version are **not** verified task completions. All 24 cases' stream/control `turn_finished` and `tool_result` metadata were tested, and a newly created runtime/service replayed each previous control ID without additional tool or fake-model execution. The source identity decoys never replaced the actively requested source.

**Call-cost accounting:** All `read_accurate`/`read_inverted` cases made three mock model requests per full task: one fast foreground, one deeper tool-command action, one final response. The inverted model condition exactly matches the correct model condition on 18 total requests and 44,214 whitespace words, ruling out unequal *scripted call count/source length* as the cause of their different correctness. This is not a matched real Qwen-token or GPU experiment: model-client calls return immediately, and measured seconds are original SWAAG Python/persistence/controller wall under concurrent Nitro CPU/GPU workloads. `direct_yes_no_tool` required only one cheap fake foreground call per case but made three unsupported false assertions; the cautious no-tool path required two fake calls for each of six unresolved tasks. The correct arm's larger cost is cost of the real file tool and source-carrying prompts, not proof that expensive semantic reasoning is necessary for every task. There were **54** total fake client requests across all arms, no real Qwen inference calls and no changes to production services.

### Separate independently implemented artifact re-grader

The new independent stdlib-only `independent_regrade_source_receipts_20261027.py` does **not import either source experiment's code or rerun an existing model/tool effect**. It checks the 24 actual appended `isolated_case_completed` receipts, all input and archived artifact SHA-256s, recovers exact source truth again from immutable `git show` source bytes (without trusting original expected-label fields), verifies source and decoy hashes, reclassifies each final user-visible reply as TP/TN/FP/FN or safe abstention, and recomputes every recorded model-call count, fake prompt-word proxy, tool-read count and full harness wall from the independent final case ledger. It also independently checks the *previous* round-nine source-version result artifact against its two original immutable Git objects: old/new correct headings, actual tool counts, negative-control false assertion and separately persisted source identities. It accounts for **24/24 completed cases, zero unexplained attempts and no missing trial outputs**.

As a **posthoc source-specific diagnostic only**, an ordinary program that requires both an authenticated `read_file` receipt **and** agreement between the final `Yes`/`No` and the exact source's Markdown heading line accepts the six correct grounded claims and withholds the other **18** finished/refrained outputs. It has zero observed false accept/reject on these six deliberately selected exact-schema source tasks, with **no extra LLM calls**. However this rule was constructed *after seeing the outcomes*, cannot verify unrestricted semantic or factual questions and was **not deployed** or prospectively benchmarked. The tool used immutable original Git bytes to reconstruct source predicates, which would require equivalent authorized authoritative source access in any live application.

**Honest independent verification limitation:** The saved experiment journal retains source hashes, event sequences and event hashes but **not full raw ephemeral SQLite event payloads**. The experiment itself verified its own complete history hash chain during runtime; a truly external auditor cannot recompute *each individual chain hash cryptographically from saved artifacts alone*. The independent audit therefore verifies **source truth, receipt identities, output labels and costs**, not a second independent hash-chain reconstruction. Claiming full independent raw-history proof from the archived hash labels would be ungrounded.

## Reliability and scope limits

The original old/new history-journal repair from round eight remains committed to the research branch, with 7/7 focused per-session read/write contention controls, 100/100 focused SWAAG integration tests and 124/124 prior source research tests in that earlier round. This round's test-created history files are exclusively in throwaway directories, not the installed server. The new independent regrader also found that the round-nine mechanical gold remains internally correct, but **it does not provide missing real-model accuracy**. None of the source pairs are independent human ratings of worker-vs-user relevance or a representative random sample, and deliberately inverted proposals are not evidence of a real Qwen failure frequency. No statistical population confidence interval is meaningful from these six deterministic cases; a fake bootstrap would conceal that selection.

**Remaining decisive original empirical work:** obtain authentic SWAAG requests with original source/effect truth independently graded, and fully complete both installed Qwen routes (direct, stage-one selector, final specialist and actual optional reviewer) on the **same tasks** with identical permission/safety/input conditions, plus end-to-end first-useful-answer latency, true tokenizer input/output counts, GPU queue/shared VRAM contention and reviewer wrong→right vs right→wrong. Also obtain genuine independent multi-rater user/worker relevance judgments to compare numeric vs ordered-category formats and a matched-FLOP current Qwen auxiliary grammar training experiment. Denied Thor operations and unrelated concurrent research were not touched. Until these exist, the main claim “one-call or decomposed reviewer wins” remains **unproved**.
